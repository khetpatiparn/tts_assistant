## 1. บริบทและเป้าหมาย

M1.1–M1.4 เสร็จแล้ว: 254 automated tests ผ่าน, flow เต็ม (Start → scan → preview → select → export)
ยืนยันด้วยมือในเบราว์เซอร์จริงแล้วว่าใช้งานได้ พร้อมไฟล์ export ที่ตรวจแล้วว่าถูกต้อง

**M1.5 มีเป้าหมายเดียว: ปิด G1 ให้จบอย่างซื่อสัตย์** — ไม่ใช่เพิ่มฟีเจอร์ แต่คือ
(ก) ทำให้สิ่งที่เคยทดสอบด้วยมือกลายเป็น automated test ที่จับ regression ได้
(ข) ทำ validation ที่เหลือซึ่งทำได้จริงกับ mock
(ค) เขียนรายงาน sign-off ที่ระบุชัดว่าอะไรผ่าน อะไรยังไม่ผ่าน และเพราะอะไร

**G1 รอบนี้คือ "mock-only prototype G1" ไม่ใช่ live-ready G1** — ตรงตามที่ G1 checklist ข้อแรกของ spec
เขียนไว้เองว่า *"G0 ผ่านหรือ label ชัดว่า mock-only prototype ไม่ใช่ live-ready"*

## 3. Playwright E2E harness

### 3.1 โครงสร้างไฟล์

| Path | หน้าที่ |
|---|---|
| `playwright.config.ts` | `testDir: './tests/e2e'`, ไม่รวมใน `npm test` |
| `tests/e2e/fixtures/extension.ts` | fixture เปิด persistent context พร้อม `--load-extension=dist`, รอ service worker, ดึง extension ID จาก URL ของ SW |
| `tests/e2e/load-unpacked.spec.ts` | extension โหลดได้, SW ลงทะเบียน, dashboard เปิดได้, banner mock-only แสดง, ไม่มี console error |
| `tests/e2e/scan-flow.spec.ts` | คลิก Start จริง → รอ finished → เลือก 2 ตัว → คลิก Export → ตรวจไฟล์ที่ดาวน์โหลด |
| `tests/e2e/network-isolation.spec.ts` | PK04 — เก็บ request ทุกตัวที่เกิดขึ้น แล้ว assert ว่าไม่มี scheme `http`/`https` ออกนอกเครื่อง |

### 3.2 การตัดสินใจเชิงเทคนิค

- **`npm test` ยังเป็น vitest อย่างเดียว** — `npx playwright install chromium` ต้องโหลด browser ผ่าน network
  ซึ่งขัดกับ network deny-by-default (R15) ถ้าเอามารวม จึงแยกเป็น `npm run test:e2e` และเขียนใน README
  ว่าเป็น setup step ที่ต้องทำครั้งเดียวก่อน (ประเด็นนี้ code reviewer ของ M1.3 เตือนไว้แล้ว)
- **ใช้ Chromium ที่ Playwright ดาวน์โหลดมาเอง** ไม่ชี้ไปที่ Brave/Chrome ที่ผู้ใช้ติดตั้ง (ตาม spec §13.1
  ที่ห้ามชี้ automation ไป browser profile หลักของผู้ใช้) — ดังนั้น **VA09 (Brave/Chrome จริง) ยังเป็น manual**
- **E2E ทดสอบ `dist/` (mock channel) เท่านั้น** — release channel ไม่มี adapter ให้สแกน
- **ไม่ใช้ `page.route` ดัก request ของ service worker** ตามที่ spec §13.1 เตือน — ใช้
  `context.on('request')` เก็บ log แล้ว assert แทน

## 4. UAT (VA items)

### 4.1 ผ่านแล้วระหว่าง brainstorming (มีหลักฐานจริง)

| VA | หลักฐาน | สถานะ |
|---|---|---|
| **VA07** (user intent) | ผู้ใช้เลือกสินค้า 3 ตัวแล้ว export — ไฟล์ `flow-a-export-9e01f052…json` มี `selectedProductIds` และ `products` ตรงกัน 3 ID เป๊ะ ไม่มีแถวอื่นปน | **PASS** |
| **VA08** (privacy boundary) | เปิด DevTools → Application → IndexedDB → `flow-a-checkpoints` → `products` → ขยายแถวเต็ม: มีเฉพาะ field ใน schema §8.1 ทั้ง 19 ช่อง ไม่มี cookie/token/session/authorization | **PASS** |

### 4.2 ที่เหลือใน M1.5

| VA | ขั้นตอน |
|---|---|
| **VA09** (browser compat) | ทำซ้ำขั้นตอนเดิม (build:mock → load unpacked → Start → select → export) บน **Chrome** แล้วบันทึกเวอร์ชันจริง — Brave ผ่านแล้ว 2026-09-19 |

### 4.3 Package security ที่เหลือ

| ID | ใครทำ | วิธีตรวจ |
|---|---|---|
| **PK02** (เต็มรูปแบบ) | automated | ขยาย bundle scan ที่มีอยู่: นอกจาก `eval`/remote loader (PK02a ตรวจแล้ว) ให้เพิ่ม assert ว่า release bundle ไม่มี (ก) string ที่ match `/(api[_-]?key\|secret\|passwd\|password\|bearer\s)/i` (ข) การอ้างถึง `chrome.cookies` (ค) `chrome.permissions.request` นอกไฟล์ dashboard — เพื่อยืนยันว่าไม่มีเส้นทาง export credential |
| **PK05** | manual | ถอนการติดตั้ง extension → เปิด DevTools บน extension page ไม่ได้อีก และ IndexedDB `flow-a-checkpoints` หายไป; ยืนยันว่า cookie ของเว็บอื่นไม่ถูกแตะ (PK01 พิสูจน์แล้วว่าไม่มี permission `cookies` ตั้งแต่ manifest) |

## 5. Coverage

G1 กำหนด **branch coverage ≥90% สำหรับ parser/pagination/error state**

- ติดตั้ง `@vitest/coverage-v8`, ตั้ง threshold เฉพาะไฟล์กลุ่มนี้:
  `domain/envelope.ts`, `domain/product.ts`, `domain/page.ts`, `domain/json-lossless.ts`,
  `core/pagination.ts`, `core/retry.ts`, `core/runner.ts`
- **ถ้าไม่ถึง 90% ให้บันทึกตัวเลขจริงและเพิ่ม test ให้ถึง ไม่ใช่ลดเกณฑ์**
- coverage ไม่แทน semantic validation (spec เขียนไว้เอง) — เป็นเกณฑ์เสริม ไม่ใช่หลักฐานความถูกต้อง

## 8. ความเสี่ยงที่รู้อยู่แล้ว

| เรื่อง | ผลกระทบ | แนวทาง |
|---|---|---|
