# บันทึกการนำเข้าไฟล์ (ImportLog) + อัปหลายไฟล์พร้อมกัน

**วันที่:** 2026-08-03

## ปัญหา

ผู้ใช้ลืมว่าอัปไฟล์อะไรไปแล้วบ้างในรอบนั้น สาเหตุมี 3 อย่างประกอบกัน:

1. **ข้อความยืนยันหายตอน refresh** — สรุปผลหลังอัป ("นำเข้า 15 คลิป") เก็บใน `useActionState` ซึ่งเป็น state ฝั่ง client ล้วน ผู้ใช้มีนิสัย refresh หน้าหลังอัป ทำให้หลักฐานว่าเพิ่งทำอะไรไปหายทันที ทั้งที่ฐานข้อมูลรู้ (`importedAt` มีทุกแถว) แต่ไม่เคยถูกนำมาแสดง
2. **Content.csv ต้องอัป 3 ไฟล์ต่อรอบ แต่แยกไม่ออกว่าทำไปกี่ไฟล์** — ทั้ง 3 ไฟล์ (ช่วง 7/28/60 วัน) เขียนลง `ClipMetric` ที่ `capturedOn` เดียวกัน ทำให้ "อัปล่าสุดเมื่อไร" ของทั้งสามเท่ากันหมด มองไม่เห็นว่าอัปไป 1 จาก 3 หรือครบ 3
3. **ไฟล์ทุกช่วงชื่อ `Content.csv` เหมือนกันหมด** — TikTok Studio ตั้งชื่อแบบนี้เสมอ ผู้ใช้ไม่ต้องการเปลี่ยนชื่อเอง

สถานะที่มีอยู่แล้ว (`ImportStatusLine`, `ReminderBanner`) บอกได้แค่ "เกินกำหนดมากี่วัน" ของ 2 ชนิดไฟล์ (รายได้/วิวคลิป) และไม่ได้ตอบว่า *รอบนี้ทำอะไรไปแล้วบ้าง*

## เป้าหมาย

ตอบให้ได้ว่า **"รอบนี้อัปอะไรไปแล้ว และเหลืออะไร"** โดยไม่ต้องให้ผู้ใช้จำหรือติ๊กเอง และไม่หายเมื่อ refresh

## สิ่งที่ตัดออกโดยตั้งใจ

- **ไม่ให้ติ๊กเอง** — โปรเจกต์นี้เคยตัดสินใจเรื่องนี้ไปแล้วตอนทำบล็อกคำแนะนำ มีคอมเมนต์กำกับใน `components/recommendations.tsx` ว่า *"ปัญหาต้นทางของผู้ใช้คือลืม/ไม่ได้ทำ ของที่ต้องจำไปติ๊กคือของที่ลืมได้อีกอย่าง"* ซึ่งตรงกับปัญหานี้พอดี
- **ไม่เดาชื่อช่วงของไฟล์ (7/28/60 วัน) มาแสดง** — ทดสอบกับไฟล์จริงแล้วพบว่า "คลิปเก่าสุดที่โพสต์" แยก 7/28/60 ออกจากกันได้ (1 ก.ค. / 19 มิ.ย. / 28 พ.ค.) แต่แยก 60 กับ 365 ไม่ออก (28 พ.ค. เท่ากัน) และเกณฑ์นี้เลื่อนไปตามอายุช่อง **การเดาผิดแย่กว่าไม่เดา** จึงแสดงลายเซ็นดิบให้ผู้ใช้ดูออกเอง
- **ไม่บล็อกการอัปเมื่อไฟล์ไม่ครบ** — ไฟล์แต่ละตัวเป็นอิสระต่อกัน ถ้า export ไฟล์ใดพลาดต้องยังอัปตัวที่เหลือได้ ข้อมูลบางส่วนดีกว่าไม่มีเลย
- **ไม่บล็อกเมื่ออัปไฟล์ซ้ำ แค่เตือน** — การอัปไฟล์เดิมซ้ำไม่ทำอันตราย (ทุก importer เป็น upsert) และบางครั้งตั้งใจ เช่นตอนแก้บั๊ก parser แล้วต้อง import ใหม่ (เกิดขึ้นจริงในโปรเจกต์นี้ตอนแก้บั๊กปีของ `Overview.csv`)
- **ไม่ทำ multi-file ให้ importer อื่น** — มีแค่ Content.csv ที่ต้องอัปหลายไฟล์ต่อรอบ อีก 3 ตัวเป็นไฟล์เดียวจบ เพิ่ม `multiple` ให้ด้วยจะชวนสับสนโดยไม่ได้ประโยชน์

## สถาปัตยกรรม

### 1. ตาราง `ImportLog`

```prisma
/// บันทึกทุกครั้งที่อัปไฟล์ — ตอบว่า "รอบนี้ทำอะไรไปแล้ว" ให้รอด refresh
/// (ต่างจาก importedAt ในตารางข้อมูลที่บอกได้แค่ "ล่าสุดเมื่อไร" ไม่บอกว่ากี่ไฟล์)
model ImportLog {
  id         String   @id @default(cuid())
  /// "orders" | "clips" | "followers" | "channel"
  kind       String
  uploadedAt DateTime @default(now())
  /// sha256 ของไฟล์ดิบ — ใช้ตรวจว่าอัปไฟล์เดิมซ้ำ
  fileHash   String
  /// จำนวนแถวที่ parse ได้จากไฟล์นี้
  rowCount   Int
  /// ลายเซ็นสั้นให้ผู้ใช้ดูออกว่าไฟล์ไหนคือไฟล์ไหน เช่น "15 คลิป · เก่าสุด 1 ก.ค."
  summary    String

  @@index([kind, uploadedAt])
  @@index([fileHash])
}
```

### 2. `lib/import-log.ts` (pure + helper)

- `hashFile(buf: Buffer): string` — sha256 hex
- `groupLatestRound(logs: ImportLogRecord[]): RoundSummary[]` — pure function จัดกลุ่มตาม `kind` แล้วเอาเฉพาะรายการของ**วันล่าสุดที่ kind นั้นมีการอัป** (ไม่ใช่ของวันนี้เสมอ เพราะบางชนิดอัปทุก 2 เดือน) คืน `{ kind, day, files: { uploadedAt, rowCount, summary }[] }` โดย `files` เรียงตามเวลาเก่า→ใหม่

จัดกลุ่มตาม "วันล่าสุดที่มีการอัปของ kind นั้น" ทำให้ครอบทั้งกรณีอัป 3 ไฟล์ในการกดครั้งเดียว และกรณีกด 3 ครั้งแยกกัน โดยไม่ต้องรู้ว่าเป็นแบบไหน

**`uploadedAt` เป็น timestamp จริง (ไม่ใช่ UTC midnight) → ตัดวันด้วย local getter** เหมือน `orderDate` ใน `lib/dashboard.ts`/`lib/weekly-scoreboard.ts` **ห้ามใช้ UTC getter** เพราะจะทำให้การอัปช่วงเย็นเวลาไทย (หลัง 17:00 = ข้ามวัน UTC) ถูกจัดไปคนละวันกับการอัปตอนเช้าของวันเดียวกัน

### 3. Multi-file เฉพาะ `importClipMetrics`

- `<Input type="file" name="files" multiple>` (เปลี่ยนจาก `name="file"`)
- action อ่านด้วย `formData.getAll("files")` แล้ววนประมวลผลทีละไฟล์
- แต่ละไฟล์เขียน `ImportLog` 1 แถว
- สรุปที่คืนกลับรวมทุกไฟล์: `{ files: number; total: number; matched: number; unmatched: number; duplicates: string[] }`

`duplicates` คือลายเซ็นของไฟล์ที่ `fileHash` ตรงกับที่เคยอัปแล้ว — ใช้แสดงคำเตือน ไม่ใช่หยุดการทำงาน

### 4. Importer อีก 3 ตัวเขียน `ImportLog` ด้วย

`importAffiliateOrders` / `importFollowerActivity` / `importChannelMetrics` ยังรับไฟล์เดียวเหมือนเดิม แต่เพิ่มการเขียน `ImportLog` 1 แถวต่อการอัป 1 ครั้ง เพื่อให้แผงสถานะครอบทุกชนิดไฟล์

**ลายเซ็น (`summary`) ของแต่ละชนิด:**

| kind | ตัวอย่าง summary |
|---|---|
| `orders` | `"361 ออเดอร์ · 26 พ.ค.–2 ส.ค."` |
| `clips` | `"15 คลิป · เก่าสุด 1 ก.ค."` |
| `channel` | `"365 วัน · 2 ส.ค. 2025–1 ส.ค. 2026"` |
| `followers` | `"336 แถว · 14 วัน"` |

### 5. แผง `components/import-log-panel.tsx`

แทนที่ `ImportStatusLine` เดิม วางไว้ที่เดิม (นอกส่วนที่พับ เห็นตลอด):

```
อัปล่าสุด
  รายได้        3 ส.ค. 13:20 · 361 ออเดอร์ · 26 พ.ค.–2 ส.ค.
  วิวคลิป       3 ส.ค. · 2 จาก 3 ไฟล์
                  15 คลิป · เก่าสุด 1 ก.ค.      (13:45)
                  14 คลิป · เก่าสุด 19 มิ.ย.    (13:47)
  วิวทั้งช่อง   3 ส.ค. 12:50 · 365 วัน
  ผู้ติดตาม     2 ส.ค. 20:10 · 336 แถว
```

- ชนิดที่ยังไม่เคยอัปเลย → ไม่แสดงบรรทัด (ไม่ใช่แสดงว่า "ยังไม่อัป" ซึ่งจะรกโดยเปล่าประโยชน์)
- **แสดง "N จาก M ไฟล์" เฉพาะ `clips` เท่านั้น** — อีก 3 ชนิดเป็นไฟล์เดียวจบ ไม่มีเลขคาดหวัง แสดงแค่เวลากับลายเซ็นบรรทัดเดียว
- แตกรายการย่อยรายไฟล์เฉพาะเมื่อชนิดนั้นมีมากกว่า 1 ไฟล์ในวันนั้น (ชนิดไฟล์เดียวไม่ต้องแตก)
- **แผงนี้แทนที่ `ImportStatusLine` เดิม และดูดคำเตือน "เกินกำหนดมา N วัน" เข้ามาไว้ในตัว** — แสดงต่อท้ายบรรทัดของชนิดนั้น (เป็นคนละเรื่องกับความครบของรอบ: อันหนึ่งบอกความสดของข้อมูล อีกอันบอกว่ารอบนี้ทำครบไหม) เกณฑ์ยังใช้ `IMPORT_STALE_DAYS` เดิมจาก `lib/dashboard.ts` ไม่ตั้งค่าใหม่

### 6. ค่าคงที่ `EXPECTED_CLIP_FILES = 3`

จำนวนไฟล์ Content.csv ที่ควรอัปต่อรอบ ใช้แสดง "2 จาก 3 ไฟล์"

**ผูกกับการตัดสินใจเรื่องช่วง export (7/28/60 วัน) ไม่ใช่ค่าที่คำนวณได้** — ถ้าเปลี่ยนชุดช่วงที่ใช้ ต้องแก้ค่านี้ตาม ให้เพิ่มเข้าไปในหัวข้อ "ค่าคงที่ที่ผูกกับสเกลข้อมูล" ของ `CLAUDE.md` เพื่อให้ถูกทบทวนเป็นระยะ (ที่มาของตัวเลข 3: วัดจากไฟล์จริง 4 ช่วงเมื่อ 2026-08-03 พบว่าช่วง 365 วันไม่เพิ่มคลิปใหม่เลยแม้แต่ตัวเดียว จึงเหลือ 7+28+60)

## การจัดการข้อผิดพลาด

- ไฟล์ที่ parse ไม่ผ่านในชุด multi-file → ข้ามเฉพาะไฟล์นั้น ไฟล์ที่เหลือยังทำงานต่อ แล้วรายงานว่าไฟล์ไหนพลาด (ไม่ทำให้ทั้งชุดล้ม)
- ถ้าทุกไฟล์ในชุด parse ไม่ผ่าน → throw ตามเดิม
- `ImportLog` เขียน**หลัง** import สำเร็จเท่านั้น — ไฟล์ที่ล้มไม่ควรถูกบันทึกว่าอัปแล้ว

## การทดสอบ

โปรเจกต์ไม่มี test runner → คอมไพล์ด้วย `tsc` ลง scratch dir แล้วรันด้วย node (แบบเดียวกับ `lib/channel-reach.ts`)

**เทสต์ `groupLatestRound`:**
- log หลายชนิดหลายวัน → แต่ละชนิดต้องได้เฉพาะรายการของวันล่าสุด*ของชนิดนั้น* (ไม่ใช่วันล่าสุดรวม)
- ชนิดที่ไม่มี log เลย → ไม่โผล่ในผลลัพธ์
- 3 ไฟล์ในวันเดียวกัน → รวมเป็นกลุ่มเดียวมี 3 รายการ เรียงตามเวลา
- input ว่าง → คืน array ว่าง ไม่ throw

**เทสต์ `hashFile`:** ไฟล์เดียวกันได้ hash เดิม · ต่างกัน 1 ไบต์ได้ hash ต่าง

**ตรวจด้วยไฟล์จริง:** อัป `Content_07days` + `Content_28days` + `Content_60days` พร้อมกันในการกดครั้งเดียว ต้องได้ 3 บรรทัดใน log · รวม 28 คลิปใน snapshot วันนั้น · อัปไฟล์ใดไฟล์หนึ่งซ้ำต้องขึ้นคำเตือนแต่ยังนำเข้าสำเร็จ

## เกณฑ์ว่าสำเร็จ

1. อัป 3 ไฟล์พร้อมกันได้ในการกดครั้งเดียว
2. refresh หน้าแล้วยังเห็นว่ารอบนี้อัปอะไรไปแล้วบ้าง
3. เห็นลายเซ็นแยกได้ว่าแต่ละไฟล์คือช่วงไหน โดยไม่ต้องเปลี่ยนชื่อไฟล์
4. อัปไฟล์เดิมซ้ำ → ขึ้นเตือน แต่ยังนำเข้าสำเร็จ
5. `npx tsc --noEmit` + `npm run lint` ผ่านสะอาด
6. ไม่แตะ `dev.db` ตัวจริงระหว่างทดสอบ
