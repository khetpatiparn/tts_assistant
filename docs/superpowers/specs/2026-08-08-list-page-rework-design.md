# รื้อหน้ารายการสินค้า — ตัวกรองรวมศูนย์ แถวใหญ่ขึ้น มีหัวคอลัมน์

วันที่: 2026-08-08 · สถานะ: อนุมัติแล้ว รอทำแผนลงมือ

## 1. ปัญหาที่แก้

ผู้ใช้รายงาน 6 อาการในหน้า `/`:

1. **ตัวกรองวันที่ชวนเข้าใจผิด** — ช่อง "จากวันที่/ถึงวันที่" กับปุ่ม "วันนี้/7 วัน/30 วัน" วางแยกกันคนละแถวและเป็นคนละกลไก ทำให้เข้าใจว่าถ้าเลือกช่วง 5-20 ส.ค. แล้วกด "7 วัน" มันจะหมายถึง 7 วันภายในช่วงนั้น (จริงๆ คือ 7 วันล่าสุดนับจากวันนี้ และมันเขียนทับช่วงที่เลือกไว้ทั้งหมด)
2. ตัวอักษรเล็กเกินไป ไม่อิงมาตรฐาน UX ใดๆ
3. ปุ่มดูไม่ออกว่ากดได้ ต้องลองกดถึงจะรู้
4. แถวในรายการเล็กไป รูปสินค้าเลยเล็กตาม ดูไม่ออก
5. ไม่มีหัวคอลัมน์บอกว่าแต่ละช่องคืออะไร
6. ยอดขาย/วิวโผล่บางแถว ทำให้แต่ละแถวโครงไม่เหมือนกัน

ข้อ 2-3 ถูกแก้เป็นกฎกลางไปแล้วในโปรเจกต์ A (ธีม+ตัวอักษร) แต่ `entry-list.tsx` ถูกกันไว้ไม่ให้แตะโดยตั้งใจ เพื่อไม่ให้เขียนโค้ดทิ้งสองรอบ — โปรเจกต์นี้คือตัวที่เอากฎเหล่านั้นมาใช้จริง

หลักฐานจากโค้ดปัจจุบัน:

| ของที่วัดได้ | ค่า |
|---|---|
| ตัวอักษรเล็กสุดในไฟล์ (`text-[0.55rem]`) | 8.8px (พื้นต่ำสุดที่ตกลงกันไว้คือ 12px) |
| จุดที่ใช้ขนาด arbitrary | 10 จุด |
| จุดที่ใช้ `font-mono` (ส่วนใหญ่ครอบข้อความไทย) | 16 จุด |
| จุดที่ยังใช้ alias สีเก่า | 7 จุด |
| ป้ายกำกับที่พิมพ์ซ้ำในทุกแถว | 4 ป้าย × 30 แถว/หน้า |
| ขนาดรูปย่อ | 44px |

## 2. ขอบเขต

โปรเจกต์นี้คือก้อน **B** จาก 3 ก้อน (A → B → C):

- **A (เสร็จและ merge แล้ว)** — ธีม Navy + Brass, ตัวอักษร, กฎ affordance
- **B (สเปกนี้)** — รื้อหน้ารายการสินค้า
- **C** — รื้อ "ควรทำอะไรต่อ" ในหน้ารายได้

**ไม่ทำในสเปกนี้:** ตรรกะค้นหา/กรอง/เรียง/แบ่งหน้าไม่แตะเลย (`lib/entry-rows.ts`, `lib/entry-date-filter.ts`, `lib/entry-sort.ts`, `lib/entry-search.ts`) · ไม่แตะ schema · ไม่เพิ่มฟีเจอร์ใหม่

**ตัดสินใจแล้วว่าไม่ทำ: คอลัมน์หมวดสินค้า** — ผู้ใช้ถามระหว่าง brainstorm ตรวจแล้วว่าฟิลด์นี้ไม่มีใน `PromptEntry` เลย จึงไม่ใช่การเพิ่มคอลัมน์แต่เป็นฟีเจอร์ใหม่ (schema + migration + backfill 55 รายการ) และการคำนวณ power แสดงว่าการวิเคราะห์รายหมวดที่ข้อมูลนี้จะไปป้อนต้องใช้ ~310 คลิปขึ้นไป (ราว ธ.ค. 2026) จึงจะแยกความต่างระดับ 3 เท่าได้ ส่วนการโชว์ในหน้ารายการเองไม่เปลี่ยนการตัดสินใจใดของผู้ใช้ (เลือกสินค้าจาก TikTok Shop ไม่ได้เลือกจากลิสต์ตัวเอง) รายละเอียดอยู่ใน auto-memory `project_analysis_limits.md`

## 4. โครงหน้าใหม่

### 4.1 แถบควบคุม

ของเดิม 3 แถว:

```
[ค้นหา][จากวันที่][ถึง][ถึงวันที่][ค้นหา]              [+ สินค้าใหม่]
[ทั้งหมด][ยังไม่มี prompt][รอลงคลิป][ลงแล้ว] | [วันนี้][7 วัน][30 วัน] | ตามวัน: [ลงคลิป][สร้าง]
พบ 12 จาก 55  ล้างตัวกรองทั้งหมด
```

ของใหม่ 2 แถว:

```
[ค้นหาสินค้า....................] [ค้นหา]                [+ สินค้าใหม่]

| ทั้งหมด | ยังไม่มี prompt | รอลงคลิป | ลงแล้ว |      [วันที่ v]

พบ 12 จาก 55 รายการ · ล้างตัวกรองทั้งหมด
```

- **ตัวกรองสถานะ** = กลุ่มตัวเลือกที่มีกรอบรวมรอบทั้งกลุ่ม ตัวที่เลือกพื้นทึบ ตัวที่ไม่ได้เลือกโปร่งแต่อยู่ในกรอบเดียวกัน (แบบเดียวกับเมนูหลักในหัวเว็บที่ทำในโปรเจกต์ A) · สูง 36px · ตัวอักษร 14px ไม่ใช่ 10.4px ตัวพิมพ์ใหญ่ยืดตัวอักษรแบบเดิม
- **ตัวกรองวันที่** = ปุ่มเดียวที่โชว์ค่าปัจจุบันบนตัวปุ่ม
- ช่องวันที่ 2 ช่องที่เคยอยู่ในฟอร์มค้นหาย้ายเข้าไปในเมนูทั้งหมด

### 4.2 หัวคอลัมน์และแถว

```
รูป        สินค้า                          สถานะ           วันที่ลงคลิป
-----------------------------------------------------------------------
[80px]    ที่ลับเล็บแมว                    (จุด) ลงแล้ว        12 ก.ค.
          angle: โชว์แมวใช้จริง
```

- หัวคอลัมน์ตัวอักษร 12px สีจาง มีเส้นคั่นใต้ · **ไม่ใช่แถวที่กดได้** (ไม่มีการเรียงลำดับตามคอลัมน์ — การเรียงยังเป็นแบบเดิมจาก `lib/entry-sort.ts` คือยังไม่ลงคลิปอยู่บนสุด แล้วใหม่ไปเก่า)
- ชื่อสินค้า 18px หนา · บรรทัด angle 14px สีรอง
- **ป้ายกำกับที่พิมพ์ซ้ำในทุกแถวหายไปทั้งหมด** (`สถานะ` `วันที่` `ยอดขาย` `วิว`) เพราะหัวคอลัมน์บอกแล้ว — ป้ายเหล่านี้คือส่วนที่ทำให้แถวเดิมรกโดยไม่ให้ข้อมูลเพิ่ม
- **หัวคอลัมน์ที่ 4 เปลี่ยนตามฐานวันที่** — ฐาน `posted` แสดง `วันที่ลงคลิป` และค่าในแถวคือ `postedAt` · ฐาน `created` แสดง `วันที่สร้าง` และค่าในแถวคือ `createdAt` · ปัจจุบันแถวสลับข้อความเองต่อแถวระหว่าง "วันที่"/"สร้างเมื่อ" ซึ่งอ่านแล้วไม่รู้ว่าคอลัมน์นี้คืออะไรกันแน่
- **ตัดคอลัมน์ยอดขายและวิวออก** ทำให้ทุกแถวมีโครงเหมือนกันหมด ไม่มีบางแถวสูงกว่าเพราะมีข้อมูลขาย

## 5. เมนูตัวกรองวันที่

### 5.1 ป้ายบนปุ่ม

| สถานะ | ปุ่มเขียนว่า |
|---|---|
| ไม่ได้กรอง | `วันที่` |
| ตรงกับช่วงสำเร็จรูป | `วันนี้` / `7 วันล่าสุด` / `30 วันล่าสุด` |
| กำหนดเองสองด้าน | `5 ส.ค. - 20 ส.ค.` |
| กำหนดเองด้านเดียว | `ตั้งแต่ 5 ส.ค.` หรือ `ถึง 20 ส.ค.` |

ปุ่มไฮไลต์เมื่อมีการกรองอยู่ เพื่อให้เห็นแต่ไกลว่ารายการที่เห็นไม่ใช่ทั้งหมด

### 5.2 เนื้อในเมนู

```
(o) ทั้งหมด
( ) วันนี้
( ) 7 วันล่าสุด
( ) 30 วันล่าสุด
( ) กำหนดเอง
    [ 5 ส.ค. ] ถึง [ 20 ส.ค. ]      <- โผล่เฉพาะตอนเลือก "กำหนดเอง"
              [ ใช้ช่วงนี้ ]
    ------------------------------
    นับจาก:  [ลงคลิป] [สร้าง]
```

- 5 ตัวเลือกเป็นชุดเดียวกัน (เลือกได้ทีละอัน) — **นี่คือการแก้ที่รากของปัญหา** เพราะเดิมช่วงสำเร็จรูปกับกำหนดเองเป็น state คนละก้อน ค้างพร้อมกันได้ ทำให้ดูเหมือนใช้ร่วมกัน
- `ทั้งหมด` เป็นตัวเลือกจริงในลิสต์ ไม่ต้องไปหาลิงก์ล้างตัวกรองที่อื่น
- ช่องวันที่โผล่เฉพาะตอนเลือก "กำหนดเอง" เพื่อไม่ให้ชวนเข้าใจว่าใช้ร่วมกับช่วงสำเร็จรูปได้
- `นับจาก: ลงคลิป/สร้าง` ย้ายมาอยู่ในเมนูนี้เพราะเป็นส่วนหนึ่งของการตั้งค่าวันที่ ไม่ใช่ตัวกรองแยก

### 5.3 กลไก: ตัวกรองทั้งหมดอยู่ในฟอร์มเดียว

ค้นหา + สถานะ + วันที่ อยู่ใน `<form method="get" action="/">` ก้อนเดียวกัน การเลือกตัวกรองสั่ง submit ฟอร์ม URL เปลี่ยน server component เรนเดอร์ใหม่ตามเดิม

**อะไร submit ทันที อะไรไม่:**

| การกระทำ | submit ทันที |
|---|---|
| กดตัวกรองสถานะ | ใช่ |
| เลือก `ทั้งหมด` / `วันนี้` / `7 วันล่าสุด` / `30 วันล่าสุด` | ใช่ |
| เลือก `กำหนดเอง` | **ไม่** — แค่เปิดช่องวันที่ให้กรอก |
| แก้ค่าในช่องวันที่ | **ไม่** — กันหน้าเด้งทุกครั้งที่เปลี่ยนวัน |
| กด `ใช้ช่วงนี้` | ใช่ |
| สลับ `นับจาก: ลงคลิป/สร้าง` | ใช่ |
| กด `ค้นหา` | ใช่ (เหมือนเดิม) |

ได้:
- **คำค้นหาที่พิมพ์ค้างถูกพาไปด้วยอัตโนมัติ** เพราะอยู่ในฟอร์มเดียวกัน (ไม่ต้องอ่าน DOM หรือยก state ขึ้นไป)
- ตัวกรองทุกตัวมีผลทันทีเท่ากันหมด ไม่มีบางตัวต้องกดค้นหาก่อน
- ปุ่มแบ่งหน้าและ "ล้างตัวกรองทั้งหมด" ยังเป็นลิงก์ธรรมดา

เสีย:
- ปุ่มตัวกรองสถานะไม่ใช่ `<a href>` อีกต่อไป จึง**คลิกกลางเปิดแท็บใหม่ไม่ได้** (ปุ่มย้อนกลับของเบราว์เซอร์ยังทำงานปกติ เพราะ form GET สร้าง history entry เหมือนลิงก์) — ยอมรับได้เพราะเป็นเครื่องมือส่วนตัวผู้ใช้คนเดียว และความสม่ำเสมอของพฤติกรรมคือสิ่งที่ผู้ใช้บ่นถึงโดยตรง

### 5.4 URL ไม่เปลี่ยน

พารามิเตอร์ยังเป็น `?q=&status=&from=&to=&by=&page=` ชุดเดิมทุกตัว บุ๊กมาร์กเก่ายังใช้ได้ และ `lib/entry-date-filter.ts` กับ `lib/entry-rows.ts` ไม่ต้องแก้

การเลือกตัวกรองใดๆ ต้อง**รีเซ็ต `page` กลับเป็น 1** (form GET ไม่ส่ง `page` จึงได้พฤติกรรมนี้ฟรี)
