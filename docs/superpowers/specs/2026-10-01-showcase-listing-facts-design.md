# Showcase listing facts + claim check — design

> สถานะ: ร่าง 2026-10-01 · รอผู้ใช้ทบทวน

## ปัญหา

- งานที่เริ่มจาก Showcase ได้ `productName` = ชื่อร้านทั้งพวง (97–153 ตัว เต็มไปด้วยคำ SEO/โฆษณา) และ `productInfo`/`extraNotes` ว่าง — ต่างจากเส้นทางแคปเองที่ Gemini ย่อชื่อเหลือ 2–5 คำแล้วเก็บรายละเอียดไว้
- ข้อมูลจริงของสินค้าอยู่ใน**รูปแกลเลอรีของร้าน** (6–10 รูป/สินค้า มี infographic: ขนาด จำนวน วัสดุ จุดเด่น) แต่ไม่ได้ใช้เลย — ขั้น 0 สกัดสเปกจากรูปที่ Flow วาดใหม่เท่านั้น (อาจวาดจำนวนตะขอ/ชิ้นส่วนผิด)
- ตอนนี้ AI เขียนเสียงพากย์โดยมีแค่ชื่อ + รูป → มีโอกาสแต่งจุดขายที่หน้าสินค้าไม่ได้เขียน
- กฎ TikTok Shop: คำโฆษณาในคลิปต้อง**ตรงกับหน้าสินค้า/บรรจุภัณฑ์** และห้ามเสมอ (แม้ร้านเขียนเอง): การันตีผล, สุขภาพ/การรักษา, อันดับ 1/ดีที่สุด/ถูกที่สุด, รางวัล/ใบรับรองที่ยืนยันไม่ได้, ราคา/โปร

## เป้าหมาย / ไม่ใช่เป้าหมาย

- ✅ ชื่อสั้นเหมือนเส้นทางแคปเอง · ใช้ข้อความจากรูปร้านค้าให้ AI บรรยายสินค้าถูกและพูดเฉพาะสิ่งที่หน้าสินค้ายืนยัน · ตัดคำเสี่ยงทิ้งก่อนถึง AI · เตือนคำเสี่ยงในเสียงพากย์/แคปชันก่อนโพสต์ (ทุกคลิป)
- ❌ ไม่ดึงคำอธิบายสินค้าจาก API อื่นของ TikTok (ไม่ได้รับอนุญาต เพิ่มความเสี่ยงบัญชี) · ไม่ใช้ป้ายโปร/ราคา · ไม่แก้ข้อความให้อัตโนมัติ (แค่เตือน) · ไม่มี migration

## ส่วนประกอบ

### 1. ย่อชื่อตอน "ทำคลิปตัวนี้" (`startShowcaseProduct`)
- Gemini `EXTRACT_MODEL` (flash-lite) ข้อความล้วน structured output `{ shortName }` กฎเดียวกับ `EXTRACT_INSTRUCTION` ("2–5 คำ บอกว่าสินค้าคืออะไร") + ตัดคำโฆษณา (เกรดอาหาร, เหมาะหอพัก, ขายดี …)
- `productName` = ชื่อสั้น · `productInfo` = `ชื่อเต็มจากร้าน: <title>` (บรรทัดเดียว เป็นที่พักรอขั้น 2)
- Gemini ล้ม/โควตาหมด/ได้ค่าว่างหรือยาวเกิน 60 ตัว → ใช้ชื่อเต็มเหมือนเดิม **ห้ามทำให้การเริ่มงานพัง**
- ต้องเสร็จก่อนสร้างงาน Flow เพราะบอทพิมพ์ `productName` ในพรอมต์รอบ 1

### 2. อ่านรูปร้านค้า (ใน `generateWithAI` ก่อนขั้น 0)
- ทำเมื่อ entry ผูกกับ `ProductCandidate` ที่มี `CandidateImage` และ `productInfo` ยังเป็นค่าว่างหรือแค่บรรทัด `ชื่อเต็มจากร้าน:` (= ยังไม่เคยสกัด) → ครั้งเดียวต่อสินค้า
- ส่งรูปทั้งหมด (สูงสุด 10, ย่อด้านยาว ≤768px) + ชื่อเต็ม ให้ flash-lite ด้วย **structured output** (`response_format` ของ interactions API): รายการ `{ text, kind }` โดย `kind ∈ visual_fact | listing_claim | risky`
  - `visual_fact`: ขนาด/ตัวเลข, จำนวนชิ้น, วัสดุ, สี, รูปทรง, วิธีติดตั้ง/กลไก, ของที่ได้ในกล่อง
  - `listing_claim`: จุดเด่นที่ร้านเขียนไว้และไม่เข้าหมวด risky (เช่น "มุมมนกลม")
  - `risky`: การันตี, สุขภาพ/ความปลอดภัย/ฆ่าเชื้อ, อันดับ 1/ดีที่สุด/ถูกที่สุด, รางวัล/ใบรับรอง/มาตรฐาน, ราคา/โปร/ส่วนลด, ความทนทาน/รับน้ำหนักเชิงเปรียบเทียบเกินจริง — ไม่แน่ใจ = risky
- **โค้ด**เป็นคนคัด (pure function `formatListingFacts`) → เขียน `productInfo`:
  ```
  ชื่อเต็มจากร้าน: …
  ข้อเท็จจริงที่เห็นจากรูปร้านค้า (ใช้บรรยายรูปทรงให้ถูก):
  - …
  จุดเด่นที่หน้าสินค้าเขียนไว้ (เสียงพากย์พูดได้เฉพาะเรื่องในรายการนี้ ด้วยถ้อยคำกลางๆ ห้ามพูดจุดเด่นอื่นที่ไม่มีในรายการ):
  - …
  ```
  `risky` ไม่เข้าพรอมต์ (log จำนวนที่ตัดไว้ใน console เท่านั้น)
- ผ่าน regex คำต้องห้ามของข้อ 4 ซ้ำอีกชั้นกับทุกบรรทัดก่อนเขียน — โดนคำห้าม = ตัดบรรทัดนั้น (กัน AI ติดป้ายผิด)
- ล้มเหลว = ข้ามเงียบๆ (console.error) ไม่ทำให้ "สร้างด้วย AI" พัง · ครั้งหน้าที่กดสร้างใหม่จะลองอีก

### 3. ขั้น 0 เห็นรูปของจริงด้วย
- `extractProductSpec` รับรูปร้านค้า (สูงสุด 4 รูปแรก) เพิ่มต่อท้ายรูปที่ Flow วาด พร้อม caption `รูปจริงจากร้านค้า` · ยังสกัดเฉพาะตอน `productSpec` ว่าง (กฎเดิม)

### 4. ตัวตรวจคำเสี่ยง (ทุกคลิป ไม่ใช่แค่ Showcase)
- `lib/claim-check.ts` (pure, ไม่มี import): `checkClaims(text) → { word, level: "ban" | "check", snippet }[]`
  - `ban`: ดีที่สุด, อันดับ 1/อันดับหนึ่ง/เบอร์ 1, 100%, การันตี, รับประกันผล, ได้ผลแน่นอน, หายขาด, รักษา, ลดน้ำหนัก, ฆ่าเชื้อ, ทางการแพทย์, ถูกที่สุด, ราคาถูกที่สุด, ของแท้ 100%
  - `check` (ต้องตรงหน้าสินค้า): ปลอดภัย, ทนทาน, เกรดอาหาร, ไม่เป็นสนิม, ขายดี, กันน้ำ, รับน้ำหนัก
- ตรวจเฉพาะ**ข้อความที่จะออกสู่คนดู**: ประโยคหลัง `เสียงพากย์:` / บล็อก `Full voice-over script` ใน 10-part prompt + caption + hashtags (ไม่ตรวจ Negative Prompt ซึ่งมีคำห้ามเป็นตัวอย่าง)
- แสดง: การ์ด "พร้อมโพสต์" ใน /flow และแท็บ ② ของหน้า entry — กล่องเหลืองบรรทัดเดียวต่อคำ ("พบ 'ดีที่สุด' ในแคปชัน — ลบก่อนโพสต์" / "พบ 'ทนทาน' — เช็กว่าหน้าสินค้าเขียนไว้ไหม") ไม่บล็อกอะไร
- ตรวจกับข้อมูลจริงก่อนใช้: รันกับ 40 entry ล่าสุด อ่านทุกแถวที่โดนจับ ปรับรายการคำจนไม่มี false positive ที่ไร้สาระ (ตอนสำรวจพบ "ปลอดภัย" 2, "ทนทาน" 1 ในแคปชันจริง)

### 5. เติมย้อนหลัง
- สคริปต์ `scripts/backfill-showcase-facts.ts <entryId…>` ทำข้อ 1+2 ให้งานที่ระบุ (3 งานที่ยังไม่โพสต์) — ผู้ใช้รันเองด้วย `!` (แตะ dev.db จริง) · ไม่แตะ `productSpec` ที่มีแล้ว · พิมพ์ before/after + เวลาที่ใช้

## การทดสอบ
- pure: `formatListingFacts`, `checkClaims` (+ กรณี Negative Prompt ไม่โดน, คำในเสียงพากย์โดน), การเลือกว่าต้องสกัดไหม → เพิ่มใน `npm run check:flow` หรือสคริปต์ใหม่ใน `check:*`
- Gemini: สคริปต์ dry-run อ่าน dev-test.db + รูปจริงของ 3 สินค้า พิมพ์ผลแยกหมวด + เวลา — ผู้ใช้ดูว่าคัดคำเสี่ยงสะอาดไหมก่อนเปิดใช้
- `npx tsc --noEmit`, lint, UI smoke 1440/1920 บนพอร์ต 3001 กับ dev-test.db

## ความเสี่ยงที่ยอมรับ
- AI ติดป้ายผิดได้ → มี regex ซ้ำ + ตัวตรวจข้อ 4 + คนดูก่อนโพสต์เป็นด่านสุดท้าย
- โควตา flash-lite เพิ่ม ~2 ครั้ง/สินค้า → ล้มแล้วข้าม ไม่พัง
- "จุดเด่นที่หน้าสินค้าเขียนไว้" เข้าเสียงพากย์ได้ (ผู้ใช้เลือกแบบอิงหน้าสินค้า 2026-10-01)
