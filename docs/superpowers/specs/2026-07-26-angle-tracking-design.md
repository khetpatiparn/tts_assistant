# Angle ต่อคลิป — เลือก angle ใหม่ไม่ให้ซ้ำของเดิม (Design)

## Problem

ระบบแนะนำให้ "ทำ winner ซ้ำด้วย angle ใหม่" แต่**ไม่มีอะไรในระบบรู้จักคำว่า angle เลย** — `buildPromptText` (`lib/prompt-template.ts:52`) สั่งแค่ *"เลือก use case เดียวที่เหมาะที่สุด"* แล้วปล่อยให้ Gemini คิดเอง เมื่อ input เหมือนเดิม (ปุ่มทำซ้ำก๊อปทุกฟิลด์มาให้ครบ) ที่ temperature 0.3 โมเดลจึงวนกลับไปคิดแนวเดิม

เกิดขึ้นจริงแล้วกับ "ที่ลับเล็บแมว" (winner ที่ทำเงิน 1,914 บาท = 71% ของรายได้ทั้งช่อง): คลิปที่ทำซ้ำเมื่อ 2026-07-26 ได้ Scene/use-case แทบเป็นข้อความเดียวกับต้นฉบับ ต่างแค่การเลือกใช้คำ

ผู้ใช้ระบุความต้องการชัดเจน: **"เราไม่ได้อยากมานั่งคิด angle เองอะ เราอยากให้มีเลือก angle เองไปเลย แล้วก็สามารถ tracking ได้ด้วยว่า angle นี้ใช้ไปแล้วนะ"**

ปัญหาต่อเนื่องอีก 2 ข้อที่พบระหว่างออกแบบ:
- **การ์ด "ควรทำอะไรต่อ" ไม่มีความจำ** — `detectSignals` คำนวณใหม่จากตัวเลขทุกครั้ง ไม่รู้ว่าผู้ใช้ทำตามคำแนะนำไปแล้วหรือยัง เปิดมาอีกอาทิตย์ก็เห็นข้อความเดิมเป๊ะ แยกไม่ออกว่า "ยังไม่ได้ทำ" หรือ "ทำไปแล้ว"
- **ปุ่ม "สร้าง Prompt" เป็นกับดัก** — `brief-form.tsx:375` แสดงปุ่มนี้ตลอดเวลาแม้กำลังเลือก entry อยู่ และ `createPrompt` สร้าง entry ใหม่เอี่ยมที่ `duplicatedFromId = null` เสมอ กดพลาดหลังทำซ้ำ = สายเลือดขาด ระบบตามรอย angle ไม่ได้

## หลักการที่คุมดีไซน์นี้

**บันทึกให้ครบ ไม่ตัดสินแทน** — คำถาม "กี่ angle ถึงพอ" และ "angle เดิมดีกว่า angle ใหม่ไหม" เป็นคำถามเชิงประจักษ์ที่ยังตอบไม่ได้ (conversion ของช่อง 0.206% → คลิปทดสอบ 1 ตัวได้ 0-3 ออเดอร์ แยก "ได้ผล" จาก "ดวง" ไม่ออก) ระบบจึงต้อง**ไม่มีกฎจำกัดจำนวน angle และไม่จัดอันดับว่า angle ไหนดีกว่า** — หน้าที่คือเก็บ angle → ผลลัพธ์ ไว้ให้ครบ เพื่อให้คำถามเหล่านี้ตอบได้เองในอีกหลายเดือน

ผู้ใช้สรุปหลักการนี้เองว่า *"สิ่งนี้ก็ต้องได้จากการทดสอบคลิป ทดสอบระบบต่างๆนี่แหละ"*

## ข้อเท็จจริงจากโค้ด/ข้อมูลจริง (load-bearing — ตรวจสอบแล้ว 2026-07-26)

### การจัดกลุ่ม "สินค้าเดียวกัน"
- **ห้ามจัดกลุ่มด้วย `productName`** — ในฐานข้อมูลมี entry ที่ชื่อมีคำว่า "ลับเล็บ" อยู่ **5 อัน** และเป็น**สินค้าคนละชิ้นกันหลายตัว**: `"ที่ลับเล็บแมว"` (12 ก.ค. — ของเล่นไม้ 4-in-1 มีกังหัน+เสาป่าน = winner ตัวจริง), `"ที่ลับเล็บแมว"` (13 ก.ค. — **บ้านลับเล็บกระดาษลูกฟูก 2 ชั้น มีหน้าแมว คนละสินค้าสิ้นเชิง**), `"ของเล่นแมว ที่ลับเล็บแมว"` (16 ก.ค.), `"โซฟาแมว ที่นอนแมว...เก้าอี้ลับเล็บแมว"` (22 ก.ค.), `"ที่ลับเล็บแมว"` (26 ก.ค. — ตัวที่ทำซ้ำ) → ชื่อซ้ำแต่คนละสินค้า และสินค้าเดียวกันก็ตั้งชื่อไม่เหมือนกัน
- **ต้องจัดกลุ่มด้วยสายเลือด `duplicatedFromId`** — สะท้อน "เจตนา" ตอนผู้ใช้กดปุ่มทำซ้ำ ปัจจุบันมี entry เดียวในระบบที่มีค่านี้ (26 ก.ค. → 12 ก.ค.) และมันถูกต้อง (ตัด entry 13 ก.ค. ที่ชื่อซ้ำแต่คนละสินค้าออกอัตโนมัติ)
- ข้อจำกัดที่ยอมรับ: ถ้าผู้ใช้สร้าง entry ใหม่เองโดยไม่กดปุ่มทำซ้ำ จะไม่มีสายเลือด — ยอมรับได้เพราะปุ่มทำซ้ำประหยัดแรงกว่าอยู่แล้ว

### กับดักที่ต้องระวังในโค้ดปัจจุบัน
- **`duplicatePrompt` ก๊อป `chatgptOutput` มาด้วย** (`app/actions.ts:72`) → entry ที่ทำซ้ำแล้วยังไม่ได้ regenerate จะถือ 10-part prompt ของ**ต้นฉบับ**อยู่ ถ้าอ่าน angle จาก `chatgptOutput` แบบไม่กรอง จะนับ angle เดิมซ้ำสองครั้ง
- **`duplicatePrompt` ระบุฟิลด์ที่ก๊อปแบบ explicit list** (`app/actions.ts:64-77`) → คอลัมน์ `angle` ใหม่จะไม่ถูกก๊อปโดยอัตโนมัติ ซึ่งเป็นพฤติกรรมที่ต้องการ (คลิปใหม่ต้องได้ angle ใหม่) แต่ต้องมีคอมเมนต์กำกับกันคนมาเพิ่มทีหลัง
- **ฟอร์ม Brief ไม่มี path สำหรับ "อัปเดต" entry ที่มีอยู่** — ปุ่ม submit เรียก `createPrompt` เท่านั้น (`prompt-workspace.tsx:133-144`) และ `generateWithAI` อ่านค่าจาก **DB ไม่ใช่จากฟอร์ม** (`app/actions.ts:377-383`) → **ช่อง angle ต้องบันทึกลง DB ด้วย server action ของตัวเอง** ไม่ใช่เก็บใน form state ไม่งั้น `generateWithAI` จะไม่เห็นค่าเลย · มี precedent อยู่แล้วคือ `updateProductImageCaption` (`app/actions.ts:305-311`)
- รูปสินค้าที่แนบตอนมี entry ถูกเลือกอยู่ **อัปโหลดเข้า entry นั้นทันที** (`prompt-workspace.tsx:152-163`) ไม่ต้องกด submit — ยืนยันแล้วว่าการ "ลบรูปตอนใช้งานแล้วใส่รูปใหม่ + กดสร้างด้วย AI" รักษาสายเลือดไว้ครบ (entry 26 ก.ค. มี `duplicatedFromId` ครบ มีรูป 2 ใบ มี output และลงคลิปแล้ว)

### จุดเชื่อมกับโค้ดที่มีอยู่
- `buildPromptText` ถูกเรียก 2 ที่: `generateWithAI` (`app/actions.ts:377`) และ `getFewShotExamples` (`lib/few-shot.ts:33`) → เพิ่มพารามิเตอร์ `angle` ต้องแก้ทั้งสองที่ (few-shot ส่ง `""`)
- `detectSignals` คืน `ClipSignal` ที่มี `entryId` อยู่แล้ว (`lib/recommender.ts:19-26`) → เอาไปหาสายเลือดต่อได้ทันที
- `Recommendations` รับ prop `entries: { id, productName }[]` (`components/recommendations.tsx:23`) ซึ่งมาจาก `dashboardEntries` ใน `prompt-workspace.tsx:271-282` (เพิ่งมี `postedAt` เข้าไปแล้วจากงาน scoreboard) → ต้องเพิ่ม `duplicatedFromId` เข้าไปด้วย
- `GEMINI_MODELS` เป็นแหล่งเดียวของรายชื่อโมเดล (`lib/gemini.ts:9`) · งานข้อความล้วนล็อกที่ `gemini-3.1-flash-lite` เสมอ (precedent: `CAPTION_MODEL`, `EXTRACT_MODEL`)

## Design

### 1. Data model — คอลัมน์เดียว ไม่มีตารางใหม่

```prisma
model PromptEntry {
  // ...ฟิลด์เดิม
  angle String @default("")   // angle ที่เลือกใช้กับคลิปนี้ (ข้อความอิสระ 1-2 บรรทัด)
}
```

**เลือกเก็บเป็นข้อความอิสระ ไม่ใช่หมวดหมู่ตายตัว** — สินค้าในช่องกระจายมาก (ของเล่นแมว, ชั้นวางของ, โต๊ะรีดผ้า, ราวตากผ้า, ผ้าม่าน) หมวด angle ที่ครอบคลุมทุกหมวดสินค้าได้จะกว้างจนไร้ประโยชน์ ส่วนการกันซ้ำไม่ต้องแม่น 100% — ให้ Gemini อ่านข้อความเดิมแล้วเลี่ยงเองก็เพียงพอ

### 2. นิยาม "angle ที่ใช้ไปแล้ว" (จุดที่พลาดง่ายที่สุด)

หาสมาชิกครอบครัวจากสายเลือด แล้ว**แบ่ง 3 สถานะ**:

| สถานะ | เงื่อนไข | นับเป็น "ใช้ไปแล้ว"? |
|---|---|---|
| **ลงแล้ว** | `videoUrl` ไม่ว่าง | **ใช่** — angle จาก `angle` ถ้ามี ไม่มีก็สกัดจาก `chatgptOutput` |
| **วางแผนไว้** | ยังไม่ลง + `angle` ไม่ว่าง | **ใช่** (แสดงแยกว่า "ยังไม่ได้ลง") |
| **ร่างเปล่า** | ยังไม่ลง + `angle` ว่าง | **ไม่** — ข้ามทิ้ง |

**ทำไมต้องข้ามร่างเปล่า:** `duplicatePrompt` ก๊อป `chatgptOutput` ของต้นฉบับมาด้วย ถ้าไม่กรอง entry ที่ยังไม่ได้ regenerate จะถูกอ่านว่า "ใช้ angle เดียวกับต้นฉบับ" ทั้งที่ยังไม่มีคลิปอยู่จริง → รายการ angle จะซ้ำตัวเองทันที

### 3. ปุ่ม "เสนอ angle ใหม่" (AI ช่วยคิด ผู้ใช้เลือก)

Server action ใหม่ `suggestAngles(entryId)`:
- หา angle ที่ใช้ไปแล้วตามตาราง §2
- ส่งให้ Gemini (`ANGLE_MODEL = "gemini-3.1-flash-lite"` ล็อกไว้ เหตุผลเดียวกับ `CAPTION_MODEL`/`EXTRACT_MODEL`): ชื่อสินค้า + ข้อมูลสินค้า + รายการ angle ที่ใช้แล้ว → ขอ **3 ตัวเลือก พร้อมเหตุผลสั้น 1 บรรทัด** โดยต้องต่างจากที่ใช้ไปแล้วอย่างชัดเจน
- `temperature` สูงกว่างานสกัด (0.9) เพราะงานนี้ต้องการความหลากหลาย ไม่ใช่ความแม่น
- parser อยู่ใน `lib/angle.ts` ตามแบบ `lib/caption.ts` — **ผิดฟอร์แมตแล้วไม่ throw** คืนทั้งก้อนเป็นตัวเลือกเดียวแทนการทิ้งโควตาที่จ่ายไปแล้ว
- **ไม่ revalidatePath** — action นี้ไม่แตะข้อมูล (แบบเดียวกับ `extractProductInfo`)

การสกัด angle จาก `chatgptOutput` ของคลิปเก่า (สำหรับ entry ที่ทำก่อนมีฟีเจอร์นี้) เป็น pure function ใน `lib/angle.ts`:
- ดึงหัวข้อ **Scene** + บรรทัด **Full voice-over script** จาก 10-part prompt
- regex ต้องทนการเยื้องบรรทัด (ข้อมูลจริงมีทั้งแบบเยื้อง 3 ช่องและไม่เยื้อง)
- สกัดไม่ได้ → fallback เป็น 600 ตัวอักษรแรก **ไม่ throw**
- ไม่ migrate ข้อมูลเก่า ไม่เขียนทับ `angle` ของ entry เดิม — สกัดสดตอนต้องใช้

### 4. แผง "Angle ของคลิปนี้" — คอมโพเนนต์แยก

สร้าง `components/angle-panel.tsx` **แยกจาก `brief-form.tsx`** (ซึ่งใหญ่อยู่แล้ว) แสดงในแท็บ Brief เมื่อมี entry ถูกเลือก:

```
Angle ของคลิปนี้
┌ เคยใช้กับสินค้านี้แล้ว 1 angle ─────────────────────┐
│ • แมวเบื่อของเล่นเดิม — แมวเล่นเองในห้องนั่งเล่น      │
│   ลงแล้ว 1 ก.ค. · 67,703 วิว · 131 ออเดอร์ · 1,914฿  │
└──────────────────────────────────────────────────────┘
[ เสนอ angle ใหม่ ]

<textarea>  angle ของคลิปนี้ (บันทึกเมื่อออกจากช่อง)  </textarea>
```

- กดปุ่มเสนอ → แสดง 3 ตัวเลือกพร้อมเหตุผล → คลิกอันใดอันหนึ่ง = เติมลง textarea (ยังแก้ได้) → บันทึกลง DB
- **บันทึกด้วย server action `saveAngle(entryId, angle)` ตอน blur** (แบบ `updateProductImageCaption`) ไม่ใช่ผ่าน form submit — เพราะ `generateWithAI` อ่านจาก DB
- **ตัวเลข วิว/ออเดอร์/รายได้ เป็นข้อเท็จจริงล้วน** ไม่มีการจัดอันดับ ไม่มีป้าย "angle นี้ดีที่สุด" — ผู้ใช้เห็นตัวเลขแล้วตัดสินเอง
- แผงนี้ทำหน้าที่เป็น**ความจำระดับสินค้า**ด้วย: สินค้าที่เคยลองหลาย angle แล้วได้ 0 ออเดอร์จะเห็นชัดเองตอนกำลังจะทำซ้ำ (แก้ปัญหา "ลืมว่าระบบเคยเตือนว่าสินค้านี้หยุดแล้ว") โดยไม่ต้องมีคำเตือนค้างในการ์ดรวมให้รก

### 5. ส่ง angle เข้าโจทย์ AI

`buildPromptText` รับ `angle` เพิ่ม:
- **angle ว่าง** → พฤติกรรมเดิมเป๊ะ (Gemini เลือก use case เอง) — ต้องไม่ regress กับ 55 entries เดิม
- **angle ไม่ว่าง** → เพิ่มบล็อก `Angle ที่ต้องใช้สำหรับคลิปนี้` และ**เปลี่ยนคำสั่งข้อแรก** จาก *"เลือก use case เดียวที่เหมาะที่สุด"* เป็น *ใช้ angle ที่กำหนดให้ ห้ามเลือกเอง* (สองประโยคนี้ขัดกันถ้าปล่อยไว้ทั้งคู่)
- `lib/few-shot.ts` ส่ง `angle: ""` (golden examples ไม่มี angle)
- **ความเสี่ยงที่ต้องตรวจ:** golden examples ถูกสร้างขึ้นตอนไม่มี angle โมเดลอาจไหลไปตาม angle ของตัวอย่างแทนที่จะทำตามที่สั่ง → verification ต้องเช็กว่า output สะท้อน angle ที่เลือกจริง

### 6. บรรทัดสถานะในการ์ด "ควรทำอะไรต่อ"

`components/recommendations.tsx` เพิ่มบรรทัดใต้ signal ที่มีสายเลือดลูก โดยใช้ข้อมูลที่มีอยู่แล้ว (`duplicatedFromId` + `postedAt`) — **ไม่มีตารางใหม่ ไม่มี checkbox**:

```
[กำลังมา]  ที่ลับเล็บแมว
ทำ angle ใหม่ซ้ำตอนนี้
วิวเพิ่ม 4,649 ในรอบล่าสุด · 131 ออเดอร์ · conv 0.19%
→ ทำซ้ำไปแล้ว 1 คลิป · ลงล่าสุด 26 ก.ค.
```

**เลือก "บอกสถานะ" ไม่ใช่ "ซ่อนคำแนะนำ"** — ถ้าซ่อน ผู้ใช้จะไม่รู้ว่าคลิปต้นฉบับยังโตอยู่ (ข้อมูลที่มีค่า) และถ้าคลิปที่ทำซ้ำไม่เวิร์กก็ยังอยากเห็นว่าตัวเดิมยังฮอต · **ไม่ใช้ checkbox ให้ติ๊กเอง** เพราะปัญหาต้นทางของผู้ใช้คือลืม/ไม่ได้ทำ — การเพิ่มของที่ต้องจำไปติ๊กคือการเพิ่มสิ่งที่ลืมได้อีกอย่าง (บทเรียนเดียวกับที่ตัด quest/gamification ออกไป) สายเลือดตรวจได้เองและลืมไม่ได้เพราะไม่ต้องทำอะไร

### 7. ปิดกับดักปุ่ม "สร้าง Prompt"

เมื่อมี entry ถูกเลือกอยู่ (`selectedId !== null`) เปลี่ยนป้ายปุ่มเป็น **"สร้างเป็นรายการใหม่"** พร้อมข้อความกำกับเล็กๆ ว่าจะได้รายการใหม่ที่**ไม่ผูกกับสินค้าเดิม**

**ไม่ซ่อนปุ่มทิ้ง** เพราะมันเป็นกลไก "สร้าง variant" ที่มีมาก่อนปุ่มทำซ้ำ และไม่มี path อื่นแทน — แก้ด้วยความชัดเจนแทนการตัดความสามารถ (การทำ path อัปเดตฟอร์มจริงเป็นงานคนละก้อน อยู่นอกขอบเขต)
