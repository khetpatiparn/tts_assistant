# Responsive Mobile/Tablet UI — Design

วันที่: 2026-08-22

## ปัญหา

ผู้ใช้ออกไปข้างนอกบ่อยและมีเวลาว่าง แต่ทำคลิปไม่ได้เพราะไม่ได้เอา notebook ไปด้วย ต้องการใช้ระบบนี้บนมือถือและแท็บเล็ต

ปัญหานี้มีสองชั้นที่ต้องแยกจากกัน:

1. **เข้าถึงเครื่องไม่ได้** — แอปรันบนเครื่องที่บ้าน ซึ่งไม่มีเน็ตตอนผู้ใช้ออกไปข้างนอก
2. **หน้าจอไม่รองรับ** — UI ออกแบบมาแบบ desktop-first

## ขอบเขตของเอกสารนี้

เอกสารนี้ครอบคลุม **ชั้นที่ 2 เท่านั้น**

ชั้นที่ 1 (ย้ายขึ้น cloud) ออกแบบและคิดต้นทุนเสร็จแล้ว แต่ **ผู้ใช้ตัดสินใจพักไว้จนกว่ายอดขายเฉลี่ยจะแตะ ฿500-600/วัน** สรุปสั้น ๆ ของสิ่งที่ตัดสินใจไปแล้วเพื่อไม่ให้ต้องคิดซ้ำ:

- **Tailscale / Cloudflare Tunnel / port forwarding ใช้ไม่ได้** — เน็ตหลักของคอมคือ hotspot จากมือถือผู้ใช้ พอผู้ใช้ออกจากบ้าน เน็ตเดินตามไปด้วย ไม่มีเครื่องมือไหนแก้ได้
- **แผนที่เลือกแล้วคือ Fly.io + `auto_stop_machines`** ~$2/เดือน (฿65) — วาง `dev.db` + `uploads/` บน volume เดียวกัน ไม่ต้องแตะ Prisma/SQLite/`better-sqlite3` เลย เหลืองานจริง 3 อย่าง (Dockerfile, middleware รหัสผ่านเดียว, ย้ายข้อมูลครั้งเดียว)
- **DigitalOcean ออกจาก GitHub Student Pack แล้ว** (31 ก.ค. 2026) · **Heroku ($13 × 24 เดือน) ไม่คุ้ม** เพราะ filesystem เป็น ephemeral ต้องรื้อ SQLite→Postgres และ `uploads/`→R2
- **ไม่ทำ hybrid (local + cloud สลับกัน)** — จะได้ `dev.db` สองไฟล์ที่ merge ไม่ได้ และไม่จำเป็น เพราะเน็ตของผู้ใช้คือมือถือที่อยู่กับตัวเสมอ cloud จึงครอบคลุมทั้งบ้านและข้างนอก

**ค่าที่งานนี้ให้ทันทีก่อนถึง trigger:** ตอนอยู่บ้าน มือถือคือ hotspot คอมจึงอยู่บน LAN เดียวกัน เปิด `http://192.168.x.x:3000` จากมือถือ/แท็บเล็ตได้เลย ไม่เสียเงิน — คือ "ทำคลิปบนโซฟา/เตียงแทนที่จะต้องนั่งโต๊ะ" ส่วน "ทำคลิปตอนอยู่ข้างนอก" ต้องรอ cloud

## หลักการ

### 1. `lg:` ขึ้นไปห้ามแตะ

```
0-639px     (base)  โทรศัพท์            ← งานใหม่เกือบทั้งหมด
640-767px   sm:     โทรศัพท์แนวนอน
768-1023px  md:     แท็บเล็ต → 2 คอลัมน์  ← งานใหม่ส่วนที่เหลือ
1024px+     lg:     เดสก์ท็อป            ← ของเดิมทั้งหมด ไม่แตะ
```

โค้ดเดิมใช้ `lg:` เป็นเส้นแบ่งเลย์เอาต์เดสก์ท็อปอยู่แล้ว (`app/layout.tsx:48`, `components/entry-workspace.tsx:230,245`) เส้นนี้จะไม่ถูกย้าย และคลาส `lg:`/`xl:` ทุกตัวที่มีอยู่จะเหลือเหมือนเดิมทุกตัวอักษร

**เหตุผล:** ผู้ใช้ทำคลิปหาเงินด้วยแอปนี้ทุกวันบนเดสก์ท็อป ความเสี่ยงที่งาน responsive จะไปทำให้เลย์เอาต์เดสก์ท็อปพังต้องเป็นศูนย์ · หน้าจอ 1440px คือหนึ่งใน checkpoint การทดสอบบังคับ

### 2. ไม่ทำ bottom tab bar

พิจารณาแล้วไม่คุ้ม — เป็นคอมโพเนนต์ใหม่ที่ต้องดูแลคู่ขนานกับ `app-header.tsx` ตลอดไป เพื่อแลกกับเมนูแค่ 4 อัน และชนกับแถบล่างของ Safari/Chrome บนมือถือ

ใช้การย่อหัวเว็บแทน: ที่ base ซ่อนคำโปรย (`app-header.tsx:38-40`) และย่อหัวข้อ ปัจจุบันหัวเว็บกิน ~140px จากจอสูง 780px (18%) ลดเหลือ ~80px

### 3. กติกา UI ที่ยึดตามเดิม + หนึ่งข้อที่แก้

ยึดตาม CLAUDE.md ทุกข้อ: ห้ามขนาดตัวอักษร arbitrary (`text-[...]`) · ห้าม hex ใน `components/*` · `--border` (ตกแต่ง) กับ `--border-interactive` (กดได้ ต้องผ่าน 3:1) ห้ามสลับกัน · line-height ไทย ≥ 1.6 · ห้าม `tracking-widest`/`uppercase` กับข้อความไทย · `node scripts/check-contrast.mjs` ต้องผ่านถ้าแตะสี

**แก้หนึ่งข้อ (ผู้ใช้อนุมัติแล้ว):** กฎ "ปุ่มสูงขั้นต่ำ 36px" ตั้งมาสำหรับเมาส์ → เปลี่ยนเป็น **36px ที่ `lg:` ขึ้นไป (เหมือนเดิม) และ 44px ที่ต่ำกว่านั้น** ไม่ใช่ลดเกณฑ์ แต่เพิ่มเกณฑ์เฉพาะบนสัมผัส (Apple แนะนำ 44px, Google 48px) ต้องอัปเดต CLAUDE.md ตอนจบงาน

### 4. Next.js เวอร์ชันนี้เป็น build พิเศษ

`next` pinned ที่ `16.2.10` — ต้องอ่าน `node_modules/next/dist/docs/01-app/` ก่อนเขียนโค้ดที่แตะ `next/image` และ viewport metadata ห้ามเดาจาก API ที่คุ้นเคย · Recharts เป็น v3.9.2 ต้องเช็ก `node_modules/recharts/types/` จริงก่อนแก้กราฟ

## เฟส 1 — ทำให้ใช้งานได้จริง

เป้าหมาย: **เปิดจากมือถือแล้วทำคลิปได้จนจบโดยไม่มีอะไรขวาง** ไม่ใช่ความสวยงาม

### 1.1 `history-rail.tsx` → ลิ้นชัก

**ปัญหา:** บรรทัด 53 `w-full ... lg:w-60` — ต่ำกว่า `lg:` ไม่ใช่ sidebar แต่เป็นบล็อกเต็มความกว้างที่วางอยู่**เหนือ**ฟอร์ม ทุกครั้งที่เปิดหน้า entry บนมือถือต้องเลื่อนผ่านรายการ 15 อันก่อนถึงช่องกรอกบรีฟ

**แก้:** ต่ำกว่า `lg:` ห่อด้วย `Drawer` จาก `@base-ui/react/drawer` (มี `swipe-area` และ `virtual-keyboard-provider` มาให้ในตัว) เปิดจากปุ่มใหม่ใน `entry-header.tsx` · `lg:` ขึ้นไปยังเป็น `<aside>` เดิม

**ไม่ใช้ `hidden lg:flex`** เพราะการสลับไปงานอื่นเร็ว ๆ คือประโยชน์จริงของแถบนี้ ถ้าซ่อนทิ้งต้องกลับไปหน้า `/` ทุกครั้ง

### 1.2 เมนู ⋮ ที่มองไม่เห็นบนสัมผัส

**ปัญหา:** `history-rail.tsx:112` ใช้ `opacity-0 ... group-hover:opacity-100` — จอสัมผัสไม่มี hover **เมนูทำซ้ำ/ลบจึงหายไปทั้งหมด** นี่คือฟีเจอร์ที่ใช้ไม่ได้จริง ไม่ใช่เรื่องความสวยงาม

**แก้:** `opacity-100 lg:opacity-0 lg:group-hover:opacity-100` + เป้าสัมผัส 44px ที่ base

### 1.3 `entry-list.tsx` → การ์ดที่ต่ำกว่า `md:`

**ปัญหา:** แถว (บรรทัด 132-169) ใช้ความกว้างตายตัว: รูป `size-20` (80) + สถานะ `w-32` (128) + วันที่ `w-28` (112) + gap/padding ≈ **392px ก่อนที่ชื่อสินค้าจะได้พื้นที่** บนจอ 390px ชื่อสินค้าเหลือศูนย์

**แก้:**

```
base–md:   [รูป 64px] ชื่อสินค้า
                      [badge สถานะ] วันที่
md: ขึ้นไป: แถวเดิมทุกพิกเซล (w-32 / w-28 / size-20 คงไว้)
```

หัวคอลัมน์ (บรรทัด 119-127, `aria-hidden`) ซ่อนที่ base เพราะไม่มีคอลัมน์ให้หัวแล้ว

### 1.4 ปุ่มคัดลอกต้องไม่ตาย — 3 จุด

**ปัญหา:** `navigator.clipboard` ทำงานเฉพาะ secure context (HTTPS หรือ localhost) การเปิดจากมือถือผ่าน LAN คือ HTTP ธรรมดา **ปุ่มคัดลอกจึงตายเงียบ** ซึ่งเป็นหัวใจของ workflow ทั้งหมด (คัดลอก prompt ไป Google Flow)

จุดที่กระทบ:
- `entry-workspace.tsx:204` — 10-part prompt
- `production-panel.tsx:74` — caption + hashtags
- `production-panel.tsx:80` — prompt ซ้ำ

**แก้:** สร้าง `lib/clipboard.ts` ตัวเดียวใช้ร่วมกัน 3 ชั้น:
1. ลอง Clipboard API
2. ถ้าไม่ได้ → textarea ชั่วคราว + `document.execCommand("copy")`
3. ถ้ายังไม่ได้ → เปิดกล่องข้อความที่ select ทั้งหมดไว้แล้ว พร้อมข้อความ "กดค้างเพื่อคัดลอก"

**ต้องรายงานความล้มเหลว** — ปัจจุบัน `handleCopy` ตั้ง `copied=true` ทันทีโดยไม่เช็กว่าสำเร็จจริงไหม

### 1.5 Thumbnail — ลดหน้ารายการจาก ~13MB เหลือ ~0.4MB

**ปัญหา:** ทั้ง 3 จุดเสิร์ฟรูปต้นฉบับเต็มขนาดด้วย `<img>` ธรรมดา (`eslint-disable @next/next/no-img-element`) ข้อมูลจริง: `uploads/` 205 MB / 308 ไฟล์ = **เฉลี่ย 665 KB ต่อรูป** หน้ารายการ 20 แถว ≈ 13 MB ต่อการเปิดหนึ่งครั้ง บน 4G คือทั้งช้าและเปลืองเน็ตของผู้ใช้เอง

**แก้:** ใช้ `next/image` (ไม่ต้อง backfill รูปเก่า 308 ไฟล์ — optimizer ย่อและ cache ให้เอง และ `sharp` ติดตั้งอยู่แล้ว) ขนาดที่ขอจาก optimizer ต้องตรงกับขนาดที่แสดงจริงคูณ DPR 2:

| จุด | ขนาดแสดง | ขนาดที่ขอ |
|---|---|---|
| `entry-list.tsx:139` | 64px (base) / 80px (`md:`) | 160px |
| `history-rail.tsx:86` | 36px | 72px |
| `brief-form.tsx:444` | ตามแผงแก้ caption | 400px — ต้องดูรายละเอียดสินค้าเพื่อเขียน caption จึงย่อมากไม่ได้ |

**ทางเลือกที่ไม่เลือก:** สร้างไฟล์ thumbnail ตอนอัปโหลดด้วย `sharp` — ตัดทิ้งเพราะต้อง backfill 308 ไฟล์เดิมและเพิ่มสถานะบนดิสก์ที่ต้องดูแล

### 1.6 หน่วย viewport + safe area

**ปัญหา:** `entry-workspace.tsx:230` ใช้ `min-h-screen` / `lg:h-screen` — `vh` บนมือถือคิดรวมแถบ URL ที่ยุบเข้าออก ทำให้เนื้อหาโดนตัด

**แก้:** เปลี่ยนเป็น `dvh` · เพิ่ม `viewport` export ใน `app/layout.tsx` พร้อม `viewport-fit=cover` และ padding safe-area สำหรับรอยบากไอโฟน

**ห้ามปิดการซูม** (`maximum-scale=1` / `user-scalable=no`) — เป็นปัญหา accessibility

### 1.7 หัวเว็บย่อขนาด

- `app-header.tsx` — ซ่อนคำโปรยบรรทัด 38-40 ที่ base, ย่อหัวข้อ, ปุ่มและเมนูขึ้นเป็น 44px
- `entry-header.tsx` — ต้องมีที่ให้ปุ่มเปิดลิ้นชัก (1.1)

### ไม่อยู่ในเฟส 1

`/products`, `/dashboard`, กราฟ, `entry-filters.tsx` — ตัวสุดท้ายใช้ `flex-wrap` + Popover + `h-9` อยู่แล้ว รอดบนมือถือแบบพอใช้ได้

## เฟส 2 — ขัดหน้าที่เหลือ

### 2.1 `/products` — ตาราง 10 คอลัมน์ → การ์ด

`candidates-route.tsx` (491 บรรทัด) — หนักที่สุดในเฟสนี้

**ปัญหา A:** ตาราง `min-w-[64rem]` (1024px) มี `overflow-x-auto` ครอบ จึงไม่พังทั้งหน้า แต่บนมือถือคือการเลื่อนซ้ายขวาหาข้อมูลตลอดเวลา คอลัมน์: ชื่อ · หมวด · ป้าย · ราคา · ค่าคอม · ขาย/สัปดาห์ · % · ศักยภาพรายได้ · คำเตือน · จัดการ

**ปัญหา B (ร้ายกว่า):** ข้อความคำเตือนฉบับเต็มเก็บไว้ใน `title=` อย่างเดียว (คอมเมนต์บรรทัด ~318 เขียนไว้เองว่า "เอาเมาส์ชี้") **บนจอสัมผัสไม่มีการเอาเมาส์ชี้ คำเตือนทั้งหมดจึงหายไปเงียบ ๆ** — หน้าหาสินค้าบนมือถือจะไม่บอกเลยว่าสินค้าไหนมีปัญหา

**แก้:** ต่ำกว่า `md:` เปลี่ยนเป็นการ์ด เลือกเฉพาะสิ่งที่ใช้ตัดสินใจจริง — ชื่อ + ป้ายเป็นหัว, ศักยภาพรายได้เด่นสุด (เป็นตัวจัดอันดับอยู่แล้ว), ราคา/ค่าคอม/ขายต่อสัปดาห์เป็นแถวรอง, **คำเตือนเป็นข้อความจริงไม่ใช่ `title`** · `md:` ขึ้นไปยังเป็นตารางเดิม

**ห้ามทำพัง:** คอมเมนต์บรรทัด 285-296 อธิบายว่าทำไมต้องมี `relative` (กัน `sr-only` หลุดไปยืด scrollWidth ของหน้าเพจ 209px) และทำไมหัวตารางถึงไม่ sticky — ต้องรักษาไว้

### 2.2 กราฟรายได้ — `revenue-charts.tsx`

ใช้ `ResponsiveContainer width="100%"` อยู่แล้ว จึงไม่พัง แค่อ่านยาก: `YAxis width={64}` กินไป 16% ของจอ 390px และ tick วันที่จะเบียดกันจนอ่านไม่ออก

**แก้:** ลด `YAxis width` และตั้ง `interval` บนมือถือ — เช็ก `node_modules/recharts/types/` ก่อน (v3.9.2 API ต่างจากตัวอย่าง v2 ทั่วไป)

### 2.3 แผงข้อมูลที่เหลือ

`revenue-by-clip.tsx` · `recommendations.tsx` · `angle-panel.tsx` · `import-log-panel.tsx`

ทั้งหมดใช้ `flex ... gap` กับ `flex-wrap` อยู่แล้ว งานคือให้แถวยุบเป็นแนวตั้งที่ base + เป้าสัมผัส 44px **ไม่ต้องรื้อโครง**

หมายเหตุ: `revenue-by-clip.tsx` แบ่งเงิน 3 ทาง (จ่ายแล้ว/รอ/ไม่มีสิทธิ์) ซึ่งต้องตรงกับ `summarizeOrders` เสมอ — งานนี้แตะเฉพาะเลย์เอาต์ ห้ามแตะตรรกะแบ่งเงิน

### 2.4 หน้าทำงาน entry

- **`brief-form.tsx` (539 บรรทัด)** — พึ่ง paste รูปเป็นทางหลัก (`window` paste listener บรรทัด 210) ซึ่งบนมือถือแทบใช้ไม่ได้ ต้องดัน `<input type="file">` (บรรทัด 287, 516) ขึ้นมาเป็นทางหลักที่เห็นชัดบนมือถือ
- **HEIC** — `accept="image/jpeg,image/png,image/webp"` ไม่รับฟอร์แมตกล้องไอโฟน ต้องทดสอบจริงว่ามือถือของผู้ใช้ส่งอะไรมา (iOS Safari มักแปลงให้อัตโนมัติ, Android อาจไม่)
- **`production-panel.tsx`** — textarea สูงเหมาะกับมือถือ · ระวัง `toDateInputValue` (UTC) กับ `toLocalDateInputValue` (local) ห้ามสลับกัน
- **`date-picker-field.tsx`** — ต้องกดง่ายด้วยนิ้ว

### 2.5 หน้าที่เหลือ

`dashboard-panel.tsx` · `core-prompt-panel.tsx` · `entry-filters.tsx` — เบาที่สุด ทั้งสามมี `sm:grid-cols-2` / `xl:flex-row` / `flex-wrap` อยู่แล้ว เหลือช่องค้นหาเต็มความกว้างบนมือถือ, ฟอร์มอัปโหลดยุบแนวตั้ง, เป้าสัมผัส

### 2.6 งานกวาดท้ายเฟส

## การตรวจสอบ

โปรเจกต์นี้ไม่มี test runner การตรวจสอบจึงเป็นการรันจริง และต้อง**ไม่ไปรบกวน `start.bat` ของผู้ใช้ที่รันอยู่บน port 3000**

1. `npx tsc --noEmit` — เช็ก type โดยไม่เขียน `.next`
2. `npm run lint` — ไม่แตะ `.next`
3. `cp dev.db dev-test.db` แล้ว `NEXT_DIST_DIR=.next-dev DATABASE_URL="file:./dev-test.db" npm run dev -- -p 3001`
4. Playwright (ติดตั้งใน scratch dir แยก ไม่ใช่ dependency ของโปรเจกต์) ถ่าย screenshot ที่ **390px / 820px / 1440px**
   - **1440px คือ checkpoint บังคับ** — พิสูจน์ว่าเลย์เอาต์เดสก์ท็อปไม่เปลี่ยน
5. `node scripts/check-contrast.mjs` ถ้าแตะสี
6. `git diff tsconfig.json` ก่อน commit — dev server อาจ auto-patch (repo pin `target: "ES2017"` ไว้ตั้งใจ)
7. `npm run build` เต็มรูปแบบเฉพาะตอนปิดงาน และต้องเช็ก port 3000 ว่างก่อน — ถ้าไม่ว่างให้ถามผู้ใช้ **ห้าม kill เอง**

**ห้ามใช้ `dev.db` ตัวจริงตอนทดสอบ UI** — เคยมี entry ทดสอบค้างในข้อมูลจริงมาแล้ว และ SQLite ไม่ได้เปิด WAL จึงเสี่ยง lock ชนกันถ้าเขียนพร้อมผู้ใช้

### สิ่งที่ screenshot อย่างเดียวพิสูจน์ไม่ได้ — ต้องทดสอบด้วยมือบนเครื่องจริง

- ลิ้นชักเปิด/ปิด/ปัดได้จริงบนนิ้ว
- ปุ่มคัดลอกทั้ง 3 จุดทำงานจริงเมื่อเปิดผ่าน LAN แบบ HTTP (นี่คือกรณีที่ fallback มีไว้เพื่อ)
- อัปโหลดรูปจากคลังภาพมือถือได้จริง และฟอร์แมตที่ได้มาไม่ถูกปฏิเสธ
- เมนู ⋮ กดได้จริงบนสัมผัส

## ลำดับการทำ

เฟส 1 ทั้งหมด → ผู้ใช้ลองใช้จริงบนมือถือผ่าน LAN → แก้ตามที่เจอ → เฟส 2
