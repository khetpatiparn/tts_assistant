# ธีมและตัวอักษรใหม่ — Navy + Brass, สลับสว่าง/มืดได้

วันที่: 2026-08-08 · สถานะ: อนุมัติแล้ว รอทำแผนลงมือ

## 1. ปัญหาที่แก้

ผู้ใช้รายงาน 3 อาการ:

1. ธีมสว่างเกินไปจนตาล้าเมื่อใช้ต่อเนื่องนานๆ (ใช้แอปนี้ทำงานทุกวัน)
2. อยากให้ข้อความไทยใช้ Noto Sans Thai
3. ตัวอักษรเล็กเกินไป และ **แยกไม่ออกว่าอะไรกดได้** ถ้าไม่ลองกดดู

ข้อ 3 ไม่ใช่ความรู้สึก — วัดได้จากโค้ดปัจจุบัน:

| ของที่วัดได้ | ค่าปัจจุบัน | เกณฑ์ |
|---|---|---|
| ตัวอักษรเล็กสุด (`text-[0.55rem]`) | 8.8px | ขั้นต่ำ 12px |
| จำนวนจุดที่ตัวอักษรต่ำกว่า 12px | 23 จุด / 9 ไฟล์ | 0 |
| ขอบในโหมดมืด `oklch(1 0 0 / 12%)` | **1.6:1** | 3:1 (WCAG 1.4.11) |
| `line-height` ของข้อความไทยหลายจุด (`leading-snug`) | 1.375 | 1.6 สำหรับไทย |

`.dark` block ใน `app/globals.css` มีอยู่แล้วแต่ **ไม่มีอะไรใส่ class `dark` เลย** จึงเป็น dead code และค่าที่มีก็ derive จากพาเลตต์สว่างโดยไม่ได้ออกแบบเพื่อสายตา

## 2. ขอบเขต

โปรเจกต์นี้เป็นก้อน **A** จาก 3 ก้อนที่แตกออกมาจากคำขอชุดใหญ่ ลำดับคือ A → B → C:

- **A (สเปกนี้)** — ธีม + ตัวอักษร + กฎ affordance + ปุ่มสลับธีม
- **B** — รื้อหน้ารายการสินค้า (`entry-list.tsx`)
- **C** — รื้อ "ควรทำอะไรต่อ" ในหน้ารายได้ (`recommendations.tsx`, `dashboard-panel.tsx`)

A ต้องมาก่อนเพราะ B/C จะได้ใช้ token และกฎจาก A ทันที ไม่ต้องแก้สองรอบ

**ไม่ทำในสเปกนี้:** ย้าย layout, เพิ่ม/ลบฟีเจอร์, แตะตรรกะข้อมูล (`lib/*`, `app/actions.ts`, Prisma, การคิวรี)

## 3. การตัดสินใจที่ล็อกแล้ว

| # | ประเด็น | ที่เลือก |
|---|---|---|
| 1 | เก็บโหมดสว่างไหม | **มี toggle สองโหมด** และ **ออกแบบใหม่ทั้งคู่** ไม่ใช่เพิ่มมืดแล้วปล่อยสว่างเดิม |
| 2 | ทิศทางสี | **Navy + Brass** (เปลี่ยนจาก teal + amber เดิม) |
| 3 | JetBrains Mono | เก็บไว้เฉพาะตัวเลขที่เรียงเป็นคอลัมน์ ตัดออกจาก label/ข้อความไทย |
| 4 | สเกลตัวอักษร | base 15px · ชื่อสินค้า 18px · พื้นต่ำสุด 12px |
| 5 | ปุ่มสลับ | อยู่ทั้ง `app-header.tsx` และ `clapper-header.tsx` · ค่าเริ่มต้น = มืด |
| 6 | ขอบเขตการกวาด | 17 ไฟล์ **เว้น** `entry-list.tsx` และ `recommendations.tsx` (B/C จะรื้ออยู่แล้ว) |

### 3.1 ข้อห้ามที่นิยามว่า "ไม่เป็น AI slop"

- ห้าม gradient ม่วง-น้ำเงิน, glassmorphism/blur, เงาเรืองแสง
- ห้ามสี accent อิ่มจัดบนพื้นที่กว้าง
- ห้ามพาเลตต์ default ของ framework (Tailwind `blue-600` `#2563EB`, `violet-600` `#7C3AED` ฯลฯ)
- ห้ามพื้น `#000000` และตัวอักษร `#FFFFFF` — เป็นต้นเหตุ halation ที่ทำให้ตาล้าที่สุดในธีมมืด
- **ห้าม tone-on-tone** — พื้นปุ่ม/badge กับตัวอักษรในนั้นห้ามเป็นเฉดเดียวกัน

## 4. โครงสร้าง token

### 4.1 สามชั้น

```
primitive   --navy-50 … --navy-950 , --brass-400 … --brass-700     สเกล OKLCH ดิบ
    ↓
semantic    --background --surface --border-interactive --primary   สลับตามโหมด
    ↓
component   ปุ่ม/badge/input อ้าง semantic เท่านั้น                 ห้ามมี hex ในคอมโพเนนต์
```

ปัจจุบันมีแค่ 2 ชั้น และชั้นล่างสุดเป็น hex ดิบ (`--teal: #0a6d64`) จึงคุมความสว่างข้ามโหมดไม่ได้ — นี่คือสาเหตุที่ธีมมืดปัจจุบันได้ teal `#22c1b3` ที่สว่างจ้า

ใช้ OKLCH เพราะเป็นปริภูมิที่ค่า `L` ตรงกับความสว่างที่ตารับรู้จริง การกำหนดขั้นความสว่างเป็นตัวเลขจึงเชื่อถือได้ ต่างจาก hex ที่ต้องเดา

### 4.2 บทบาทของสองสี

- **Navy** = พื้นผิว โครงสร้าง และ **ปุ่มหลักในโหมดสว่าง**
- **Brass** = accent, focus ring, เส้นกราฟ และ **ปุ่มหลักในโหมดมืด**

เหตุผล: ปุ่มหลักต้องตัดกับพื้นหน้าเสมอ โหมดสว่างพื้นเกือบขาว ปุ่มจึงต้องเข้ม / โหมดมืดพื้นเป็นกรมท่า ปุ่มจึงต้องสว่าง ถ้าใช้สีเดียวกันทั้งสองโหมดจะมีโหมดหนึ่งที่ปุ่มจมหายเสมอ

หลักคุมความอิ่มสี: **พื้นที่ยิ่งกว้าง chroma ยิ่งต่ำ** — พื้นหลัง/การ์ดอยู่ที่ `C ≈ 0.018` (เกือบเทาแต่มีอุณหภูมิสี) เก็บ chroma สูง (`C ≈ 0.12`) ไว้ให้ปุ่มและจุดสถานะที่มีพื้นที่เล็กเท่านั้น นี่คือกลไกที่ทำให้ตาไม่ล้า มากกว่าการเลือกเฉดสี

### 4.3 ค่าจริง (ตรวจ contrast แล้วทุกคู่)

| บทบาท | โหมดมืด | อัตรา | โหมดสว่าง | อัตรา |
|---|---|---|---|---|
| พื้นหลัง | `oklch(.19 .018 250)` `#0E141C` | — | `oklch(.965 .006 250)` `#F0F4F7` | — |
| การ์ด/แผง | `oklch(.24 .020 250)` `#182029` | — | `oklch(.99 .003 250)` `#FAFCFE` | — |
| พื้นรอง (hover/muted) | `oklch(.29 .015 250)` | — | `oklch(.945 .006 250)` | — |
| ตัวอักษรหลัก | `oklch(.93 .008 250)` `#E4E8ED` | **13.4:1** | `oklch(.25 .020 250)` `#1A222B` | **15.5:1** |
| ตัวอักษรรอง | `oklch(.69 .015 250)` `#959CA5` | **5.9:1** | `oklch(.51 .015 250)` `#60676F` | **5.6:1** |
| ปุ่มหลัก (พื้น) | brass `oklch(.72 .12 85)` | — | navy `oklch(.38 .07 250)` | — |
| ปุ่มหลัก (ตัวอักษร) | ink `oklch(.18 .03 250)` | **7.2:1** | ครีม `oklch(.99 .004 250)` | **9.7:1** |
| เส้นคั่นตกแต่ง | `oklch(.34 .018 250)` | 1.6:1 (ไม่ต้องผ่าน) | `oklch(.87 .010 250)` | 1.3:1 |
| **ขอบของสิ่งที่กดได้** | `oklch(.52 .018 250)` `#616A73` | **3.4:1** | `oklch(.62 .012 250)` `#81878D` | **3.3:1** |
| focus ring | brass `oklch(.75 .11 85)` | 8.3:1 | navy `oklch(.38 .07 250)` | — |
| จุดสถานะ สำเร็จ | `oklch(.72 .12 155)` | 7.0:1 | `oklch(.52 .13 155)` | 5.0:1 |
| ข้อความผิดพลาด | `oklch(.70 .14 25)` | 5.8:1 | `oklch(.50 .17 25)` | 6.4:1 |

พื้นมืดที่สุดคือ `#0E141C` ตัวอักษรสว่างที่สุดคือ `#E4E8ED` — **ไม่มีดำสนิทและไม่มีขาวสนิท**

### 4.4 สองข้อที่ตัวเลข contrast บังคับ

1. **ปุ่ม brass ในโหมดมืดต้องใช้ตัวอักษรกรมท่าเข้ม ไม่ใช่ครีม** — ครีมบน brass `L.58` วัดได้ **4.20:1 ตกเกณฑ์ 4.5** ส่วนกรมท่าเข้มบน brass `L.72` ได้ 7.2:1 (ไม่ใช่ tone-on-tone เพราะคนละเฉด อ่านเป็น "ดำบนทอง")
2. **`--border` ต้องแตกเป็นสอง token** — วันนี้ token เดียวทำสองหน้าที่: เส้นคั่นตกแต่ง กับ ขอบของสิ่งที่กดได้ ในโหมดมืดมันคือ `oklch(1 0 0 / 12%)` = **1.6:1** ปุ่มกับกล่องเฉยๆ จึงหน้าตาเหมือนกันเป๊ะ ซึ่งคือรากของอาการ "ดูไม่ออกว่ากดได้" · ขอบของสิ่งที่กดได้ต้องผ่าน 3:1 → บังคับ `L ≥ .52` (มืด) / `L ≤ .62` (สว่าง) **จางกว่านี้ไม่ได้แม้จะอยากให้ดูมินิมอลแค่ไหน**

### 4.5 ชื่อ token เดิม 143 จุด

นับจากโค้ดจริง: `teal` 62 · `paper` 31 · `danger` 20 · `ink` 12 · `smoke` 12 · `amber` 4 · `success` 2 = **143 จุดใน 18 ไฟล์**

การเก็บชื่อเดิมไว้แล้วชี้ไปสีใหม่จะทำให้ `bg-teal` ให้สีทองเหลือง — โค้ดโกหก และเป็นกับดักถาวร

**วิธีที่จะทำ:** เปลี่ยนไปใช้ชื่อตามบทบาท (`bg-primary`, `text-muted-foreground`, `border-interactive`) ในไฟล์ที่กวาด และ **คงชื่อเก่าไว้เป็น alias ชั่วคราว** สำหรับ 2 ไฟล์ที่ยกเว้น พร้อมคอมเมนต์กำกับว่าให้ลบเมื่อโปรเจกต์ C จบ

## 5. ตัวอักษร

### 5.1 ฟอนต์

| | เดิม | ใหม่ |
|---|---|---|
| ข้อความไทย | Noto Sans Thai | Noto Sans Thai (คงเดิม) |
| ข้อความ/ตัวเลขละติน | Plus Jakarta Sans | **Noto Sans Thai** (ตัด Jakarta ออก) |
| ตัวเลขในคอลัมน์ (เงิน/วิว/วันที่) | JetBrains Mono | JetBrains Mono (เหลือแค่ตรงนี้) |
| label ไทย | JetBrains Mono ← ผิด | **Noto Sans Thai** |

เหตุผลที่ mono กับ label ไทยเป็นของผิด: JetBrains Mono **ไม่มี glyph ภาษาไทย** ข้อความไทยที่ใส่ `font-mono` จึงตกไปใช้ฟอนต์สำรอง แล้วยังโดน `tracking-widest` ยืดอีกชั้น ได้ผลเป็นตัวไทย 8.8px ที่ระยะห่างผิดธรรมชาติ

**จุดเทคนิคที่ห้ามลืม:** `app/layout.tsx` โหลด `Noto_Sans_Thai({ subsets: ["thai"] })` — ถ้าตัด Jakarta ออกโดยไม่แก้ตรงนี้ ตัวอักษรละตินจะไม่มี glyph แล้วตกไปใช้ฟอนต์ระบบ ต้องเป็น `subsets: ["thai", "latin"]`

### 5.2 สเกล

| token | ขนาด | line-height | ใช้กับ |
|---|---|---|---|
| `text-xs` | 12px (พื้นต่ำสุด) | 1.5 | label, caption |
| `text-sm` | 14px | 1.6 | ข้อความรอง, angle, คำอธิบาย |
| `text-base` | 15px | 1.6 | เนื้อหาหลัก |
| `text-lg` | 18px | 1.5 | ชื่อสินค้าในรายการ, หัวข้อย่อย |
| `text-xl` / `2xl` / `3xl` | 20 / 24 / 30px | 1.35 | หัวข้อ |

`text-lg` = 18px ไม่ใช่ 16px โดยตั้งใจ: เนื้อหาหลักอยู่ที่ 15px ถ้าชื่อสินค้าเป็น 16px จะต่างกัน 1px ซึ่งตาแยกไม่ออก ไม่เกิดลำดับชั้นจริง และไม่แก้อาการ "list เล็กไป"

### 5.3 กฎบังคับ

1. **ห้ามใช้ขนาดตัวอักษรแบบ arbitrary (`text-[...]`)** — ต้องมาจาก token เท่านั้น กฎนี้คือสิ่งที่ทำให้ปัญหาไม่ย้อนกลับมา
2. **line-height ข้อความไทยขั้นต่ำ 1.6** (ไม่ใช่ 1.5 แบบละติน) เพราะสระบนและวรรณยุกต์ซ้อนสองชั้น
3. **ห้าม `tracking-widest` + `uppercase` กับข้อความไทย** — `uppercase` เป็น no-op กับอักษรไทย ส่วน `tracking-widest` ทำให้สระลอยห่างจากพยัญชนะเจ้าของ

## 6. กฎ affordance

### 6.1 กฎแกน

> ทุกสิ่งที่กดได้ต้องบอกว่ากดได้โดยไม่ต้องเอาเมาส์ไปชี้

ปัจจุบันปุ่มกรองสถานะเป็นข้อความเปล่า มีพื้นเฉพาะตอน `hover:` และตอน active — **ตัวที่ยังไม่ได้เลือกจึงไม่มีสัญญาณใดๆ ว่าเป็นปุ่ม**

### 6.2 สามระดับเท่านั้น

| ระดับ | หน้าตา | ใช้เมื่อ |
|---|---|---|
| หลัก | พื้นทึบ (brass ในมืด / navy ในสว่าง) + ตัวอักษรตัดกัน ≥7:1 | การกระทำหลักของหน้า — 1 ปุ่มต่อหน้า |
| รอง | พื้นโปร่ง + **ขอบ ≥3:1** | การกระทำรอง |
| กลุ่มตัวเลือก | **กรอบรวมรอบทั้งกลุ่ม** + ตัวที่เลือกพื้นทึบ ตัวที่ไม่ได้เลือกโปร่งแต่อยู่ในกรอบเดียวกัน | ตัวกรองสถานะ, ตัวสลับฐานวันที่, ปุ่มช่วงวันที่ |

ระดับที่สามคือตัวแก้อาการโดยตรง: ตัวเลือกที่ยังไม่ถูกเลือกไม่ต้องมีขอบของตัวเอง แต่กรอบรวมบอกว่าทั้งแถวกดได้ **สเปกนี้กำหนดกฎ ส่วนการนำไปใช้กับแถวตัวกรองจริงเกิดในโปรเจกต์ B**

### 6.3 ขนาดและระยะ

ปุ่มสูงขั้นต่ำ **36px** · เป้าคลิกไอคอนขั้นต่ำ **24×24px** · เว้นระหว่างเป้า **8px**

ยึด WCAG 2.2 (24×24) ไม่ใช่ 44×44 แบบสัมผัส เพราะแอปนี้ใช้บนคอมพิวเตอร์เป็นหลัก — ถ้าภายหลังต้องใช้บนมือถือด้วย ต้องยกเป็น 44px ทั้งหมด ซึ่งจะทำให้ทุกแถบควบคุมสูงขึ้น

### 6.4 สถานะที่ต้องมีครบ

- **focus** — วงแหวนจาก token `--ring` หนา 2px + เว้นขอบ 2px (brass ในโหมดมืด / navy ในโหมดสว่าง ตามตาราง 4.3) · ห้ามลบ outline เด็ดขาด
- **hover** — เปลี่ยนพื้น ไม่ใช่เปลี่ยนแค่สีตัวอักษร
- **active** — ขยับลง 1px (มีอยู่แล้วใน `components/ui/button.tsx` เก็บไว้)
- **disabled** — ทึบแสง 50% + `cursor-not-allowed`

### 6.5 แยก "ปุ่ม" ออกจาก "ป้ายสถานะ"

badge (`ลงแล้ว` / `รอลงคลิป`) กดไม่ได้ จึงต้องดูต่างจากปุ่มชัดเจน:

- badge = ทรงแคปซูล (`rounded-full`) + จุดสีนำหน้า + ไม่มีขอบระดับ interactive
- ปุ่ม = มุมโค้ง 8px + ไม่มีจุดสี

## 7. กลไก toggle

1. สคริปต์สั้นฝังใน `<head>` ของ `app/layout.tsx` — อ่าน `localStorage.theme` แล้วใส่ class `dark` บน `<html>` **ก่อนหน้าจอวาดครั้งแรก** ไม่มีค่า = มืด (กันอาการกระพริบขาวตอนโหลด ซึ่งจะแสบตากว่าเดิมถ้าไม่ทำ)
2. `<html suppressHydrationWarning>` เพราะ class ฝั่ง server กับ client ต่างกันโดยตั้งใจ
3. `components/theme-toggle.tsx` (`"use client"`) — ปุ่มไอคอน สลับ class + เขียน `localStorage`
4. วางใน `app-header.tsx` และ `clapper-header.tsx`

ไม่เพิ่ม dependency ใหม่ · `@custom-variant dark (&:is(.dark *))` ใน `globals.css` มีอยู่แล้วและใช้กับวิธีนี้ได้เลย

## 9. การตรวจสอบ

โปรเจกต์นี้ไม่มี test runner จึงต้องตรวจด้วยการรันจริงและด้วยการค้นหาคำ:

1. `npx tsc --noEmit` + `npm run lint` สะอาด (ไม่แตะ `.next` ไม่ชนกับ `start.bat` ที่ผู้ใช้รันอยู่)
2. **สคริปต์ตรวจ contrast** เก็บเข้า repo แล้วรันกับค่าจริงใน `globals.css` — ทุกคู่ต้องผ่านตามตาราง 4.3 นี่เป็นทางเดียวที่จับ regression ของสีได้
3. **ค้นหาคำที่ต้องเหลือศูนย์** ในไฟล์ที่กวาด: `text-[` (ขนาด arbitrary), `tracking-widest` คู่ข้อความไทย, `#` (hex) ใน `components/`
4. รันบน dev server แยก (`NEXT_DIST_DIR=.next-dev` + `DATABASE_URL="file:./dev-test.db"` + port 3001) แล้วตรวจด้วยตา: สลับธีมทุกหน้า · รีเฟรชแล้วต้อง **ไม่กระพริบขาว** · กด Tab ดูวงแหวน focus · ดูกราฟ Recharts ทั้งสองโหมด
5. `git diff tsconfig.json` ต้องว่างก่อน commit (dev server อาจ auto-patch)
6. `npm run build` เต็ม — **ต้องขอ port 3000 จากผู้ใช้ก่อน ห้าม kill เอง**

## 10. ต้องอัปเดต CLAUDE.md ตอนจบ

บรรทัดที่ระบุว่า *"palette Dusk Market … ให้ใช้ของเดิม อย่าเพิ่มสี/ฟอนต์ใหม่"* จะไม่จริงอีกต่อไป ต้องเขียนใหม่พร้อมกฎใหม่:

- ห้าม arbitrary text size · พื้นต่ำสุด 12px
- ห้าม hex ในคอมโพเนนต์ · ใช้ semantic token เท่านั้น
- แยก token เส้นคั่นตกแต่ง ออกจาก ขอบของสิ่งที่กดได้ (3:1)
- line-height ข้อความไทยขั้นต่ำ 1.6 · ห้าม `tracking-widest` กับไทย
- alias ชื่อสีเก่า (`teal`/`paper`/`ink`/…) เป็นของชั่วคราว ลบเมื่อโปรเจกต์ C จบ

## ภาคผนวก — สิ่งที่ประเมินแล้วไม่ใช้

**`nextlevelbuilder/ui-ux-pro-max-skill`** (ผู้ใช้เสนอให้ลอง) — อ่าน `SKILL.md` และ `data/colors.csv` จริงแล้ว **ไม่ติดตั้ง** ด้วยเหตุผลที่ตรวจสอบได้:

- ระบุว่า shadcn/ui สร้างบน **Radix UI** แต่ repo นี้ใช้ `@base-ui/react` → prop ไม่ตรงกัน
- มีสคริปต์ generate `tailwind.config.js` แต่ repo นี้เป็น Tailwind v4 CSS-first ไม่มีไฟล์ config
- แนะนำ `npx shadcn@latest init` ซึ่งจะทับ `components.json` และ `globals.css`
- ทุกแถวใน `colors.csv` ให้พาเลตต์เดียว **ไม่มีคู่สว่าง/มืด** → ใช้กับข้อกำหนด toggle ของเราไม่ได้
- ค่าสีเป็น Tailwind default ตรงๆ (`#2563EB` = blue-600, `#EC4899` = pink-500)
- แถวโหมดมืดใช้ตัวอักษร `#FFFFFF` และบางแถวพื้น `#000000` → คือ halation ที่สเปกนี้ตั้งใจเลี่ยง

**สิ่งที่รับมาใช้จากสกิลนั้น:** แนวคิด token 3 ชั้นจาก `design-system/references/token-architecture.md` (หัวข้อ 4.1) และตาราง priority ใน `SKILL.md` ที่ระบุเกณฑ์ contrast 4.5:1 / ห้ามตัวอักษรต่ำกว่า 12px / ห้าม raw hex ในคอมโพเนนต์ / touch target ขั้นต่ำ — ใช้เป็นเกณฑ์ตรวจในหัวข้อ 9

จงใจไม่ทำตาม 2 ข้อของสกิลนั้น พร้อมเหตุผล:

- **"body ขั้นต่ำ 16px"** → สเปกนี้ใช้ 15px เพราะเป็นแอปข้อมูลแน่นบนเดสก์ท็อป และปัญหาจริงของผู้ใช้คือ *ลำดับชั้นแบน* (ชื่อสินค้าตัวเท่าข้อความรอง) ไม่ใช่ทุกอย่างเล็ก — จึงแก้ด้วยการไล่ 18/15/14/12 ให้ต่างกันจริง แทนการดันทุกอย่างขึ้นพร้อมกันซึ่งจะทำให้หน้ารายได้ที่ยาวอยู่แล้วยาวขึ้นอีก
- **"touch target 44×44"** → สเปกนี้ใช้ WCAG 2.2 (24×24) ตามหัวข้อ 6.3 เพราะใช้บนคอมพิวเตอร์เป็นหลัก
