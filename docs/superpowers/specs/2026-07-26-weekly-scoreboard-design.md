# สรุปรายสัปดาห์ (Weekly Scoreboard) — Design

## Problem

ผู้ใช้ทำคลิปไม่สม่ำเสมอ **ไม่ใช่เพราะไม่รู้ว่าต้องทำอะไร แต่เพราะทำแล้วไม่เห็นว่าคืบหน้าจริงไหม** — คำพูดของผู้ใช้: "ถ้ามันไม่มีอะไรที่รู้ว่าเราทำไปแล้วก้าวหน้าขึ้นจริงๆ จะทำไปทำไม มันเหมือนกับเราทำไปเรื่อยๆ จนเราไม่รู้เลยว่าเราทำอะไรแล้วก็ลืมไป"

ระบบปัจจุบันแสดงข้อมูลเป็น **ยอดสะสมตลอดกาล** (เงินที่ได้จริง, ราย-คลิป) กับ **สัญญาณต่อคลิป** (`lib/recommender.ts`) แต่ไม่มีมุมที่ตอบว่า **"เดือนที่ผ่านมาเราขยับขึ้นหรือย่ำอยู่กับที่"** ซึ่งเป็นมุมเดียวที่ตอบคำถามเรื่องความคืบหน้าได้

## Scope — ตัดเหลือเท่าที่จำเป็นจริง

ฉบับก่อนหน้าของสเปกนี้ออกแบบระบบวางแผนรายสัปดาห์เต็มรูปแบบ (แท็บใหม่ + 3 ตาราง + AI เสนอเควส + บทเรียนสะสม + ประตูข้อมูล) แล้ว**ตัดทิ้งทั้งหมด**หลังทบทวน เหตุผลที่ตัด (บันทึกไว้กันคิดวนซ้ำ):

1. **รอบสัปดาห์สั้นเกินกว่าจะประเมินการทดลองได้** — conversion จริงของช่องคือ **0.206%** (256 ออเดอร์ / 124,567 วิว) คลิปทดสอบ 2 ตัว/สัปดาห์ให้ออเดอร์ระดับ 0-3 ซึ่งแยกไม่ออกระหว่าง "เวิร์ก" กับ "ดวง" · รายได้ settle ช้า 7+ วัน · วิวยังไหลเข้าหลังโพสต์ → การตัดสิน "ได้ผล/ไม่ได้ผล" รายสัปดาห์คือการอ่าน noise
2. **ให้ AI สรุป "บทเรียน" จากข้อมูลบางๆ = ผลิตรูปแบบปลอม** และผู้ใช้ระบุเองว่าคำแนะนำจาก Claude มีน้ำหนักต่อการตัดสินใจมาก — ระบบที่ป้อนข้อสรุปมั่นใจเกินจริงทุกสัปดาห์จึงเป็นความเสี่ยง ไม่ใช่คุณค่า
3. **พิธีกรรม 10-15 นาที/สัปดาห์เสี่ยงล้มด้วยกลไกเดียวกับที่ทำให้ไม่ได้ทำคลิป** — เครื่องมือแก้วินัยที่ต้องใช้วินัยในการใช้
4. **คำแนะนำรายสัปดาห์จะซ้ำเดิมหลายเดือน** (ทำหมวดแมว · ทำ winner ซ้ำ · เลี่ยงสินค้าที่ต้องใช้รูปคน) — รู้ตั้งแต่สัปดาห์แรกแล้ว ไม่ต้องมีระบบมาบอกซ้ำ

**สิ่งที่เหลือคือ 2 อย่างที่ให้คุณค่าสูงสุดต่อต้นทุน และเป็น "ข้อเท็จจริง" ไม่ใช่ "ข้อสรุป"**

> **หลักการกำกับทั้งสเปก: รายงานข้อเท็จจริง ไม่ตีความแทนผู้ใช้** — ตัวเลขที่วัดได้ตรงๆ (คลิปกี่ตัว เงินเท่าไร) เชื่อถือได้เสมอแม้ข้อมูลน้อย ต่างจากข้อสรุป ("สิ่งนี้ได้ผล") ที่ต้องการตัวอย่างมากกว่าที่มี

## ข้อเท็จจริงจากโค้ด/ข้อมูลจริง (load-bearing — ตรวจสอบแล้ว 2026-07-26)

- `app/page.tsx:35-39` คำนวณ `lastImportedAt` จาก **`AffiliateOrder` เท่านั้น** → อัปแค่ไฟล์รายได้ก็รีเซ็ตคำเตือน ทั้งที่ข้อมูลวิวอาจเก่าหลายสัปดาห์ · **`ClipMetric` และ `FollowerActivity` มีคอลัมน์ `importedAt` อยู่แล้ว จึงไม่ต้องแก้ schema**
- `lib/dashboard.ts` เป็นเจ้าของ `IMPORT_STALE_DAYS = 7`, `summarizeOrders()`, `INELIGIBLE_STATUS`, `ReminderState` · `PAID_STATUS = "ชำระแล้ว"` อยู่ใน `lib/affiliate.ts`
- `components/dashboard-panel.tsx` เรียงลำดับ: หัวข้อ → `ReminderBanner` (บรรทัด 118) → `Recommendations` (120) → การ์ดเงิน (132+) → `PostTimePanel` (183) → ฟอร์มนำเข้า + บรรทัดสถานะ (190+)
- `components/reminder-banner.tsx` ใช้ `r.daysSinceImport` ค่าเดียว (มาจากไฟล์รายได้) · `components/recommendations.tsx:78` แสดง "ยังไม่มีข้อมูลวิว N คลิป" อยู่แล้ว → **ไม่ต้องทำบรรทัดความครอบคลุมซ้ำ**
- `PromptEntry.postedAt` เก็บเป็น **UTC midnight ของวันที่โพสต์** (ดู `toDateInputValue` ใน `production-panel.tsx`) — การหาว่า entry อยู่สัปดาห์ไหนต้องเทียบแบบ UTC ห้ามใช้ local getters
- `AffiliateOrder.orderDate` เป็น timestamp จริง (มีเวลา) — คนละแบบกับ `postedAt`
- ข้อมูลปัจจุบัน: 55 entries · 52 มี `videoUrl` · 24 มีข้อมูลวิว · 30 มีออเดอร์ · ออเดอร์ 269 แถว (26 พ.ค.–26 ก.ค.) จับคู่ได้ 268
- จำนวนคลิปต่อสัปดาห์แกว่งมาก: W24=3 · W25=6 · W26=5 · W27=3 · W28=23 · W29=9 → **การเทียบแค่ "สัปดาห์นี้ vs สัปดาห์ก่อน" จะเหวี่ยงจนอ่านไม่ออก ต้องแสดงหลายสัปดาห์พร้อมกัน**

## Design

### 1. แผง "4 สัปดาห์ล่าสุด" ในแท็บ ④ รายได้

**ไม่มีแท็บใหม่ ไม่มีตารางใหม่ ไม่มี AI** — เป็นแผงเดียวที่คำนวณจากข้อมูลที่มีอยู่แล้วทั้งหมด

วางไว้**เหนือ `Recommendations`** (ใต้ `ReminderBanner`) เพราะเป็นภาพรวมที่ควรอ่านก่อนคำแนะนำต่อคลิป

```
┌ 4 สัปดาห์ล่าสุด ──────────────────────────────────┐
│  สัปดาห์            คลิป   เงินที่ได้จริง   winner ใหม่ │
│  21-27 ก.ค. (นี้)     4        1,240฿          1      │
│  14-20 ก.ค.           9        2,110฿          2      │
│   7-13 ก.ค.          23        1,780฿          0      │
│  30 มิ.ย.-6 ก.ค.      3          940฿          1      │
│                                                        │
│  มี 2 คลิปที่เพิ่งลงไม่ถึง 7 วัน — ยังเร็วเกินสรุป      │
└────────────────────────────────────────────────────────┘
```

**นิยามของแต่ละคอลัมน์ (ทั้งหมดเป็นข้อเท็จจริงที่วัดได้ ไม่ใช่การตีความ):**

- **สัปดาห์** — จันทร์–อาทิตย์ เวลาไทย (UTC+7) แถวบนสุดคือสัปดาห์ปัจจุบันและกำกับว่า "(นี้)" เพราะยังไม่จบ จึงเทียบกับแถวอื่นตรงๆ ไม่ได้
- **คลิป** — นับ `PromptEntry` ที่ `postedAt` อยู่ในสัปดาห์นั้น
- **เงินที่ได้จริง** — ผลรวม `finalRevenue` ของออเดอร์สถานะ `ชำระแล้ว` ที่ `orderDate` อยู่ในสัปดาห์นั้น (นิยามเดียวกับ `settledRevenue` ใน `summarizeOrders` เพื่อไม่ให้ตัวเลขขัดกันเองในหน้าเดียวกัน)
- **winner ใหม่** — จำนวน entry ที่ได้ออเดอร์ **ชำระแล้ว** เป็นครั้งแรกในสัปดาห์นั้น (คำนวณจาก `min(orderDate)` ของออเดอร์ที่ชำระแล้วต่อ entry)
- **บรรทัดล่าง** — จำนวนคลิปที่โพสต์ไม่ถึง 7 วัน เพื่อกันการด่วนสรุปว่าสัปดาห์นี้แย่ทั้งที่ยังไม่ครบรอบ

**สิ่งที่แผงนี้จะไม่ทำ:** ไม่บอกว่าสัปดาห์ไหน "ดี/แย่" ไม่คำนวณ %เปลี่ยนแปลง ไม่แนะนำอะไร — ตัวเลข 4 แถววางเรียงกันสื่อทิศทางด้วยตัวมันเองแล้ว และการตีความจากตัวอย่างน้อยขนาดนี้คือการเดา

### 2. แก้คำเตือนความสดข้อมูลให้แยกรายไฟล์ (บั๊กเดิม)

`ReminderState` เพิ่มเป็น 3 ค่า:

```ts
export type ReminderState = {
  daysSinceOrdersImport: number | null;   // เดิมชื่อ daysSinceImport
  daysSinceMetricsImport: number | null;  // ใหม่
  unmatchedSoldProducts: number;
};
```

- `app/page.tsx` คำนวณเพิ่มจาก `max(ClipMetric.importedAt)`
- `reminder-banner.tsx` เตือนแยกข้อความ ("ไม่ได้นำเข้าข้อมูลรายได้มา N วัน" / "ไม่ได้นำเข้าข้อมูลวิวมา N วัน")
- บรรทัดสถานะใต้ฟอร์มนำเข้า (`dashboard-panel.tsx:206-222`) แสดงทั้ง 2 ไฟล์
- **ไม่ติดตาม `FollowerActivity`** — เปลี่ยนช้าและใช้แค่วิเคราะห์เวลาโพสต์ การเตือนจะกลายเป็น noise (บทเรียนจาก `CLIP_AWAITING_THRESHOLD` ที่เคยติด active ถาวรจนกลบคำเตือนอื่น)

### ไฟล์ที่แตะ

**เพิ่ม**
- `lib/weekly-scoreboard.ts` — pure ล้วน: `weekBounds(now, offset)` (จันทร์–อาทิตย์ เวลาไทย), `buildWeeklyScoreboard({ entries, orders, now, weeks: 4 })` คืน `WeekRow[]` + `tooEarlyClips`
- `components/weekly-scoreboard.tsx` — แผงตาราง (client component เพื่อความสม่ำเสมอกับแผงอื่นในแท็บนี้ ไม่มี state ของตัวเอง)

**แก้**
- `lib/dashboard.ts` — `ReminderState` 3 ฟิลด์
- `app/page.tsx` — คำนวณ `daysSinceMetricsImport`, ปรับเงื่อนไข `reminderActive`
- `components/reminder-banner.tsx` — ข้อความแยกรายไฟล์
- `components/dashboard-panel.tsx` — วาง `<WeeklyScoreboard>` + บรรทัดสถานะ 2 ไฟล์
- `components/prompt-workspace.tsx` — ส่ง prop ที่เพิ่ม (ถ้าจำเป็น)
- `CLAUDE.md` — บันทึกวิธี export ที่ถูกต้อง (ดูหัวข้อถัดไป)

### บันทึกลง CLAUDE.md (ไม่สร้าง UI)

ความรู้ที่ได้จากการตรวจไฟล์จริงวันนี้ ควรอยู่ในเอกสาร ไม่ใช่ในโค้ด:

- **Content.csv จาก TikTok Studio ให้สูงสุด 15 แถวเสมอ** ไม่ว่าเลือกช่วง 7/28/60/365 (ยืนยันจากไฟล์จริง 2 รอบ) — เป็น "ท็อป N ตามวิว" ของช่วงนั้น
- **วิธีเลี่ยง:** export 2 ครั้งในวันเดียวกัน (ช่วง 7 วัน + ช่วง 365 วัน) — `ClipMetric` unique ที่ `(videoId, capturedOn)` และ `capturedOn` มาจากคอลัมน์ `Time` (วันที่ export) จึง**รวมเป็น snapshot เดียวที่ครอบคลุมกว่า** (พิสูจน์แล้ว: 15+15 → 23 คลิปใน snapshot 2026-07-26) · สัปดาห์ที่ลงคลิปเกิน ~12 ควร export กลางสัปดาห์เพิ่ม
- **ไฟล์รายได้ให้เลือกช่วงกว้างสุดเสมอ** — `importAffiliateOrders` เป็น upsert by `orderId` ที่อัปเดตสถานะย้อนหลัง (รอ→ชำระแล้ว) ช่วงแคบจะทำให้ออเดอร์เก่าที่เพิ่ง settle ไม่ถูกอัปเดต
- **selection bias ที่วัดได้:** median วิว 1,828 (ตอนมีแต่ท็อป 15) → 1,538 หลังเติมคลิปวิวน้อย — `detectSignals` ใช้ median เป็นเกณฑ์ (`max(500, median*2)`) จึงเคยตั้งสูงเกินจริง ยิ่งอัปครบยิ่งแม่น

## Non-goals

ตัดออกโดยตั้งใจ (เหตุผลอยู่ในหัวข้อ Scope):

- แท็บใหม่ · ตารางใหม่ · AI วางแผน/สรุปบทเรียน · รายการเควสติ๊กเอง · บทเรียนสะสม · ประตูข้อมูลบล็อกการทำงาน · gamification ทุกรูปแบบ (streak/badge/level/แต้ม) · notification · auto-import · UI สอนวิธี export · เตือนเรื่องจำนวนคลิปต่อสัปดาห์
- **ไม่แตะ `lib/recommender.ts`** และไม่แตะตรรกะการนำเข้าไฟล์ใดๆ
- **ไม่คำนวณ %เปลี่ยนแปลงหรือตัดสินว่าสัปดาห์ไหนดี/แย่**

หากใช้แผงนี้จริงต่อเนื่อง 4 สัปดาห์แล้วยังรู้สึกขาด ค่อยพิจารณาเพิ่มทีละชิ้นบนหลักฐานการใช้จริง — และถ้าจะทำรอบประเมิน ควรเป็น **14 วันหรือรายเดือน** ให้ตรงกับสถิติจริงของช่อง ไม่ใช่รายสัปดาห์

- **ตรวจความถูกต้องของตัวเลขด้วยสคริปต์แยก** (เขียนเป็นไฟล์ `.js` ใน scratch อ่าน `dev.db` แบบ readonly ตามกฎใน CLAUDE.md): query SQL ตรงๆ หาจำนวนคลิป/รายได้ settled/winner ใหม่ ของ 4 สัปดาห์ล่าสุด แล้วเทียบกับที่แผงแสดง — ต้องตรงทุกช่อง
- ทดสอบ UI จริง (dev-test.db, port 3001):
  - แท็บ ④ แสดงแผง 4 สัปดาห์เหนือ "ควรทำอะไรต่อ" · แถวบนสุดกำกับ "(นี้)"
