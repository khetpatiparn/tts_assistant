# แยกขั้น "สกัดสเปกสินค้า" ออกจากการเจน 10 ส่วน (Design)

## Problem

วิดีโอที่เจนออกมาได้สินค้าผิดโครงสร้างซ้ำๆ โดยที่**ระบบไม่มีบั๊ก** — รูปแนบครบ พรอมต์เจนครบ บันทึกถูก แต่จุดที่พังคือ**สิ่งที่ถูกเขียนลงพรอมต์**

### เคสที่ยืนยันแล้ว 2 เคส คนละหมวดสินค้า พังด้วยกลไกเดียวกัน

| เคส | พรอมต์บรรยายไว้ | **ไม่ได้บรรยาย** | Flow เดาเอง |
|---|---|---|---|
| ชั้นวางเหล็ก (2026-07-26) | โครง + ทรง + สี | **พื้นผิวแผ่นชั้น** | เป็นตะแกรงเจาะรู |
| กล่องขนมอกไก่ (2026-07-27) | ภาชนะ + สี + ฉลาก | **กลไกฝา** | เป็นฝาเกลียวบนโหลกลม |

**จุดที่ไม่ได้เขียนลงพรอมต์ = จุดที่เพี้ยน ทั้งสองครั้ง**

### หลักฐานเชิงปริมาณ

วัดจากพรอมต์ 10 คลิปล่าสุดใน `dev.db` (นับความยาวข้อ 3+4 เทียบกับทั้งพรอมต์):

```
ขนมอกไก่ฟรีซดราย      23%     ชั้นวางของเหล็ก        24%
ผ้าเช็ดตัวขนเป็ด       19%     หวีแปรงกำจัดขน         19%
ที่ลับเล็บแมว          20%     ห้องน้ำกระต่าย         19%
ของเล่นสกุชชี่         20%     ชามอาหารสัตว์          20%
ชั้นวางฝาหม้อ          20%     ดัมเบล                 21%
```

**เฉลี่ย 20.7% ของพรอมต์ใช้บรรยายตัวสินค้า อีก 79.3% เป็น style/scene/timeline/camera/framing/lighting/negative/QA** — ช่วง 19-24% นิ่งมากทุกสินค้า แปลว่าเป็นโครงสร้าง ไม่ใช่ความบังเอิญ

### หลักฐานว่า "สั่งให้ทำ" อย่างเดียวไม่พอ (สำคัญที่สุด)

`lib/prompt-template.ts` **มีคำสั่งให้ถอดกลไกอยู่แล้ว**:

> "ถอดโครงสร้างที่เห็นจริง (รูปทรง สี ชิ้นส่วน สัดส่วน ตำแหน่ง logo ด้านหน้า/หลัง **กลไก**) ลง Product Accuracy ... ให้ครบ**ตามระดับความเสี่ยงของสินค้า** — สินค้าซับซ้อน/อสมมาตร (logo ด้านเดียว, **พับ/กาง/มีกลไก**) ให้บรรยายละเอียดพอจะกันเพี้ยน ส่วนสินค้าเรียบง่ายเขียนสั้นกระชับ **ไม่ต้องยัดเยิน**"

กล่องขนมมีฝาพับบานพับ = เข้าเงื่อนไข "มีกลไก" ตรงตัว แต่โมเดลตัดสินเองว่า "กล่องพลาสติก = เรียบง่าย" แล้วย่อเหลือ 4 bullet

> **กฎมีอยู่แล้วและครอบคลุมเคสนี้ แต่มันแขวนอยู่บนการตัดสินความเสี่ยงที่โมเดลตัดสินพลาด** — การเขียนคำสั่งให้ดังขึ้นจึงเป็นการรันการทดลองที่ล้มเหลวไปแล้วซ้ำ

### หลักฐานว่าข้อความชนะรูป

กล่องขนมแนบรูป 3 ใบ ทุกใบเป็นทรงเหลี่ยม และใบที่ 3 โชว์ฝาพับเปิดชัดเจน แต่ผลออกมาเป็นโหลกลมฝาเกลียว

สาเหตุ: พรอมต์ใช้คำว่า **"กระปุก" 14 ครั้ง** vs **"ทรงเหลี่ยม" 4 ครั้ง** และ **9 ใน 14 ครั้งที่ "กระปุก" ปรากฏโดดๆ ไม่มีคำขยายทรงกำกับ** — ในภาษาไทย "กระปุก" หมายถึงภาชนะทรงกลมโดยปริยาย (กระปุกออมสิน/กระปุกครีม) ผลลัพธ์จึงตรงกับคำนามที่ถูกย้ำ ไม่ใช่คำขยายที่พูดน้อยกว่า

**ข้อสรุป: โมเดลมองรูปเห็นถูก (มันเขียน "ทรงเหลี่ยม" ออกมาได้) แต่ของหายระหว่างทางตอนเขียน**

### ข้อมูลจากฟอร์มไม่ได้ช่วย

ตรวจแล้ว `productInfo` ของกล่องขนม**ไม่มีคำว่า กระปุก/ทรงเหลี่ยม/ฝา เลยแม้แต่คำเดียว** (เป็นข้อความการตลาดเรื่องส่วนผสม) — ข้อมูลรูปทรงทั้งหมดมาจากการมองรูปล้วนๆ **การเพิ่มช่องในฟอร์มจึงไม่ใช่ทางแก้** (และช่องที่มีอยู่ก็ไม่ถูกใช้: `riskModule` ว่างหรือ `"-"` แทบทุก entry, `extraNotes` ว่าง 55/55)

## หลักการที่คุมดีไซน์นี้

**หนึ่งการเรียก = หนึ่งงาน** — ตอนนี้โมเดลต้องทำ 4 อย่างพร้อมกันในการเรียกครั้งเดียว: มองรูป + ถอดสเปกสินค้า + แต่งฉาก/กล้อง/บทพูด + คุมฟอร์แมต 10 ส่วนและความยาว งานที่โดนเบียดคือการถอดสเปก

แบบแผนนี้มีอยู่ในระบบแล้ว 3 จุด: `extractProductFields` (แคป→ข้อความ), `generateCaptionAndHashtags` (10-part→caption), `suggestAngleOptions` (ประวัติ→angle) — **ดีไซน์นี้คือการใช้แบบแผนเดิมกับงานที่สำคัญที่สุดซึ่งยังไม่ได้ใช้**

## Design

### ภาพรวม 3 ชั้น

```
รูปสินค้า + ชื่อ + ข้อมูลร้าน
        ↓
[ขั้นที่ 0 — ใหม่] สกัดสเปกสินค้า → บันทึกลง PromptEntry.productSpec
        ↓
[ขั้นที่ 1] เจน 10 ส่วน ← สเปก(ข้อความ) + รูป + Core Prompt v8
        ↓
[ขั้นที่ 2] Caption/Hashtags (ไม่เปลี่ยน)
```

### 1. Data model — คอลัมน์เดียว

```prisma
model PromptEntry {
  // ...ฟิลด์เดิม
  productSpec String @default("")   // สเปกสินค้าที่สกัดจากรูป ว่าง = ยังไม่เคยสกัด
}
```

ไม่มีตารางใหม่ ไม่มี relation ใหม่

### 2. ขั้นที่ 0 — `extractProductSpec` ใน `lib/gemini.ts`

**โมเดล: ใช้ตัวที่ผู้ใช้เลือกใน dropdown** (ไม่ล็อก flash-lite) เพราะเป็นงาน**มองรูป** ตรงกับแบบแผนเดิมที่งาน vision ให้ผู้ใช้เลือก ส่วนงานข้อความล้วนล็อก flash-lite · และเพราะสกัดครั้งเดียวต่อสินค้า การใช้ `gemini-3.5-flash` (20/วัน) จึงไม่เปลืองโควตา

**หัวข้อตายตัว เนื้อหาเขียนอิสระ** (บังคับความครบ แต่ยังแก้มือง่าย):

```
รูปทรงและสัดส่วน:
วัสดุและพื้นผิว (แยกทีละส่วน ระบุทึบ/โปร่ง/มีรู ให้ชัด):
ชิ้นส่วนและกลไก (เปิด/ปิด/พับ/หมุน/ถอด — อธิบายว่าทำงานยังไง):
สี:
ฉลาก/โลโก้/ข้อความบนตัวสินค้า (ตำแหน่ง สี ขนาด ข้อความที่อ่านได้):
จุดที่ AI มักทำเพี้ยนกับสินค้าแบบนี้:
```

หัวข้อ **"วัสดุและพื้นผิว"** กับ **"ชิ้นส่วนและกลไก"** คือสองอันที่หายไปในเคสชั้นวางและกล่องขนมพอดี

**กติกาในคำสั่ง:** บรรยายเฉพาะที่เห็นในรูป ห้ามเดา · ถ้าข้อมูลร้านขัดกับรูป ให้ยึดรูปและทิ้งคำนั้น · ห้ามใช้คำนามกำกวม (กระปุก/โปร่ง/ตาราง) ให้ระบุทรงและพื้นผิวชัดเจน · `temperature` ต่ำ (0.2) เพราะเป็นงานสังเกต ไม่ใช่งานสร้างสรรค์

### 3. `saveProductSpec` + `refreshProductSpec` ใน `app/actions.ts`

- `saveProductSpec(entryId, spec)` — บันทึกตอน blur แบบเดียวกับ `saveAngle`/`updateProductImageCaption` (**ต้องเป็น action ของตัวเอง ไม่ผ่าน form submit** เพราะ `generateWithAI` อ่านจาก DB)
- `refreshProductSpec(entryId, model)` — สกัดใหม่ทับของเดิม (ปุ่ม "สกัดสเปกใหม่")
- **เขียนทับเมื่อสำเร็จเท่านั้น** — สกัดใหม่แล้วล้มเหลว สเปกเดิมต้องไม่หาย

### 4. `generateWithAI` — เพิ่มขั้นที่ 0

```
ถ้า entry.productSpec ว่าง → สกัดก่อน แล้วบันทึก
ถ้ามีแล้ว → ใช้ของเดิม (ห้ามทับ เพราะผู้ใช้อาจแก้มือไว้)
→ ส่ง productSpec เข้า buildPromptText
```

**ขั้นที่ 0 พังให้ throw ได้เลย** — ยังไม่มีอะไรถูกบันทึก ผู้ใช้กดใหม่ได้ ไม่มีของหาย (ต่างจากขั้นที่ 2 ที่ห้าม throw เพราะ 10-part บันทึกไปแล้ว)

### 5. `lib/prompt-template.ts` — แก้ให้น้อยที่สุด (เฉพาะ "การลบ")

**เหตุผลที่แยกลบ/เพิ่ม:** ไฟล์นี้เป็น**โค้ด** แก้ทีต้อง rebuild ซึ่ง CLAUDE.md ห้ามทำตอน `start.bat` ของผู้ใช้รันอยู่ จึงใส่เฉพาะสิ่งที่ต้องลบ (ทำครั้งเดียวจบ) ส่วนกฎที่ต้องปรับจูนไปอยู่ใน Core Prompt (ฐานข้อมูล แก้ในแอปได้ ไม่ต้อง rebuild)

| แก้ | ทำไม |
|---|---|
| ตัด **"ไม่ต้องยัดเยิน"** ทิ้ง | ไม่งั้นขั้นที่ 1 จะบีบสเปกกลับลงไปเหลือ 4 bullet — **สเปกจะถูกกลืน** |
| ถอดเงื่อนไข **"ตามระดับความเสี่ยงของสินค้า"** | นี่คือจุดที่โมเดลตัดสินพลาดทั้ง 2 เคส เปลี่ยนเป็นบังคับบรรยายพื้นผิว+กลไกเสมอ |
| เพิ่มบล็อก `สเปกสินค้าที่สกัดจากรูป` | ช่องทางที่สเปกเข้าโจทย์ |

**`buildPromptText` รับ `productSpec` เพิ่ม — มี 2 call sites ต้องแก้ทั้งคู่:**
- `app/actions.ts` (`generateWithAI`) → ส่ง `entry.productSpec`
- `components/prompt-workspace.tsx` (useMemo คำนวณ preview) → ส่ง `selectedEntry?.productSpec ?? ""`
- `lib/few-shot.ts` → ส่ง `""` (golden examples ไม่มีสเปก)

*(บทเรียนจากฟีเจอร์ angle: call site ที่สองใน `prompt-workspace.tsx` ถูกมองข้ามในแผน ต้องระบุให้ครบตั้งแต่ต้น)*

**สเปกว่าง = ต้องยังทำงานได้ปกติ** (entry เก่า 58 อันไม่มีสเปก) แต่**ไม่ต้องเหมือนเดิมทุกตัวอักษร** เพราะการลบ "ไม่ต้องยัดเยิน" ตั้งใจให้เปลี่ยนพฤติกรรมกับทุก entry

### 6. Core Prompt v8 — ชั้นที่ปรับจูนได้โดยไม่ต้อง rebuild

เพิ่มเวอร์ชันใหม่ในแท็บ ③ (ระบบมีเวอร์ชันในตัว สลับกลับ v7 ได้คลิกเดียว) เนื้อหาที่เพิ่ม:

- **สเปกสินค้าคือความจริงหลักเรื่องข้อเท็จจริงของสินค้า** ถ้าขัดกับข้อมูลร้าน ให้ยึดสเปก (กันโมเดลเมินสเปกแล้วไปเดาเองเหมือนเดิม)
- **ต้องบรรยายพื้นผิว/วัสดุ และกลไกการใช้งานของส่วนที่จะถูกใช้ในคลิปเสมอ** ไม่ว่าจะตัดสินว่าสินค้าเสี่ยงหรือไม่
- **ห้ามใช้คำนามกำกวม** — ระบุทรงให้ชัด (กล่อง/โหล/ถัง ไม่ใช่ "กระปุก") ระบุพื้นผิวให้ชัด (ทึบ/มีรู ไม่ใช่ "โปร่ง")
- **ใช้คำเรียกสินค้าแบบเดียวกันตลอดพรอมต์** และแนบคำขยายทรงทุกครั้งที่เอ่ยถึง

**วิธีส่งมอบ:** เขียนเนื้อหา v8 เต็มเป็นไฟล์ `prisma/seed/core-prompt-v8.md` (ตามแบบ `prisma/seed/seo-prompt-v1.md` ที่มีอยู่) แล้วผู้ใช้ก๊อปไปวางสร้างเวอร์ชันใหม่ในแท็บ ③ เอง — **ไม่ต้องเขียนสคริปต์ seed และไม่ต้องแตะ DB ตอน implement** เพราะการเพิ่มเวอร์ชันเป็นการกระทำที่ผู้ใช้ควบคุมเอง และ v8 ต้องถูกปรับจูนหลายรอบระหว่างทดสอบอยู่แล้ว

### 7. `duplicatePrompt` — ต้องก๊อป `productSpec` (ตรงข้ามกับ `angle`)

`duplicatePrompt` (`app/actions.ts`) ระบุฟิลด์ที่ก๊อปแบบ explicit list — **ต้องเพิ่ม `productSpec: source.productSpec` เข้าไป**

เหตุผล: ทำซ้ำ = สินค้าเดิม → สเปกเหมือนเดิม → ไม่ควรเสียโควตาสกัดใหม่

**และนี่ตรงข้ามกับ `angle` โดยตั้งใจ** — `angle` ห้ามก๊อปเพราะคลิปใหม่ต้องได้มุมใหม่ ส่วน `productSpec` ต้องก๊อปเพราะสินค้าไม่ได้เปลี่ยน ตอนนี้มีคอมเมนต์กำกับเรื่อง `angle` อยู่แล้วในฟังก์ชันนั้น (commit `f06e69c`) **ต้องขยายคอมเมนต์ให้อธิบายทั้งสองฝั่ง** ไม่งั้นคนอ่านทีหลังจะสับสนว่าทำไมฟิลด์หนึ่งก๊อปอีกฟิลด์ไม่ก๊อป

### 8. UI — `components/product-spec-panel.tsx`

คอมโพเนนต์ใหม่แยกไฟล์ (ไม่ยัดใน `script-output.tsx` ที่มี 92 บรรทัด หรือ `brief-form.tsx` ที่ใหญ่อยู่แล้ว) แสดงในแท็บ ① เหนือช่อง 10-part:

```
[▸] สเปกสินค้า (สกัดจากรูป)              [สกัดสเปกใหม่]
    <textarea แก้ได้ บันทึกตอนคลิกออก>
    บันทึกเมื่อคลิกออกจากช่อง
```

พับเก็บได้ · แสดงเฉพาะเมื่อมี entry ถูกเลือก · ว่างอยู่ให้บอกว่าจะถูกสกัดอัตโนมัติตอนกดสร้าง

## Non-goals

- **ไม่แตะฟอร์มอินพุต** — ข้อมูลที่ต้องใช้มีอยู่ครบแล้วในรูป การเพิ่มช่องคือให้คนพิมพ์สิ่งที่ AI มองเห็นอยู่แล้ว
- **ไม่ลบ Product Risk Module** — ถึงจะว่างตลอดแต่พับซ่อนอยู่แล้ว ไม่เกะกะ และเป็น fallback สำหรับเคสที่ผู้ใช้รู้สิ่งที่ AI มองไม่เห็น
- **ไม่แนบรูปเข้า few-shot** — เปลือง 6-9 รูปต่อการเจน และคอขวดไม่ได้อยู่ที่การมองเห็น
- **ไม่ทำ negative-prompt boilerplate ตามหมวดสินค้า** — ต้องมานั่งดูแลลิสต์ และช่วยเฉพาะหมวดที่คิดไว้ล่วงหน้า
- **ไม่แก้ golden examples** — รอดูผลก่อน (ถ้าผลไม่สม่ำเสมอ นี่คือผู้ต้องสงสัยอันดับแรก ดูหัวข้อ Risks)
- **ไม่แตะ `lib/recommender.ts` / `lib/angle.ts` / `lib/weekly-scoreboard.ts`**
