# แถบข้าง: ค้นหาที่ใช้ได้จริง และแถวที่แยกออกจากกัน (Design)

## Problem

รายการสินค้าโตถึง **71 entries** แล้ว (เพิ่มวันละ 1-3) ผู้ใช้รายงานสองอาการพร้อมกัน: **"หาที่ต้องการไม่ค่อยเจอ/เลื่อนนาน"** และ **"แยกไม่ค่อยออก"**

### อาการที่ 1: ค้นหาหลายคำได้ผลลัพธ์ว่างเสมอ (บั๊กจริง)

`matchesQuery` ใน `components/history-rail.tsx` เอาคำค้นทั้งประโยครวมเว้นวรรคไปหาเป็น substring เดียว — พิมพ์เว้นวรรคเมื่อไหร่ได้ 0 ทันที ทั้งที่มีของอยู่ **ทดสอบกับข้อมูลจริง ล้มเหลว 5/5 เคส:**

```
"ที่นอน แมว"        → ตอนนี้ 0 รายการ   (แยกคำแล้วเจอ 7)
"ชั้นวาง เหล็ก"      → ตอนนี้ 0 รายการ   (แยกคำแล้วเจอ 6)
"ขวด น้ำ"           → ตอนนี้ 0 รายการ   (แยกคำแล้วเจอ 3)
"ชามอาหาร สแตนเลส"  → ตอนนี้ 0 รายการ   (แยกคำแล้วเจอ 1)
"กระดาษ กรง"        → ตอนนี้ 0 รายการ   (แยกคำแล้วเจอ 2)
```

ล้มเหลวแบบเงียบด้วย — ขึ้นแค่ "ไม่พบรายการ" ไม่มีอะไรบอกว่าทำไม

### อาการที่ 2: ผลค้นหาบวมจนไม่ได้กรองอะไร

คำค้นถูกแมตช์กับ `productInfo` (ข้อความร้านที่ยาวและมีคำทั่วไปเยอะ) ผลจึงบวมกว่าที่ควร:

| คำค้น | ชื่อสินค้าตรงจริง | ที่ระบบแสดง |
|---|---|---|
| "ผ้า" | 9 | **28** (บวม 3 เท่า) |
| "ครัว" | 5 | **20** (บวม 4 เท่า) |
| "แมว" | 11 | 18 |
| "สแตนเลส" | 10 | 14 |

ค้นแล้วยังเหลือ 28 จาก 71 รายการ = แทบไม่ได้กรอง

### อาการที่ 3: ชื่อยาวถูกตัดจนไม่รู้ว่าคืออะไร

แถบข้างกว้าง `w-60` (240px) พอหัก padding + เลข T## + วันที่ + ปุ่มเมนู **เหลือที่ให้ชื่อประมาณ 15 ตัวอักษร** และมี **15 รายการที่ชื่อยาวเกิน 30 ตัวอักษร**

ปัญหาคือ**ส่วนที่บอกว่าเป็นสินค้าอะไรมักอยู่ท้ายชื่อ แต่การตัดเก็บส่วนหัวไว้**:

```
"【พร้อมส่ง】 BMZAR เคาเตอร์ครัว ที่เก็บของบนเคาน์เตอร์..."  (125 ตัวอักษร)
      ↓ แสดงจริงในแถบข้าง
"【พร้อมส่ง】 BMZ..."          ← คำว่า "เคาเตอร์ครัว" หายหมด
```

### อาการที่ 4: มีคู่ที่แยกไม่ออกเลยจริงๆ 1 คู่

ชื่อซ้ำมี 11 รายการจาก 5 ชื่อ แต่**ส่วนใหญ่แยกออกได้ด้วยวันที่ที่แสดงอยู่แล้ว** (เช่น "ที่ลับเล็บแมว" 3 อันลงวันที่ 1, 13, 26 ก.ค.)

**ยกเว้นคู่ BMZAR** ที่ยังไม่ได้ลงคลิปทั้งคู่ → `postedAt` เป็น null ทั้งคู่ → `shortDate` คืน null → **ไม่มีวันที่โชว์เลย สองแถวเหมือนกันเป๊ะทุกพิกเซล**

## Non-problems (ตรวจแล้วว่าไม่ใช่ปัญหา)

- **ตัวกรอง "ยังไม่ได้กรอกผลลัพธ์"** ยังใช้ได้ดี (กรองเหลือ 4-7 รายการจาก 71)
- **การจัดกลุ่มตามเดือน** ดูเยอะ (ก.ค. มี 51 จาก 71) แต่ยังไม่มีหลักฐานว่าเปลี่ยนแล้วดีขึ้น — **ไม่แตะ**

## Design

### 1. แยกคำค้นหา (แก้บั๊ก)

ตัดคำค้นด้วยช่องว่าง แล้วต้องเจอ**ครบทุกคำ** (AND) ในรายการนั้น — แทนการหาทั้งประโยคเป็นก้อนเดียว

คำค้นคำเดียวยังทำงานเหมือนเดิมทุกประการ (substring match) — เป็น superset ของพฤติกรรมปัจจุบัน ไม่ใช่การเปลี่ยนความหมาย

### 2. จัดผลค้นหาเป็น 3 ชั้น แทนการกรองแบนๆ

เมื่อมีคำค้น ให้แบ่งผลตาม**ฟิลด์ที่แมตช์** เรียงตามความน่าเชื่อถือ:

```
ตรงชื่อสินค้า (3)
  [รูป] ที่นอนแมว                    14 ก.ค.
  [รูป] ที่นอนแมว                    17 ก.ค.
  [รูป] โซฟาแมว ที่นอนแมวทนต่อ...     22 ก.ค.

พบในโน้ตของฉัน (1)
  ...

▸ พบในรายละเอียดสินค้า (19)        ← พับเก็บไว้ กดเปิดได้
```

**ทำไมแบ่งชั้นดีกว่าแค่เรียงลำดับ:** การเรียงเฉยๆ ยังต้องเลื่อนผ่าน 28 รายการโดยไม่รู้ว่าของที่ตรงจริงจบตรงไหน — ป้ายหัวข้อบอกขอบเขตชัดเจน

**ทำไมไม่ตัด `productInfo` ออกจากการค้นไปเลย:** จะเสีย recall เวลาค้นชื่อแบรนด์ที่ปรากฏแค่ในข้อความร้าน (เช่น BMZAR, PETLUSCI, TopChoice) — การพับเก็บได้ผลลัพธ์เดียวกันโดยไม่เสียความสามารถ

**ลำดับความน่าเชื่อถือ:** ชื่อสินค้า > โน้ตของฉัน (`extraNotes`, ผู้ใช้พิมพ์เอง) > รายละเอียดสินค้า (`productInfo`, ข้อความร้าน)

**กฎการจัดชั้นเมื่อค้นหลายคำ (ต้องชัดเจน ไม่งั้นตีความได้ 2 แบบ):** รายการหนึ่งอาจเจอคำหนึ่งในชื่อ อีกคำในรายละเอียด — ให้จัดชั้นตาม**ฟิลด์ที่อ่อนที่สุดที่จำเป็นต้องใช้**:

1. ทุกคำอยู่ใน `productName` → **ตรงชื่อสินค้า**
2. ไม่เข้าข้อ 1 แต่ทุกคำอยู่ใน `productName + extraNotes` รวมกัน → **พบในโน้ตของฉัน**
3. ไม่เข้าข้อ 1-2 แต่ทุกคำอยู่ในทั้งสามฟิลด์รวมกัน → **พบในรายละเอียดสินค้า**

ตรวจสอบกับข้อมูลจริง: `"ชั้นวาง เหล็ก"` → ชั้นที่ 1 ได้ 1 รายการ ส่วนอีก 5 รายการตกไปชั้นล่าง (รวม 6 ตรงกับที่วัดไว้) · แต่ละรายการอยู่ได้ชั้นเดียวเท่านั้น ไม่ซ้ำ

**เมื่อไม่มีคำค้น:** แสดงกลุ่มตามเดือนเหมือนเดิมทุกประการ — การแบ่งชั้นนี้ทำงานเฉพาะตอนค้นหา

`riskModule` ยังคงไม่ถูกค้นเหมือนเดิม (มีคอมเมนต์อธิบายเหตุผลอยู่ในโค้ดแล้ว: เนื้อหาเป็นวลีซ้ำทั่วไปที่ใช้ร่วมกันหลายสิบรายการ)

### 3. ไม่พบผลลัพธ์ = บอกทางออก

แทน "ไม่พบรายการ" เฉยๆ ให้บอกว่าลองใช้คำที่สั้นลงหรือน้อยคำลง — เพราะสาเหตุที่พบบ่อยที่สุดคือคำค้นเยอะเกิน (AND ยิ่งหลายคำยิ่งแคบ)

### 4. รูปสินค้า + ชื่อ 2 บรรทัด (ทำคู่กัน)

- **รูปสินค้าใบแรก** ขนาด ~36px หน้าแถว (`productImages[0]`, เรียง `sortOrder` มาแล้วจาก `app/page.tsx:24`)
- URL: `/api/uploads/<entryId>/<filename>` — route มีอยู่แล้วที่ `app/api/uploads/[...path]/route.ts`
- ไม่มีรูป → กรอบว่างขนาดเท่ากัน (**21 จาก 71 รายการ** เป็น entry เก่าก่อนมีฟีเจอร์รูป)
- **ชื่อขึ้นได้ 2 บรรทัด** แทนตัดบรรทัดเดียว → จาก ~15 เป็น ~35 ตัวอักษร

**ทำไมทำคู่กัน:** รูปสูง 36px ซึ่งพอดีกับข้อความเล็ก 2 บรรทัดอยู่แล้ว — **ได้ชื่อยาวขึ้นโดยไม่เปลืองความสูงเพิ่มเลย**

**ทำไมต้องมีทั้งคู่ ไม่เลือกอย่างใดอย่างหนึ่ง:** แก้คนละเคส — รูปแก้เคสชื่อซ้ำ (ที่ข้อความแก้ไม่ได้เลยเพราะชื่อเหมือนกันจริงๆ) ส่วน 2 บรรทัดแก้เคสชื่อยาวของ 21 รายการที่ไม่มีรูป

**โหลดรูปแบบ lazy** (`loading="lazy"`) — 71 รูปในแถบข้างที่สกรอลได้

### 5. แสดงวันที่สร้างเมื่อยังไม่ได้ลงคลิป

ตอนนี้ `shortDate(entry.postedAt)` คืน null เมื่อยังไม่ลงคลิป → ช่องวันที่ว่างเปล่าใน **7 รายการ**

เปลี่ยนเป็น: ถ้าไม่มี `postedAt` ให้แสดง `createdAt` แทน โดย**แยกให้เห็นว่าเป็นคนละความหมาย** (เช่น สีจางกว่า หรือมีเครื่องหมายนำหน้า)

**ทำไมดีกว่าใส่จุดสถานะ:** ให้ข้อมูลจริง (สร้างเมื่อไหร่) แทนธงเปิด/ปิด · แก้คู่ BMZAR ได้เหมือนกัน (สร้าง 21 vs 28 ก.ค.) · เติมช่องที่ว่างอยู่ — ได้ 3 อย่างจากการแก้จุดเดียว

**ต้องระวัง timezone:** `postedAt` เก็บเป็น UTC midnight ส่วน `createdAt` เป็น timestamp จริง — เป็นกับดักเดียวกับ `toDateInputValue` / `toLocalDateInputValue` ใน `production-panel.tsx` ที่ CLAUDE.md เตือนไว้ ต้องใช้ตัวจัดรูปแบบคนละตัว ไม่ใช้ร่วมกัน

### 6. กดการ์ดคำแนะนำแล้วเด้งไปที่ entry นั้น

การ์ดใน `components/recommendations.tsx` (บรรทัด 96-99) มี `s.entryId` อยู่แล้ว — ทำให้กดได้แล้วสลับไปแท็บ ① พร้อมเลือก entry นั้น

แบบแผนมีอยู่แล้วใน `prompt-workspace.tsx`: `startNew()` และ `handleDuplicate()` ต่างก็เรียก `setTab("brief")` คู่กับการตั้ง `selectedId` — ทำแบบเดียวกัน

**ทำไมทำอันนี้แทนการใส่รายได้ในแถบข้าง:**

| | ใส่รายได้ในทุกแถว | ทำการ์ดกดได้ |
|---|---|---|
| แก้ friction ข้ามแท็บ | ได้ | ได้ |
| ความถูกต้อง | **แย่** — คลิปที่เพิ่งลงจะขึ้น ฿0 เพราะเงินยัง settle ไม่ทัน (รอบ settlement 7+ วัน) อ่านแล้วเข้าใจผิดว่าเจ๊ง | ไม่มีปัญหา |
| สัญญาณรบกวน | ~60 จาก 71 แถวขึ้น ฿0 หรือเลขจิ๋ว | ไม่มี |
| ความเสี่ยงตัวเลขขัดกัน | เลขเดียวกันอยู่ 2 ที่ (เคยพังมาแล้วกับ `revenueByClip` vs `summarizeOrders`) | ไม่มี |

## Non-goals

- **ไม่ใส่รายได้/วิวในแถบข้าง** (เหตุผลในตาราง §6)
- **ไม่ทำหัวข้อเดือนติดหนึบ (sticky)** — ทุกแถวมีวันที่กำกับอยู่แล้ว รู้ตำแหน่งได้โดยไม่ต้องมีหัวข้อลอย
- **ไม่เปลี่ยนการจัดกลุ่มเดือน** — ก.ค. มี 51 รายการดูเยอะ แต่พอค้นหาใช้ได้จริงแล้วจะ browse น้อยลง เปลี่ยนตอนนี้เป็นการเดา
- **ไม่เพิ่มตัวกรอง/การเรียงลำดับใหม่** — ตัวกรอง "ยังไม่ได้กรอกผลลัพธ์" ที่มีอยู่ยังทำงานดี
- **ไม่แตะ** `lib/recommender.ts` (เปลี่ยนเฉพาะชั้นแสดงผลของการ์ด) · `lib/angle.ts` · `lib/dashboard.ts` · `lib/weekly-scoreboard.ts`
- **ไม่ใช้ `next/image`** — route เสิร์ฟรูปเป็นไฟล์ตรงๆ อยู่แล้ว และโค้ดเดิมใน `brief-form.tsx` ใช้ `<img>` พร้อม eslint-disable เป็นแบบแผนอยู่แล้ว

## Constraints (จาก CLAUDE.md)

- ห้ามรัน `npm run build`/`npm run dev` ชน port 3000 — ใช้ `npx tsc --noEmit` + isolated dev server (`cp dev.db dev-test.db` + `NEXT_DIST_DIR=.next-dev DATABASE_URL="file:./dev-test.db" npm run dev -- -p 3001`) แล้ว cleanup
- ห้ามแตะ `dev.db` ตัวจริงในการทดสอบที่เขียน · อ่านแบบ `readonly: true` ได้
- ไม่มี test runner และไม่มี `tsx` — ทดสอบ pure function ด้วย tsc-compile-then-node ในโฟลเดอร์ scratch
- ห้าม emoji · UI ภาษาไทย · design token เดิมเท่านั้น (`ink` `ink-2` `paper` `marigold` `rust` `smoke` `record` `border` `card` `muted-foreground` `foreground`)
- ไอคอน lucide ต้องเช็กชื่อ canonical จากไฟล์ `.mjs` จริงก่อนใช้
- เช็ก `git diff tsconfig.json` ก่อน commit ทุกครั้ง · ห้าม `git add -A`
- Layout เป็น fixed-viewport-with-internal-scroll — แถบข้างมี `lg:h-full` และรายการอยู่ใน `overflow-y-auto` การเพิ่มความสูงแถวต้องไม่ทำให้ chain นี้พัง

## Verification

**ตรรกะค้นหา (สคริปต์ node ใน scratch — แยกฟังก์ชันออกมาให้ทดสอบได้):**
- คำเดียว: ผลเหมือนพฤติกรรมปัจจุบันเป๊ะ (ไม่ regress)
- หลายคำ: 5 เคสที่เคยได้ 0 ต้องเจอตามจำนวนที่วัดไว้ (7, 6, 3, 1, 2)
- เว้นวรรคหน้า/หลัง/หลายช่อง ต้องไม่ทำให้ผลเพี้ยน
- คำค้นว่าง → คืนทุกรายการ
- การแบ่งชั้น: รายการที่ตรงทั้งชื่อและรายละเอียด ต้องปรากฏใน "ตรงชื่อ" เท่านั้น ไม่ซ้ำสองที่

**UI จริง (dev-test.db, port 3001):**
- พิมพ์ "ที่นอน แมว" → เจอ 7 รายการ แบ่งชั้นถูกต้อง (เดิมได้ 0)
- พิมพ์ "ผ้า" → "ตรงชื่อ" 9 รายการอยู่บนสุด ส่วน 19 รายการที่เหลืออยู่ในหัวข้อที่พับไว้
- กดเปิด/ปิดหัวข้อ "พบในรายละเอียดสินค้า" ได้
- คำค้นที่ไม่เจอ → ขึ้นข้อความแนะนำให้ลดคำ
- แถวแสดงรูปสินค้า · รายการที่ไม่มีรูป (21 รายการ) ขึ้นกรอบว่างขนาดเท่ากัน ไม่ทำให้ layout เหลื่อม
- ชื่อยาวขึ้น 2 บรรทัด — เคส "【พร้อมส่ง】BMZAR..." ต้องเห็นคำว่า "เคาเตอร์ครัว"
- คู่ BMZAR แยกออกจากกันได้ด้วยวันที่สร้าง (21 vs 28 ก.ค.)
- กดการ์ดคำแนะนำในแท็บ ④ → เด้งไปแท็บ ① พร้อมเลือก entry นั้นถูกต้อง
- ตัวกรอง "ยังไม่ได้กรอกผลลัพธ์" ยังทำงานเหมือนเดิม และใช้ร่วมกับคำค้นได้
- แถบข้างยังสกรอลได้ปกติที่ 71 รายการ · ไม่มี horizontal scroll · ไม่มี console error
- `npx tsc --noEmit` + `npm run lint` สะอาด
