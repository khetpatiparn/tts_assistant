# บอทคุมหน้าเว็บ Google Flow จริงด้วย Chrome ที่มองเห็นได้ บนบัญชีสำรอง — ไม่ใช้ API

การวาดรูปอ้างอิงและเรนเดอร์คลิปทำผ่านหน้าเว็บ Flow ด้วย Playwright + Chrome จริง (headed, โปรไฟล์ `.flow-profile`) บน**บัญชี Google สำรอง** ไม่ใช่บัญชีหลัก Ultra ของผู้ใช้ เพราะเครดิต Flow ผ่านหน้าเว็บถูกกว่าทุกทาง API ราว 6–8 เท่า (~15 เครดิต/คลิป) และผู้ใช้ตัดสินใจชัดว่าไม่ใช้ API (2026-09-30) ส่วนบัญชีสำรองจำกัดความเสียหายถ้าโดนจับว่าเป็นบอท

**ทางเลือกที่ไม่เลือก:** (1) API วิดีโอ/รูปที่จ่ายต่อครั้ง — แพงกว่ามาก (2) ยิง RPC `batchexecute` ของ Flow ตรงๆ — payload อ่านไม่ออกและเป็นสัญญาณบอทชัดที่สุด (3) ใช้บัญชีหลัก — ถ้าโดนแบนเสียทั้งเครดิต Ultra และงานที่ทำมือ

**ผลที่ยอมรับ:** หน้าเว็บเปลี่ยนเมื่อไหร่บอทพังที่ selector (แก้ที่ `worker/flow-selectors.ts` ไฟล์เดียว) · หน้าต่าง Chrome ต้องเปิดค้างและห้ามย่อ · โปรไฟล์เปิดได้ทีละโปรเซส สคริปต์ทดสอบที่ใช้ Flow จริงต้องหยุดบอทก่อน · โปรเจกต์ใน Flow เป็นของบัญชีสำรอง เปิดในเบราว์เซอร์บัญชีหลักไม่ได้ (ปุ่มในหน้า `/flow` เปิด Brave โปรไฟล์บัญชีสำรองแทน) · พังแล้วหยุดทั้งคิว ไม่ลองซ้ำเอง เพราะการยิงซ้ำใส่หน้าที่พังคือสัญญาณบอทที่ชัดที่สุด

**2026-10-03 — ข้อยกเว้นของ "พังแล้วหยุดทั้งคิว":** ถ้า Flow เองรายงานว่าวาด/เรนเดอร์ไม่สำเร็จ (`flow_error` ที่ขั้น wait-results/wait-render) บอทข้ามงานนั้นไปทำงานถัดไปได้ — จำกัดไม่เกิน `autoContinueDailyCap` ครั้ง/วัน (ตั้งไว้ 2 ตอนตัดสินใจ — ตั้งแต่ 2026-10-06 ค่าใน `flow-worker.config.json` คือ 999 = แทบไม่จำกัด เพราะผู้ใช้สั่งวาดเยอะ · 0 = ปิดฟีเจอร์) และห้ามข้ามสองครั้งติดกันโดยไม่มีรอบสำเร็จคั่น เหตุผล: สินค้าเดียวพังตอนเช้าทำให้คิวทั้งวันไม่ขยับ ทั้งที่การ์ด "failed to generate" ไม่ใช่สัญญาณบอท และบอทไม่ได้ยิงซ้ำใส่งานที่พัง (ไม่ retry งานนั้นเอง) ทุกชนิดอื่น (captcha, login, selector, timeout, crash) ยังหยุดทั้งคิวตามเดิม · ดู `docs/agents/flow-bot.md`

**2026-10-06 — ข้อยกเว้นที่สอง: เน็ตสะดุดตอนเปิด Flow** (`worker_crash` ที่ open-flow ข้อความ `net::ERR_NETWORK_CHANGED`/`ERR_INTERNET_DISCONNECTED`/… หลังลองเปิดหน้าซ้ำครบ 5×15 วิ) บอทข้ามงานนั้นไปงานถัดไปได้ ไม่เกิน 2 ครั้งติดกันโดยไม่มีรอบสำเร็จคั่น (ครั้งที่ 3 = เน็ตล่ม → หยุดคิว) ไม่มีเพดานรายวัน เหตุผล: เกิดก่อนแตะ Google (ไม่ใช่สัญญาณบอท ไม่เสียเครดิต) แต่เคยทำคิวหยุด ~5 ชม. (2026-10-05) · รอบ 4 และความล้มเหลวชนิดอื่นทั้งหมดยังเหมือนเดิม · ดู `docs/agents/flow-bot.md`

**2026-10-06 — โหลดหน้าไม่ทัน (`page.goto` timeout) ตอนเปิด Flow นับเป็นเน็ตสะดุด** (เหตุการณ์ 2026-10-06: Flow ตอบโครงหน้าแต่แอปไม่วาดภายใน 45 วิ เดิมตีเป็น `selector_drift` แล้วหยุดทั้งคิว) — ลองเปิดซ้ำ แล้วข้ามงานตามกฎข้อยกเว้นที่สอง เหตุผล: ยังไม่ถึงขั้นหาปุ่ม จึงไม่ใช่หลักฐานว่าหน้าเปลี่ยน และยังไม่ได้ขออะไรจาก Google · ขอบเขตเดียวกับข้อยกเว้นที่สอง: เฉพาะขั้น open-flow ของรอบ 1–3 — timeout ของการรอ/หาปุ่ม และ goto timeout ของรอบ 4 (โหลด 1080p) ยังเป็น `selector_drift` หยุดคิวตามเดิม

**2026-10-06 — ปุ่ม "ให้บอททำงานอื่นต่อ (ปล่อยงานพังไว้)" (ปลดการหยุดอย่างเดียว ไม่แตะงานพัง)** — เป็นการตัดสินใจของคน ไม่ใช่บอทลองซ้ำเอง: ผู้ใช้กดเองเมื่อเห็นว่าพังแค่งานเดียว (เจอจริง: เน็ตสะดุดงานเดียว คิวหยุด 20+ ชม. ทั้งที่มีงานรออีก 10) · ปลดได้**เฉพาะเหตุหยุด `worker_crash` และ `generation_timeout`** · ห้ามตั้งใจ: `captcha` (กฎพัก 1 ชม. ข้างบน) `login_required` (ไม่มี session) และ `host_unsupported`/`selector_drift`/`flow_error`/`download_failed` (พังแบบเดิมจะวนกับงานถัดไป ต้องซ่อมก่อน) · งานพังยัง `failed` บอทไม่หยิบงานพัง ผู้ใช้ รันต่อ/ข้าม ทีหลัง · ไม่มีงานพัง = ปุ่มเดียวกันข้อความ "ให้บอททำงานต่อ" · ดู `docs/agents/flow-bot.md`

**2026-10-07 — "พังแล้วหยุดทั้งคิว ไม่ลองซ้ำเอง" เปลี่ยนเป็น: จอดงานที่เป็นปัญหาของงานนั้น · ตัดวงจรแล้วลองงานถัดไปเองตามเวลาแบบจำกัด · สัญญาณบอทยังหยุดรอคนเสมอ** (วิจัย `docs/research/2026-10-06-continue-queue-despite-failures.md`: คิวหยุด 16 ครั้งใน 3 สัปดาห์ 12 ครั้งหายเมื่อกดรันต่อครั้งเดียว ไม่เคยเจอ captcha/403/429 · รอคนกดรวม ~117 ชม.) — (1) จอดงาน (failed, "รันต่อ" ได้, ไม่ลองซ้ำงานนั้น) เพิ่ม `generation_timeout` ที่ wait-*, `download_failed` ที่ download-preview และด่านจำนวนรูปแนบไม่ตรง (ยังไม่ได้กดสร้าง) · ตัวนับ "ติดกัน" ตัวเดียวทุกชนิด: จอดได้ไม่เกิน 2 งานโดยไม่มีรอบสำเร็จคั่น (แทนตัวนับแยกของข้อยกเว้นที่หนึ่ง/สอง) (2) งานที่ 3 ติดกัน = หยุดคิว และถ้าเหตุคือ `worker_crash`/`generation_timeout`/`flow_error`/`download_failed` บอทนัดลอง**งานถัดไป 1 งาน** เองหลัง 15 → 30 → 60 นาที (±20%) ผ่าน = กลับเป็นปกติ · ลองไม่ผ่านครบ 3 ครั้ง = หยุดรอคน (circuit breaker half-open — ยิงหน้า Flow ซ้ำอย่างมาก 3 ครั้งในราว 2 ชม. ไม่ใช่ถี่) (3) **ไม่ลองเองเด็ดขาด:** `captcha`/403/unusual activity (กฎพัก 1 ชม. ข้างบน), `login_required`, `host_unsupported`, `selector_drift` (ข้อมูล 21 ก.ย.: รอไปก็ไม่หาย ต้องแก้โค้ด), บอทล้มทั้งโปรเซส, รอบ 4 · ปุ่มรันต่อ/ข้าม/ให้บอททำงานอื่นต่อ ยังเป็น manual override · ความเสี่ยงที่ยังตรวจสอบไม่ได้: Google มองการลองตามเวลาเป็นสัญญาณบอทหรือไม่ (ไม่มีเอกสาร) — จึงจำกัด 3 ครั้งและเริ่มที่ 15 นาที · ดู `docs/agents/flow-bot.md`

**2026-10-07 — เปิดบอทใหม่ = กู้การหยุดเพราะเน็ตสะดุดเอง** (เคสจริง 2026-10-06: `page.goto` timeout ที่ open-flow ถูกตีเป็น `selector_drift` ก่อนแก้ แล้วค้างข้ามการเปิดบอทใหม่ ปุ่ม "ให้บอททำงานอื่นต่อ" ก็ไม่ขึ้น) — เหตุหยุด `selector_drift`/`worker_crash` ที่งานต้นเหตุพังตอนเปิด Flow (รอบ 1–3) ด้วยข้อความเน็ตสะดุด/โหลดหน้าไม่ทัน → คืนงานนั้นเข้าคิว + ปลดการหยุด แบบเดียวกับ "รันต่อ" (เหตุผลเดียวกับการกู้ `login_required`: การเปิดบอทใหม่คือการกระทำของคน และยังไม่ได้ขออะไรจาก Google) · เหตุอื่นปล่อยการหยุดไว้
