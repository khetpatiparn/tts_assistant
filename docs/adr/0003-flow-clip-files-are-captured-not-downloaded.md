# ไฟล์คลิปจาก Flow ได้มาด้วยการดักคำขอของหน้าเว็บแล้วดึงเอง ไม่ใช้การดาวน์โหลดของเบราว์เซอร์ และเปิดเมนูด้วยเมาส์เส้นตรง

ตอนกดโหลดคลิปในเมนู ⋯ → Download ของ Flow หน้าเว็บจะ fetch `flow-content.google/video/<id>` (หรือ `<id>_upsampled` สำหรับ 1080p) เองก่อนแล้วค่อยสั่งดาวน์โหลด blob — **Chrome ของบอท crash ทันทีที่เริ่มดาวน์โหลด blob** (crash dump ยืนยัน 2 ครั้ง 2026-10-01) บอทจึงใช้ `page.route` ดักคำขอไฟล์นั้น ยกเลิกทิ้ง แล้วดึงไฟล์เองด้วย `page.request` จาก URL เดียวกัน (ลิงก์ลงลายเซ็นใช้ได้หลายชั่วโมง ไม่ต้อง cookie) id ใน URL ยังใช้ระบุว่าช่องไหนคือคลิปที่ผู้ใช้กดผ่าน เพราะหลังเปิดโปรเจกต์ใหม่ thumbnail/`<video src>` เป็นลิงก์ `/asb/` ที่ไม่มี id · เมนูย่อยเปิดด้วยการชี้ "Download" แล้วเลื่อนเมาส์**เส้นตรง**แนวนอนเข้าเมนูย่อย แนวดิ่งถึงตัวเลือก — เมนูของ Flow ไม่ตอบคีย์บอร์ดแบบ Angular Material มาตรฐาน (Enter เปิดหน้าแก้ไขคลิปแทน) และเส้นเมาส์โค้งที่ผ่านรายการอื่นทำให้เมนูย่อยปิด

**ทางเลือกที่ไม่เลือก:** (1) event `download` + `saveAs` — คือทางที่ crash (2) คีย์บอร์ด ArrowRight/ArrowDown/Enter — ลองแล้วเปิดผิดหน้า (3) เทียบเนื้อไฟล์ 720p หรือ hover อ่าน `<video src>` เพื่อหาช่องคลิป — หลังโหลดหน้าใหม่ไม่มี id ให้เทียบ

**ผลที่ยอมรับ:** หน้า Flow ของบอทขึ้น toast "Failed to download media" ทุกครั้ง (เพราะเรายกเลิกเอง) · การส่องหาช่องคลิปต้องเปิดเมนู 720p ของแต่ละช่อง (ไม่โหลดจริง ไม่เสียเครดิต) · เมนูพังอีกเมื่อไหร่ให้รัน `npm run flow-smoke:dl -- <projectId>` (สอดแนม ไม่เสียเครดิต) ก่อนแก้
