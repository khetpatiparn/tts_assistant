# Showcase (Showcase Scanner extension, ลิงก์ปลายทาง, หน้า `/showcase` + `/products`)

คำศัพท์ (Candidate, Showcase, Source photo, Showcase Scanner, Destination, Destination link) อยู่ `CONTEXT.md` · สเปก: `docs/superpowers/specs/2026-09-29-showcase-destination-link-design.md` · เหตุผลที่ฝังรหัสในลิงก์: `docs/adr/0001-destination-link-secret-in-url.md` · protocol ที่แจกคนอื่น: `showcase-extension/docs/INTEGRATION.md`

## Protocol ลิงก์ปลายทาง (`showcase-scanner/1`)

- **extension ไม่รู้จัก Angle** — ส่งผลสแกนไปที่ "ลิงก์ปลายทาง" ลิงก์เดียว Angle เป็นแค่ปลายทางหนึ่ง ผ่าน route เดียว `app/api/scanner/route.ts`: GET = รายการ product ID ที่มีแล้ว · POST text/plain = นำเข้าผ่าน `importShowcaseBatch`
- **การยืนยันตัวตน = token ในลิงก์อย่างเดียว** — token อยู่ตาราง `ScannerLink` (แถว singleton) เทียบแบบ timing-safe ใน `lib/scanner-link.ts` · ปุ่มคัดลอก/สร้างลิงก์ใหม่อยู่หน้า "หาสินค้า" (`components/scanner-link-box.tsx`) · ระบบเก่า (secret header `x-showcase-secret`, `SHOWCASE_IMPORT_SECRET`, route `/api/showcase-import*`) ลบหมดแล้วรวมถึงใน `.env` — อย่าเอากลับมา
- CORS ของ `/api/scanner` (`lib/cors.ts`) จำเป็น เพราะหน้า extension เป็นคนละ origin เสมอ — extension ไม่มี (และไม่ต้องมี) host permission ของ localhost
- **POST เป็น simple request** (text/plain ไม่มี custom header) — Google Apps Script ต้องรับได้ · extension รอ POST 120 วิ เพราะ Angle โหลดรูปสินค้าในคำขอเดียวกัน
- **แก้ protocol ต้องแก้ 3 ที่พร้อมกัน:** `showcase-extension/extension/src/dashboard/destination.ts` (ฝั่งส่ง) · `app/api/scanner/route.ts` (Angle) · `showcase-extension/docs/INTEGRATION.md` + `showcase-extension/docs/examples/*` (ที่คนอื่นใช้ต่อระบบ)

## แจก extension เป็น zip

- `cd showcase-extension && npm run package` → `dist-zip/showcase-scanner-<version>.zip` — สร้างด้วย `C:\Windows\System32\tar.exe` (Compress-Archive ของ PowerShell 5.1 เขียนชื่อไฟล์เป็น `\` จน macOS/Linux แตกไฟล์พัง)
- **ตัว extension อยู่ที่รากของ zip** (แตกแล้ว Load unpacked ที่โฟลเดอร์นั้นได้ทันที) เอกสาร developer อยู่ใน `developer/` — รุ่นแรกซ่อน extension ในโฟลเดอร์ย่อยแล้วผู้ใช้จริงได้ "Manifest file is missing"
- ชื่อไฟล์/โฟลเดอร์ใน zip ขึ้นต้นด้วยตัวอื่นที่ไม่ใช่ `_` (Chrome ไม่โหลด — `scripts/package.mjs` เช็กให้)
- **คู่มือหลักอยู่ในตัว extension** หน้า `extension/src/help/` (เปิดเองตอนติดตั้งครั้งแรกผ่าน `onInstalled` ใน background.ts, ลิงก์จาก popup/หน้าจัดการ, ปุ่มคัดลอกคู่มือไปให้ AI + ดาวน์โหลด/คัดลอกโค้ด) — ผู้ใช้จริงไม่เปิดไฟล์ `.md` ในโฟลเดอร์ zip · `scripts/build.mjs` ก๊อป `docs/INTEGRATION.md` และ `docs/examples/quickstart-node.mjs` (ตัวอย่างสั้นสุดสำหรับ developer, Node ล้วน รันจริงแล้ว) เข้า `help/` ทุก build → แก้ที่ต้นฉบับใน `docs/` ไม่ใช่สำเนาใน dist

## หน้า `/showcase` กับ `/products` (ตาราง `ProductCandidate` เดียวกัน)

- **คนละขั้นงาน แยกด้วย `sourceProductId`** (ดู Candidate vs Showcase ใน `CONTEXT.md`): `/products` = แคปหน้าจัดอันดับ (`sourceProductId IS NULL`) ไว้เลือกว่าจะเพิ่มอะไรเข้า Showcase · `/showcase` = รายการงานที่ต้องทำ (`sourceProductId NOT NULL`) — **คิวรีของสองหน้ากรองคอลัมน์นี้เสมอ**
- ตรรกะสถานะ (ยังไม่เริ่ม/กำลังทำ/โพสต์แล้ว/ไม่ทำแล้ว) อยู่ `lib/showcase.ts` (pure, ตรวจด้วย `node scripts/check-showcase.mjs`) คิดจาก `linkedEntryId` + `videoUrl` ของ Entry + `dismissedAt`
- ยุบแถวซ้ำด้วย `sourceProductId` (ชื่อสินค้าซ้ำกันได้ข้ามสินค้า) · "ไม่ทำแล้ว" เซ็ต `dismissedAt` ทุกแถวของ `sourceProductId` เดียวกัน
- **Product ID แสดงนอกหน้า Showcase ด้วย (2026-10-04)** — `getProductIdsByEntry` (`lib/flow-queries.ts`) ผูก `ProductCandidate.linkedEntryId → sourceProductId` โชว์พร้อมปุ่มคัดลอกที่หัวงาน `/flow` กับหน้า entry และเป็นบรรทัดท้าย `โพสต์.txt` ของโฟลเดอร์ TTS (ไว้ค้นตอนปักตะกร้า เพราะสินค้าเก่าถูกดันลงไป) · entry ที่ไม่ได้มาจาก Showcase ไม่มี ID ไม่แสดงอะไร · งานที่ "ทำต่อเอง" (`docs/agents/flow-bot.md`) ยังเป็น "กำลังทำ" ใน Showcase จนกว่าจะวางลิงก์คลิป — สถานะคำนวณจากลิงก์คลิปของ entry ไม่ใช่จากสถานะงาน Flow
- **แฮชแท็กที่ต้องลง (Required hashtag, 2026-10-10)** — ผู้ใช้ติ๊กหลายตัวใน `/showcase` แล้วพิมพ์ครั้งเดียว (`setRequiredHashtags` ทับของเดิม / `clearRequiredHashtags` ปุ่มลบแยก — ช่องว่างไม่ใช่การลบ) · เก็บตาราง `ProductHashtag` ผูก `sourceProductId` (ไม่ผูกแถว `ProductCandidate` เพราะส่งซ้ำได้แถวใหม่ทุกชุด) · **`importShowcaseBatch`/`/api/scanner`/extension ไม่รู้จักตารางนี้เลย — สแกนซ้ำจึงไม่ทับ** (อย่าเพิ่มให้ import แตะ) · ตรรกะ pure (แปลงข้อความ เติม `#` แยก `#a#b` ตัดซ้ำไม่สนตัวพิมพ์ จำกัด 10 อัน/100 ตัว) อยู่ `lib/required-hashtag.ts` ตรวจด้วย `node scripts/check-required-hashtag.mjs` · โชว์ป้ายที่ `/showcase`, หัวงาน `/flow` และหน้า entry (`RequiredHashtagCopy` ผ่าน `getRequiredHashtagsByEntry` ต่อจาก `getProductIdsByEntry`) — **ไม่เขียนลง `โพสต์.txt` และไม่เติมลง `hashtags` ของ entry เอง** (ผู้ใช้ไม่ใช้ไฟล์นั้น) · ตารางไม่มี (ยังไม่ migrate) อ่านแล้วคืนว่าง + log ไม่ทำให้ `/flow`/entry ล่ม · **ไม่เก็บว่าสินค้า "เป็นของกิจกรรม" หรือไม่** — ข้อมูลไม่พอวิเคราะห์ เงื่อนไขกลับมาคิดดู `docs/research/2026-10-10-campaign-flag-for-analysis.md`
- `SHOWCASE_TRACKING_SINCE` ตัดชุดแรก 197 ตัวทิ้งโดยตั้งใจ (ผู้ใช้เลือกเริ่มนับใหม่)
- งานที่พังรอบ 3–4 ของ Flow = blocked เสมอ (รายละเอียดใน `docs/agents/flow-bot.md`)
- **"เลือกรูปใหม่" (`retryShowcasePhoto`) = กติกาเดียวกับ "เปลี่ยนรูปต้นทาง" ของ /flow (ticket 05, 2026-10-04)** — `showcaseFlowState` (`lib/showcase.ts`) ใช้ `canChangeSource` ของ `lib/flow-lifecycle.ts`: `retry` = ยังไม่มีงาน / ถูกข้ามรอบ 1–2 / Flow วาดไม่สำเร็จเอง (`flow_error`) รอบ 1–2 (ป้ายแดง + ปุ่มหลัก) · `change` = งานยังเดินก่อนเริ่มเรนเดอร์ (queued_r1/r2/r3, review_r1/r2, awaiting_prompt — ปุ่มรองไม่มีป้ายแดง) · `blocked` = พังด้วยเหตุอื่น (captcha/login ฯลฯ — **ห้ามเปิดทางลัด** เพราะเปลี่ยนรูปของงานพัง = ปลดการหยุดของบอท) หรือพังรอบ 3+ · `busy` = บอทกำลังทำ/เริ่มเรนเดอร์แล้ว/เสร็จ/ข้ามรอบ 3+ · **มีงานอยู่แล้ว = เปลี่ยนรูปต้นทางของงานล่าสุด** (`changeSourcePhoto` — งานเดิมกลับไปวาดรอบ 1 ไฟล์รอบเก่าไม่ถูกทับ ไม่ "ข้าม" งานเดิม ไม่สร้างงานใหม่) · สร้างงานใหม่เฉพาะเมื่อ entry ยังไม่มีงาน · ข้อความแข่งกับบอทคืนเป็น error ให้หน้า Showcase โชว์
- `ShowcasePhotoPicker` (`components/showcase-photo-picker.tsx`) รับรูปเป็น `{ id, src, filename }` (`shopPhotoSrc(candidateId, filename)`) ใช้ร่วมกับหน้า /flow · `allowLocalFile` เพิ่มปุ่ม "เลือกไฟล์จากเครื่อง" (blob: URL — ครอปได้เหมือนรูปจากร้าน) · `confirmVerb`/`note` เปลี่ยนคำบนปุ่ม/บรรทัดอธิบาย · `showExtraPrompt={false}` ปิดช่องข้อความถึง Flow · คลังรูปในหน้า entry ใช้ตัวนี้ด้วย (รูปเดียว → ขั้นครอปทันที — `docs/agents/flow-bot.md` หัวข้อคลังรูป)

## "ทำคลิปตัวนี้" (`startShowcaseProduct`)

- รับ**ไฟล์**รูปต้นทาง 1 รูป (ครอปด้วย canvas ในเบราว์เซอร์ `components/showcase-photo-picker.tsx`) → สร้าง Entry + เข้าคิว Flow · รูปนั้นเป็นรูปสินค้าของ entry ทันที (รูปต้นทางอัตโนมัติ — "เลือกรูปใหม่"/"เปลี่ยนรูปต้นทาง" แทนรูปเดิม เลือกรอบ 2 แทนด้วยรูปที่ Flow วาด ดู `docs/agents/flow-bot.md`)
- **ชื่อสั้น (Short name) ย่อเบื้องหลัง ไม่ให้ผู้ใช้รอ (ticket 07, 2026-10-04)** — `startShowcaseProduct`/`createEntryFromCandidate` สร้าง entry ด้วยชื่อเต็มของร้าน + เข้าคิวทันที แล้ว `void shortenInBackground(id)` (`lib/short-name-db.ts`: `ensureShortName` = `shortenProductName` flash-lite แล้วผ่าน `shortNameOutcome` ใน `lib/flow-jobs.ts` · ลองซ้ำเอง 10 วิ / 1 นาที / 5 นาที · ไม่ throw · แต่ละครั้งรอไม่เกิน `SHORT_NAME_ATTEMPT_TIMEOUT_MS` 60 วิ กันคำขอค้าง) · สำเร็จ = `productName` สั้น + ชื่อเต็มใน `productInfo` ขึ้นต้น `ชื่อเต็มจากร้าน: ` (`FULL_TITLE_PREFIX`, `productInfoWithFullTitle` — ข้อความที่ผู้ใช้เขียนไว้คงอยู่ ต่อบรรทัดใหม่) · เขียนแบบมีเงื่อนไข (ผู้ใช้แก้ชื่อระหว่างรอ = ไม่ทับ) · **ไม่มีเพดาน 8 วิแล้ว** — เดิมรอ Gemini ในปุ่มสูงสุด 8 วิ กดหลายตัวติดกันแล้วเกินเวลา 16 ครั้งในวันเดียว ได้ชื่อร้าน 13/20 งาน · **เหตุผลที่ต้องย่อ:** บอทพิมพ์ `productName` ลงพรอมต์วาดรูปของ Flow ชื่อ SEO ยาวที่มีคุณสมบัติ ("หนานุ่มพิเศษ ซึมซับดี…") ทำให้ Flow ใส่ตัวหนังสือลงในรูป
- **"ชื่อยังเป็นชื่อเต็มของร้าน" ตัดสินที่ `isUnshortenedName` (`lib/flow-jobs.ts`) ที่เดียว** = `productName` ตรงชื่อของ `ProductCandidate` ที่ผูก (`linkedEntryId`, ไม่สนช่องว่าง) และ (ชื่อร้านนั้น**ไม่สั้น** (> 30 ตัว/หลายบรรทัด) **หรือ** `productInfo` ยังไม่มี `FULL_TITLE_PREFIX`) — ชื่อร้านยาวนับว่ายังไม่ย่อเสมอแม้มี prefix แล้ว (2026-10-06: งานเก่าที่กติกาเดิมบันทึก `kept_full` ให้ชื่อร้านยาว บอทจึงรอ/ย่อใหม่ และสคริปต์ย้อนหลังหยิบไปย่อ · ย่อแล้ว prefix เดิมคงไว้ ไม่ต่อซ้ำ) · ความยาว/การเทียบ "สั้นลง" นับแบบเดียวกันทุกที่ (ยุบช่องว่าง + code point) · ตัวย่อตอบชื่อที่ไม่สั้นลง = ใช้ชื่อร้านได้**เฉพาะเมื่อชื่อร้านสั้นอยู่แล้ว (≤ 30 ตัว บรรทัดเดียว)** (`kept_full`: คงชื่อ + ใส่ prefix ใน productInfo ไม่วนย่อซ้ำ) · ชื่อร้านยาวกว่านั้นที่ได้คืนมาเท่าเดิม = ไม่สำเร็จ ลองใหม่ งานรอ (เดิมนับเป็น `kept_full` แล้วชื่อร้านยาวหลุดเข้าพรอมต์ Flow) · ตอบว่าง/เกิน 60/หลายบรรทัด = ไม่สำเร็จ ลองใหม่ — **ไม่มีการตัดชื่อเองเด็ดขาด** · บอทไม่วาดรอบ 1–2 ด้วยชื่อแบบนี้ (ย่อเองก่อนหยิบ ไม่ได้ = ข้ามไปงานอื่นก่อน — `docs/agents/flow-bot.md`) · ทางออกของผู้ใช้ถ้าตัวย่อพลาดตลอด: แก้ชื่อสินค้าในหน้า entry (ชื่อไม่ตรงชื่อร้าน = ผ่าน)
- **ลำดับใน `startShowcaseProduct`: เช็กกันสร้างซ้ำ (`linkedEntryId`) → สร้าง → ผูก → ย่อเบื้องหลัง (ไม่ await)** — guard กับ create ติดกันโดยไม่มีการรอ Gemini คั่น (ตรวจใน `scripts/check-flow-jobs.mjs`: ไม่ await ตัวย่อ, สร้างด้วย `candidate.name`, ย่อหลังสร้าง)
- **สคริปต์ย้อนหลัง** `npx tsx scripts/backfill-short-names-and-photos.ts [--apply]` (แทน `shorten-showcase-names.ts` เดิม · ไม่มี `--apply` = แสดงอย่างเดียว · idempotent · ผู้ใช้รันเองเพราะเขียน `dev.db`): ① ย่อชื่อ entry จากร้านที่ยังไม่โพสต์และ `isUnshortenedName` ด้วย `ensureShortName` ② ใส่รูปต้นทางอัตโนมัติ (`autoSourceBackfillPick` ใน `lib/auto-source-image.ts` → `replaceAutoSourceImage` · รูป = `currentSourceImage` ของงาน ไม่ใช่แถว index ต่ำสุดที่อาจเป็นรูปที่เปลี่ยนทิ้งแล้ว) ให้งานที่ยังเปิดและยังไม่ได้เลือกรอบ 2 ที่ยังไม่มีรูปต้นทางอัตโนมัติ · ทดสอบด้วย `DATABASE_URL=<สำเนา>` + `--uploads <โฟลเดอร์ชั่วคราวที่ก๊อปรูปต้นทางมา>` เท่านั้น · DB ของการย่อตรวจด้วย `npx tsx scripts/check-short-name-db.ts <สำเนา DB>` (ตัวย่อปลอม ไม่เรียก Gemini)

## รูปสินค้าจาก Showcase

- รูปมาเป็น thumbnail 300px (URL `...~tplv-…-resize-jpeg:300:300.jpeg`) — `importShowcaseBatch` โหลด `:0:0` (= ขนาดต้นฉบับ, `originalImageUrl` ใน `lib/showcase-import.ts`) ก่อน ไม่ได้ค่อยถอยไปลิงก์เดิม · CDN ของ ByteDance ไม่ต้องมี signature (ทดสอบสด 300x107 → 1861x661)
- สินค้าที่นำเข้าก่อน 2026-09-29 อัปเกรดรูปด้วย `npx tsx scripts/upgrade-showcase-images.ts <ไฟล์ JSON จาก extension>` (Angle ไม่เก็บลิงก์รูป ต้องใช้ไฟล์ export) — **สคริปต์นี้แก้ไฟล์ใน `uploads/_candidates/` ที่ใช้ร่วมกับ `dev.db` จริง** ทดสอบด้วยแถวปลอมที่มีโฟลเดอร์ของตัวเองเท่านั้น (แถวจริงบน `dev-test.db` = ไฟล์หายจากใต้ `dev.db`)
