## โปรเซสและวงจรชีวิตของบอท

- **บอทเป็นโปรเซสแยกจาก Next** (`worker/index.ts`) คุยกับเว็บผ่านตาราง `FlowJob`/`FlowJobImage`/`FlowWorkerState` เท่านั้น — `/flow` refresh ตัวเองทุก 30 วิ เพราะ worker เรียก `revalidatePath` ไม่ได้

- **สถานะของงาน (FlowJob) เปลี่ยนที่เดียวคือ `lib/flow-lifecycle.ts`** — ทุกจังหวะ (ผู้ใช้กดที่ Checkpoint: `choose`/`redo`/`approveRender`/`retryUpscale`/`resume`/`skip`/`takeOver`/`changeSource` · บอท: `claim`/`releaseForShortName`/`imagesReady`/`previewReady`/`finalClipSaved`/`finalClipMissing`/`roundFailed` · เปิดบอท: `staleUpscale`/`staleRender`/`staleRunning`/`loginRecovered`) คืนแผน = แพตช์ของงาน + ลบ/สร้างแถวคลิป + ปลดการหยุด แล้ว `lib/flow-lifecycle-db.ts` (`applyPlan`/`applyBulk`) เขียนลง DB ในทรานแซกชันเดียว · `app/actions.ts` และ `worker/index.ts` ห้ามเขียน `flowJob`/`flowJobImage` หรือปลด pause เอง (`scripts/check-flow-lifecycle.mjs` ตรวจ) — ไฟล์บนดิสก์ / `revalidatePath` / `logUserActivity` / แจ้งเตือน / `pauseWorker` ยังอยู่ที่ผู้เรียก · gate ของปุ่ม (`canApproveRender`/`canRetryUpscale`/`canTakeOver`/`isInRenderStage`) และ `friendlyJobMessage` อยู่ไฟล์เดียวกัน (pure, client import ได้)
- **ทำต่อเอง (Manual takeover, `takeOver` ใน `lib/flow-lifecycle.ts`, ศัพท์ใน `CONTEXT.md`, spec `docs/superpowers/specs/2026-10-04-manual-takeover-and-posting-days-design.md`)** — แทน `finishManually` เดิม: ทุกสถานะเปิดที่บอทไม่ได้กำลังทำ (`TAKEOVER_STATUSES` derive จากรายการสถานะ = ทุกสถานะเปิดที่ไม่ใช่ running_* — gate/adapter/หน้าจอใช้ร่วม ตัวช่วย `isBotWorking`/`isWaitingForBot` แทนเช็ก prefix · ตอนนี้ = queued_r1/r2/r3, review_r1/r2/r3, awaiting_prompt, queued_upscale, failed — running_* ไม่ได้) → `done` + `finishedAt` ทันที (งานพัง = ปลดการหยุดของบอทด้วย เหมือนข้าม) ไม่ล้างร่องรอยพัง ไม่แตะ round · **เขียนด้วย `applyTakeOver` (`lib/flow-lifecycle-db.ts`) เท่านั้น** — `applyTakeOver(jobId, plan, fromStatus)` — `updateMany` ที่ where สถานะ **ตรงกับที่อ่านมา** (ไม่ใช่แค่อยู่ในรายการ จึงปลด pause ตรงกับสถานะจริงเสมอ): บอทหยิบงานหรือสถานะเปลี่ยนระหว่างผู้ใช้กดปุ่ม = 0 แถว ไม่ปลด pause · ข้อความปฏิเสธคือค่าคงที่ `TAKEOVER_BOT_BUSY_MESSAGE` · action `takeOverFlowJob` (`app/actions.ts`) คืน `taken:false` + ข้อความไทยแทน throw (ข้อความ throw จาก server action ถูกซ่อนใน production) · "ทำเอง" **ไม่เก็บในงาน** — อ่านจากแถว `FlowActivity` `user_take_over` (+ `user_finish_manual` ของปุ่มเก่า นับเป็นทำต่อเองด้วย: `isTakeoverKind`, `getTookOverJobIds` ใน `lib/flow-queries.ts`) · ข้ามงาน (`skip`) ยังแปลว่า "เลิกทำสินค้านั้น" ไม่ปนกัน
- **เปลี่ยนรูปต้นทาง (ticket 05, `changeSource` ใน `lib/flow-lifecycle.ts`, spec `docs/superpowers/specs/2026-10-04-flow-tabs-photo-library-prompt-edit-design.md` stories 21–28) = transition ของงานเดิม ไม่ใช่งานใหม่:**

  - **ด่านก่อนแตะหน้ามีที่เดียวต่อเรื่อง:** 10-part prompt ว่าง → `renderClip` เอง (`paste-prompt`/`worker_crash` ก่อนเปิด session — สูตรที่จ่ายเครดิตกันตัวเอง) · ไม่มีแถวคลิปที่ผ่าน/media id/project → `processJob` (`find-video`/`worker_crash` — ข้อมูลอยู่ในแถวของงาน) · ยังไม่ได้เลือกรูป/ไม่มีรูปแคป → `processJob` (`open-flow`/`worker_crash`) · `scripts/check-flow-worker-pure.mjs` ตรวจว่าไม่มีด่านซ้ำ
- **errorMessage ขึ้นต้น "ได้ 720p" = งานจบด้วย Preview clip** — โปรโตคอลในข้อความ (ไม่มีคอลัมน์แยก) เขียนด้วย `previewOnlyMessage` อ่านด้วย `isPreviewOnlyMessage` เท่านั้น (ทั้งคู่ใน `lib/flow-lifecycle.ts`)
- เปิด: `flow-worker.bat` หรือ `start.bat` (เปิดบอทให้ทุกครั้ง) · หยุด: `flow-worker-stop.bat` หรือ `stop.bat` — ทั้งคู่สร้างไฟล์ `.flow-worker.stop` ให้บอทจบเองหลังงานปัจจุบัน
- **เปิดซ้อนได้ปลอดภัยเพราะ `main()` เปิด Chrome ก่อนแตะ DB** — โปรไฟล์ `.flow-profile` เปิดได้ทีละโปรเซส ตัวที่สอง launch ไม่ขึ้นแล้ว `exit(0)` เงียบๆ (ยืนยันด้วยการเปิด 2 ตัวจริง) → **stale sweep และ `upsertState` ทุกตัวต้องอยู่หลัง `launchFlowBrowser`** ไม่งั้นตัวที่สองจะทำให้งานที่ตัวแรกกำลังวาดกลายเป็น failed
- **เปิดเองตอนเข้า Windows:** shortcut `Angle (start app + Flow bot).lnk` ใน `shell:startup` รัน `start.bat silent` = server + บอทโดยไม่เด้งแท็บเบราว์เซอร์ (ลบ shortcut ถ้าจะเลิก) · เน็ตมักยังไม่ต่อตอนเพิ่งเปิดเครื่อง บอทจึงลอง `openFlowAndSettle` ใหม่ทุก 30 วิ สูงสุด 10 ครั้ง **เฉพาะ error `net::ERR_*`** ครบแล้วยังไม่มีเน็ต = ปิดตัวเองโดยไม่ pause คิว
- **ติดตั้งเป็นแอป (PWA):** `app/manifest.ts` + `public/icons/` (ยืนยันด้วย CDP `Page.getInstallabilityErrors` = ว่าง) · เลือก PWA แทน Electron โดยตั้งใจ (เหตุผลในคอมเมนต์ของ manifest) · ไม่มี service worker โดยตั้งใจ · `components/flow-title-badge.tsx` (อยู่ใน `app/layout.tsx`) โพล `/api/flow-status` ทุก 30 วิ ใส่ `(N)`/`⚠` หน้าชื่อแท็บทุกหน้า และตัวเลขบนไอคอน taskbar ด้วย `navigator.setAppBadge` (เฉพาะตอนติดตั้งเป็นแอป)
- **server และบอทรันในหน้าต่างซ่อน** (`powershell Start-Process -WindowStyle Hidden` — ผู้ใช้ไม่อยากเห็น console บน taskbar) · output อยู่ `pp-server.log`/`flow-worker.log` · หยุดด้วย `stop.bat`
- **หน้าต่างที่เห็นมีแค่ Chrome ของบอท (headed) — ปล่อยให้เปิดค้างไม่ย่อ** (หน้าเพจเป็น hidden ขณะบอทคลิก = สัญญาณบอท) ย้ายไปไว้ข้างหลังได้
- **ผู้ใช้ปิดหน้าต่าง Chrome ของบอท = บอทออกเงียบๆ ไม่หยุดคิว** (`context.on("close")` + `closingOnPurpose`) → ทุกจุดที่โค้ดปิด browser เองต้องผ่าน `closeBrowser()` · ตอนเปิดบอท ถ้า pause ค้างอยู่แต่ไม่มีงาน `failed` เลย บอทปลดให้เอง (กันทางตันที่ไม่มีงานให้กด "รันต่อ")
- **session หลุด (`login_required`) = บอทปิดตัวเอง** ทั้งตอนเริ่มและกลางคิว เพราะ Flow Login ต้องใช้โปรไฟล์เดียวกัน รอค้างไว้ก็ login ไม่ได้ · ตอนเริ่มเช็ก login ก่อน `selectorSetForHost` (ไม่งั้นหน้า login ถูกรายงานผิดเป็น `host_unsupported`) · เปิดบอทใหม่แล้ว session ใช้ได้ → ปลด pause + คืนงาน `errorKind=login_required` เข้าคิวรอบเดิม (การเปิดบอทใหม่คือการกระทำของคน ไม่ขัดกฎ "ไม่ retry เอง")
- **แจ้งเตือนเมื่อบอทต้องการคน:** `worker/notify.ts` ยิง Windows toast (PowerShell 5.1 + WinRT ไม่ต้องติดตั้งอะไร) ตอนรูปรอบใดพร้อมให้เลือก และทุกครั้งที่ `pauseWorker` — fire-and-forget (ไม่ throw ไม่ await) · ปิดด้วย `FLOW_NOTIFY=0`

## Selector และหลักฐานตอนพัง

- **selector ทั้งหมดอยู่ `worker/flow-selectors.ts` ไฟล์เดียว** 2 ชุด: `labs` (labs.google) · `migrated` (flow.google.com — ยืนยันครบรอบ 1–2 ด้วย E2E แล้ว) · selector ของวิดีโอทุกตัวอยู่ใน `video` ของชุด `migrated` และมาจาก DOM จริงใน spec Render — selector ใหม่ต้องยืนยันจาก DOM จริงเท่านั้น
- Flow เปลี่ยนหน้า → บอทพังที่ขั้นแรกที่หา element ไม่เจอ พร้อมหลักฐานใน `uploads/_flow-failures/<jobId>-<ts>/` (screenshot.png / page.html / steps.log / state.json) → แก้ selector ของขั้นนั้น → ยืนยันด้วย `npm run flow-smoke:s2 -- <รูป> "<ชื่อสินค้า>"` → กด "รันต่อ" ใน `/flow`
- **`attach-reference` พังแบบ `selector_drift` อาจเป็นของปลอมจาก `humanClick` ช้า (CPU แย่ง)** — แก้ต้นเหตุแล้วด้วย `prepareHumanClick` (`worker/humanize.ts`: หน่วง+เลื่อนเมาส์ก่อนเริ่มจับเวลา `waitForEvent("filechooser")`) ถ้ายังเจอ ให้กด "รันต่อ" เฉยๆ 1 ครั้งก่อน พังซ้ำที่ขั้นเดิมค่อยแก้ selector
- **promise ที่สร้างไว้รอแข่งกับอีกตัว (เช่น `uploadResponse` = `page.waitForResponse` คู่กับ `waitForEvent("filechooser")`) ต้องแนบ `.catch(() => {})` ทันทีที่สร้าง** — ไม่งั้นพอตัวคู่แข่ง throw ก่อน มันจะหมดเวลาทีหลัง (`uploadTimeoutMs` 120s) เป็น unhandled rejection ที่ฆ่าโปรเซส worker ทั้งตัว · `await` ตัวจริงยังโยน error ปกติ
- **Jev (TypeSafe) คือด่านสุดท้ายตอน selector พัง** — `firstVisible` ลอง CSS → `findByIntent` → `findByJev` (`worker/dom-heuristics.ts` + `worker/jev.ts`, key `TYPESAFE_API_KEY` ใน `.env`, ปิดด้วย `FLOW_JEV=0`) ส่งรายการปุ่มที่มองเห็น (มีชื่อ class) ให้ Jev เลือก รับเฉพาะความมั่นใจ ≥ `JEV_MIN_PROBABILITY` (0.93)
  - `JEV_INTENT` (ใน `worker/flow-driver.ts`) มีเฉพาะปุ่มที่กดผิดแล้วไม่เสียของ: สร้างโปรเจกต์/ตั้งค่า/แนบรูป/อัปโหลด/Add to prompt — Generate และช่องพิมพ์พรอมต์อยู่นอกรายการนี้เสมอ
  - บรรทัด "Jev เลือกปุ่มแทน selector…" ใน steps.log = Flow เปลี่ยนหน้าแล้ว → เอาคำอธิบายปุ่มไปแก้ selector ถาวรใน `flow-selectors.ts`
  - เรียก Jev ไม่ได้ (เน็ต/key/โควตา) = คืน null เงียบๆ พฤติกรรมเหมือนไม่มี Jev · ทดสอบย้อนหลังกับ page.html จริง 9 หน้า: ถูก 14 ผิด 0 ไม่กด 4 (ไม่หยิบปุ่ม "tune" ของ Agent เพราะไม่ถึงเกณฑ์)

- **งานดิสก์ทั้งชุดอยู่ `exportClip` ใน `lib/clip-export-fs.ts` ที่เดียว** (ตัดสินส่งซ้ำ/วันโพสต์/เลขช่อง/เช็กคลิปก่อนสร้างโฟลเดอร์/ก๊อป/ลบคลิปอีกขนาด/rollback · ฝั่งเซิร์ฟเวอร์เท่านั้น ตรวจกับโฟลเดอร์ชั่วคราวจริงด้วย `scripts/check-clip-export-fs.mjs`) · `exportJobToFolder` (`app/actions.ts`, ใช้ร่วมกันระหว่างปุ่ม `exportClipToFolder` กับ `takeOverFlowJob`) เหลือแค่หางาน อ่านแถว `user_export_clip` ล่าสุดส่งเป็น `prev` อ่านโควต้าต่อวัน หา Product ID บันทึก `record` ที่คืนมา (เมื่อ outcome ไม่ใช่ `already`) และเปิด Explorer · helper pure `lib/clip-export.ts` (ตรวจด้วย `scripts/check-clip-export.mjs`) client import ได้ ห้ามมี `node:*` — ก๊อปคลิป (`คลิป-1080p.mp4`/`คลิป-720p.mp4`) + รูปที่เลือกรอบ 1/2 + `เสียงพากย์.txt` + `โพสต์.txt` ไปที่ `<root>\<Month>\<d-m-yy>\<n>_<ชื่อสั้น≤30>\` (ปี พ.ศ. 2 หลัก, ไม่เติม 0) แล้วเปิด Explorer
- **วันที่ในโฟลเดอร์ = วันที่จะโพสต์ ไม่ใช่วันที่กดส่ง (ตั้งแต่ 2026-10-04; โฟลเดอร์ก่อนหน้านั้นยังหมายถึงวันที่ส่ง)** — ทุกการส่งใหม่ (คลิปบอท + ทำต่อเอง) ลง "วันถัดไปที่ยังไม่เต็ม" เริ่มจากพรุ่งนี้ วันละ N คลิป: `countFoldersByDay` นับโฟลเดอร์ย่อยที่มีอยู่จริงของทุกวัน (รวมที่ผู้ใช้ทำเอง; ไฟล์เดี่ยวไม่นับ) → `pickPostingDay(counts, tomorrowOf(now), N)` (pure) · วันที่ผ่านไปแล้วไม่ถูกพิจารณา · เลขช่อง = สูงสุดของวันนั้น +1 · โฟลเดอร์เดือนตามวันที่เลือก (ข้ามเดือน/ปีได้) · ส่งซ้ำ/อัปเดตไม่ย้ายวัน · โฟลเดอร์ถูกลบ = วันแรกที่ว่างตอนนั้น · กติกาใช้: โพสต์โฟลเดอร์ที่เก่าที่สุดก่อน
- **N (โพสต์วันละกี่คลิป)** = `tts-settings.json` ที่ root repo (gitignore, `lib/tts-settings.ts`, path คงที่ + `turbopackIgnore`) ค่าเริ่ม 4 จำนวนเต็ม 1–20 ไม่มี/เสีย = 4 · ตั้งจากช่อง "โพสต์วันละ [N] คลิป" บนสุดของ `/flow` (`setPostsPerDay` → `PostsPerDayControl`) ไม่ต้อง migrate/build — fingerprint ของ `start.bat` ไม่รวมไฟล์นี้ · มีผลกับการส่งครั้งถัดไป ไม่ย้ายโฟลเดอร์เดิม
- **ส่งงานที่ทำต่อเอง (ไม่มีคลิป)**: `allowNoClip` (action เปิดให้งานที่เคยทำต่อเอง และ `takeOverFlowJob` เรียกทันทีหลังจบงาน) — รูปต้นทาง (`รูปต้นทาง.<ext>` = `currentSourceImage` — รูปปัจจุบันหลังเปลี่ยนรูปต้นทาง) อยู่ในทุกโฟลเดอร์ทั้งงานบอทและทำต่อเอง (ส่งใหม่/อัปเดต/กดซ้ำ) · กดซ้ำโดยคลิปไม่เปลี่ยน (`already`) ข้ามแค่การก๊อปคลิป ข้อความ/รูปเขียนใหม่ในโฟลเดอร์เดิม ไม่ย้ายวัน ไม่บันทึกแถวใหม่ · งานทำต่อเอง: ใส่ตัวนี้เสมอ + รูปที่เลือกรอบ 1/2 + เสียงพากย์/โพสต์ตามที่มี · `record.video = null` จึงกดซ้ำเป็น `updated` ของโฟลเดอร์เดิมเสมอ (พรอมต์/แคปชัน/คลิปมาทีหลังเข้าโฟลเดอร์เดิม รูปต้นทางไม่ถูกลบ) · งานปกติของบอทยังต้องมีคลิป · export ล้มหลังทำต่อเอง = งานยังเป็น "ทำเอง" `takeOverFlowJob` คืน `exportError` ให้โชว์ทุกกรณี (มีคลิปหรือไม่) แล้วกด "ส่งเข้าโฟลเดอร์ TTS" ลองใหม่
- **Product ID** (เฉพาะสินค้าจาก Showcase; `getProductIdsByEntry` = `ProductCandidate.linkedEntryId → sourceProductId` ไม่มีคอลัมน์ใหม่): โชว์พร้อมปุ่มคัดลอก (`components/product-id-copy.tsx`) บนหัวงาน `/flow` และหน้า entry และเป็นบรรทัดท้าย `โพสต์.txt` (`Product ID: …`) — ไว้ค้นตอนปักตะกร้า · สินค้าที่ไม่ได้มาจาก Showcase ไม่แสดงอะไร
- root = `CLIP_EXPORT_ROOT` (ไม่ตั้ง = `Desktop\TTS`) · `CLIP_EXPORT_NO_OPEN=1` ไม่เปิด Explorer · **ตอนทดสอบตั้ง `CLIP_EXPORT_ROOT` ชี้ scratch เสมอ** — `Desktop\TTS` คือโฟลเดอร์งานจริงของผู้ใช้
- กดซ้ำปลอดภัย: ทุกครั้งที่ส่งบันทึก `FlowActivity` kind `user_export_clip` (`detail: { path, video }` — video = ชื่อไฟล์คลิปตอนส่ง, null = ส่งโดยไม่มีคลิป) แล้ว `exportAction` ตัดสินจากแถวล่าสุด: คลิปเดิม + โฟลเดอร์ยังอยู่ = ไม่ก๊อป คืน path เดิม (`alreadyExported`) · คลิปเปลี่ยน (720p → 1080p / เรนเดอร์ใหม่) หรือแถวเก่าที่ไม่มี `video` = เขียนทับในโฟลเดอร์เดิมและลบคลิปอีกขนาดทิ้ง (`updated`) · โฟลเดอร์ถูกลบ = ช่องใหม่ในวันโพสต์แรกที่ว่าง · หน้า `/flow` ชวนกดอัปเดตเมื่อคลิปที่ส่งไว้ไม่ใช่คลิปปัจจุบัน (`exportStaleHint`)
- สร้างโฟลเดอร์หลังเช็กว่ามีไฟล์คลิปแล้วเท่านั้น (ยกเว้น `allowNoClip`) และลบทิ้งถ้าก๊อปล้มกลางทาง (ลบเฉพาะโฟลเดอร์ที่ `mkdir` สำเร็จเอง) · อัปเดตโฟลเดอร์เดิมแล้วล้ม = ไม่ลบ
